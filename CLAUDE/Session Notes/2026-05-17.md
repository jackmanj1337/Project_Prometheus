## What Was Done

### Step 0 — gitignore: track the global class cache
`.godot/global_script_class_cache.cfg` is only regenerated by the Godot **editor**;
headless `--script` runs never rebuild it, so new `class_name` scripts were invisible
on CI / fresh clones until the gitignored cache was hand-patched. Switched `.godot/`
to `.godot/*` + a `!` negation so just that one file is versioned (everything else in
`.godot/` stays ignored). This also turned the D-3 cache patches into normal tracked
edits that land in the extraction commits — the design's §7 clone/CI breakage risk is
now gone.
- Commit: `Track .godot/global_script_class_cache.cfg so headless runs resolve class_name scripts`

### Step 1 — Extract `MapCursorSelection` (D-3 Slice A)
New `scripts/core/MapCursorSelection.gd` (`RefCounted`) owns unit selection +
movement-path planning: `select_at`, `plan_path_to`, `undo_and_reselect`, `clear`,
and the public `selected_unit` / `movement_tiles` fields. `MapCursor` keeps the FSM —
the `_state` writes, the `LOCKED` guard, the `await` move, the liveness guard, and the
EventBus relays (a `RefCounted` can't `get_node`). `_selected_unit` / `_movement_tiles`
deleted from `MapCursor`; `_try_select_unit_at_cursor` / `_try_move_selected_to_cursor`
/ `_deselect` / `_undo_move_and_reselect` / `_finish_action` rewritten as thin FSM
shells over the slice. `test_map_cursor.gd` + `test_unit_selection.gd` repointed to
`_selection.selected_unit` / `_selection.movement_tiles`. No behavior change.
- Commit: `Extract MapCursorSelection slice from MapCursor`

### Step 3 — Extract `MapCursorInput` (D-3 Slice B)
New `scripts/core/MapCursorInput.gd` (`RefCounted`) owns keyboard decoding +
held-key auto-repeat: `decode_key` (→ a state-agnostic `Intent`), `arm_repeat`,
`note_key_released`, `clear_repeat`, `tick`. `MapCursor` stays the input *receiver*
(Godot only calls `_unhandled_input` on a tree `Node`) and forwards raw events; the
member is `_input_handler` to avoid colliding with the `_input()` callback. The
`KEY_REPEAT_*` consts and `_held_*` fields moved with it; `_handle_key_press` /
`_process` / `lock` / the `_input` key-release branch rewritten over the slice.
`test_map_cursor.gd` T2 repointed to `_input_handler._held_dir`. No behavior change —
the double-`DELAY` first-repeat quirk was ported verbatim here, then fixed in Step 5.
- Commit: `Extract MapCursorInput slice from MapCursor`

### Step 4 — `test_map_cursor_input.gd` (new, 15 tests)
`decode_key` classification (confirm / cancel / next_unit / all four directions /
ESCAPE→CANCEL / unmapped→NONE) and the auto-repeat timer. Events are built as real
`InputEventKey`s with keycodes matching the project `InputMap` (loads fine in
`--script` mode). Surfaced a real finding: `cancel` and `open_menu` **both bind
ESCAPE**, and `cancel` is decoded first — so the keyboard `open_menu` path is shadowed
(was already true in the old `_handle_key_press` if/elif order; preserved, and the
test pins it).
- Commit: `Add test_map_cursor_input: 15 unit tests for the MapCursorInput slice`

### Step 5 — Fix the key-repeat double-`DELAY` quirk
The old `_process` re-armed the repeat timer with `KEY_REPEAT_DELAY` on the *first*
auto-repeat step (the `_held_initial` ternary read the flag before clearing it), so
the first repeat waited 0.25s instead of 0.10s. The design's "one-line fix" (clear
`_held_initial` before the read) would make the ternary always pick `RATE`, leaving
`_held_initial` a dead field — so the field was removed outright and `tick()` now
always re-arms with `KEY_REPEAT_RATE`. The press still waits `DELAY` (set by
`arm_repeat`), every repeat after waits `RATE`. `test_map_cursor_input.gd`'s quirk
test repointed to the fixed behavior.
- Commit: `Fix key-repeat double-DELAY quirk: first auto-repeat now uses RATE`
