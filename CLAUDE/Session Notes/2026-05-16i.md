## What Was Done

### Step 1 — [HIGH] Vantage dead-attacker bug
`CombatResolver.resolve_combat`'s attacker strike loop broke only on `def_sim_hp <= 0`.
With Vantage the defender strikes first; a counter-kill left `atk_sim_hp <= 0` but the
attacker loop still ran, so a dead attacker swung back. Added `or atk_sim_hp <= 0` to the
loop guard (`CombatResolver.gd:537`). Added a `test_combat` regression: a Vantage
defender one-shots the attacker → asserts `attacker_died`, `not defender_died`, no
exchange authored by the attacker, exactly one exchange.
- Commit: `Fix Vantage: dead attacker no longer swings after a counter-kill`

### Step 2 — [MEDIUM] preview_combat snapshot scope
`preview_combat` snapshots only the two combatants, but `apply_trigger` writes
`skill_use_counters` on any unit owning a fired use-limited skill (aura bearers) — a
latent M9 use-burning bug. Added a `dry_run` param to `SkillHandler.apply_trigger`:
when true, skill effects still run (accurate forecast) but per-map / per-combat use
counters are NOT persisted. Threaded `dry_run` through `_collect_combat_modifiers`;
`preview_combat` passes `true`, `resolve_combat` passes `false`. Test: a 1-use-per-map
skill survives two previews with 0 uses burned, then `resolve_combat` increments it.
- Commit: `Add dry_run to apply_trigger so combat previews never burn skill uses`

### Step 3 — [LOW ×5] polish batch

- `GameState._restore_unit_data` `active_modifiers` default `{}` → `[]` (field is

- Commit: `Low-severity polish: HP bar refresh, restore default, fort rounding, liveness guard`

### Follow-on — two §4 architectural carry-overs (done same session)

**`_run_strike_series` (CombatResolver).** Collapsed the four hand-written strike
loops (Vantage / attacker / counter / follow-up) into one guarded helper. Building it
surfaced a bug the 16d review **missed**: the counter loop had no actor-alive guard, so
a defender the attacker had just killed still counterattacked — a corpse swinging back.
GDD_02:167 ("if target HP ≤ 0, stop the exchange — no further attacks") makes that a
spec violation. The uniform `actor_sim_hp <= 0 or target_sim_hp <= 0` guard in
`_run_strike_series` fixes it. Consequence: a true both-die "mutual kill" can no longer
be authored by `resolve_combat` (whoever drops first ends the exchange). The `BUG-01`
mutual-kill test, which relied on the dead-defender-counterattacks behavior, was
repointed: it now asserts (a) a one-shot defender does not counterattack and the
attacker survives, and (b) `apply_combat_result` still iterates *all* exchanges so a
hand-built two-lethal-exchange result kills both units — that being the actual BUG-01
fix. `test_combat` 36 → 37.
- Commit: `Consolidate combat strike loops into _run_strike_series; fix dead-defender counterattack (GDD_02:167)`

**`_begin_phase` (TurnManager).** Extracted the per-phase routine shared by
`start_player_phase` / `start_enemy_phase` — turn-modifier tick, fort healing,
start_of_turn skills — into `_begin_phase(units)`. Behavior-preserving; the player
phase's once-per-round `map_turn` tick stays separate.
- Commit: `Extract _begin_phase helper to keep player/enemy phase routines symmetric`
