## What Was Done

### Step 1 — [HIGH] Vantage dead-attacker bug
`CombatResolver.resolve_combat`'s attacker strike loop broke only on `def_sim_hp <= 0`.
With Vantage the defender strikes first; a counter-kill left `atk_sim_hp <= 0` but the
attacker loop still ran, so a dead attacker swung back. Added `or atk_sim_hp <= 0` to the
loop guard (`CombatResolver.gd:537`). Added a `test_combat` regression: a Vantage
defender one-shots the attacker → asserts `attacker_died`, `not defender_died`, no
exchange authored by the attacker, exactly one exchange.
- Commit: `Fix Vantage: dead attacker no longer swings after a counter-kill`

### Step 2 — [MEDIUM] preview_combat snapshot scope
`preview_combat` snapshots only the two combatants, but `apply_trigger` writes
`skill_use_counters` on any unit owning a fired use-limited skill (aura bearers) — a
latent M9 use-burning bug. Added a `dry_run` param to `SkillHandler.apply_trigger`:
when true, skill effects still run (accurate forecast) but per-map / per-combat use
counters are NOT persisted. Threaded `dry_run` through `_collect_combat_modifiers`;
`preview_combat` passes `true`, `resolve_combat` passes `false`. Test: a 1-use-per-map
skill survives two previews with 0 uses burned, then `resolve_combat` increments it.
- Commit: `Add dry_run to apply_trigger so combat previews never burn skill uses`

### Step 3 — [LOW ×5] polish batch
- HP bar `max_value` now refreshed on an HP level-up (`Unit._increment_stat`).
- `GameState._restore_unit_data` `active_modifiers` default `{}` → `[]` (field is
  `Array[Dictionary]`).
- `CombatResolver` header comment reworded — the "no unit fields written" claim is now
  scoped to HP/durability/EXP, with a note that skill triggers DO mutate state.
- `MapCursor._finish_action` guards the DONE state-write with a liveness check so a unit
  that died mid-action isn't re-inserted into `TurnManager._unit_states`.
- Fort healing `ceili` → `floori` (GDD_02:76 mandates round-down). Fort and Renewal now
  share `GameConstants.PERCENT_HP_HEAL_FRACTION` (renamed from `FORT_HEAL_FRACTION`);
  Renewal's magic literal `0.10` is gone. Added a `test_unit_stats` assertion: a 25-HP
  unit on a fort heals 2, not 3.
- Commit: `Low-severity polish: HP bar refresh, restore default, fort rounding, liveness guard`

### Step 4 — [MEDIUM] pathfinding consolidation
Extracted `GridManager.dijkstra_costs(start, max_cost, ignore_occupants, blocker_unit,
came_from)` — one parameterised flood. `get_movement_range`, `get_movement_path`, and
EnemyAI's distance estimate all route through it; `EnemyAI._flood_costs` was deleted.
Kept the insertion-sorted heap (dropped the two O(n²) linear-scan frontiers). All grid /
AI suites stayed green through the refactor.
- Commit: `Consolidate movement/path/flood pathfinding into GridManager.dijkstra_costs`

### Step 5 — [TEST DEBT] EnemyAI coverage

injured ally; `_try_staff_heal` no-ops on a non-staff weapon and on a staff with no
healable target. Extended the stub script with `data`, `_weapon`, and a
`perform_staff_heal` call-tracker.
- Commit: `Expand EnemyAI test coverage: dijkstra_costs, grid-based _find_nearest, heal positioning, staff heal`
