# Session Notes — 2026-05-13 (Bug Fix Session)

## Context
Resumed from 2026-05-13 code review (`CLAUDE/code_review_2026-05-13.md`) which was added as the most recent commit at session start. The review had 2 criticals, 5 highs, 8 mediums, 5 lows, and 5 GDD-drift items, plus 5 ARCH items from the previous session's carry-overs.

## What Was Done

### C-1 — Fix 4 weapon .tres files
`javelin.tres`, `thunder.tres`, `wind.tres`, `steel_sword.tres` still wrote deprecated `range_min`/`range_max` int fields (silently dropped by Godot on load). Replaced with `range_min_formula`/`range_max_formula` strings. Javelin, Thunder, Wind now correctly work at 1–2 range.

### C-2 + H-1 — ItemHandler autoload + item button labels
- Created `scripts/items/ItemHandler.gd` autoload (registered after SkillHandler in `project.godot`). Mirrors SkillHandler design: `apply_item(unit, entry)` looks up ItemData from DataManager, dispatches on `effect_id`, decrements uses, removes exhausted entries.
- `MapCursor._apply_item_effect` became a one-line dispatch.
- `ItemMenu.show_for` now looks up `DataManager.get_item(entry["item_id"]).display_name` for button text.

### H-2 + H-3 + H-4 — Combat formula correctness
- H-2: `compute_damage` now uses `get_effective_stat("defense"/"resistance")` for defender so DEF/RES buffs are respected.
- H-3: `_get_effectiveness_multiplier` gains an `actor` parameter; callers pass the actual attacking unit so a counter-attacker with Giantkiller gets 4×.
- H-4: `WeaponData._stat_value` now prefers `get_effective_stat()` over raw `unit.data.X` so MAG buffs affect dynamic staff range.
- Added `has_skill()` to MockUnit; 2 new regression tests for H-2 and H-3.

### M-1 + M-2 + M-3 + M-5
- M-1: `MapCursor._on_map_menu_closed` now checks `gs.is_player_turn()` before unlocking.
- M-2: `_set_tile` guards `position = _grid.tile_to_world(...)` with a `_grid != null` check.
- M-3: `_handle_mouse_motion` added `_grid == null` to early-return guard.
- M-5: `TurnManager._on_unit_died` now also erases `_original_tiles[unit]`.

### M-4 — LevelUpScreen respects setting
`_on_unit_leveled_up` returns early on "skip". `_show_next` uses `CONNECT_ONE_SHOT` timer for auto-dismiss (1.5s) and hides prompt label in auto mode. `_unhandled_input` ignores input in auto mode.

### M-6 + H-5 — AI profile dispatch + healer pathing
- `EnemyAI._act` now dispatches `"passive"` → `_act_passive`, `"healer"` → `_act_healer` at the top.
- `_act_passive`: holds position, attacks only if player already in range.
- `_act_healer`: calls `_choose_heal_move_tile` to find best tile for healing (most-injured ally in range, tie-break by terrain DEF+Dodge). Then `_try_staff_heal`.
- `_choose_heal_move_tile`: uses `GridManager.TERRAIN_DEF_BONUS`/`TERRAIN_DODGE_BONUS` constants.

### L + M-8 — Low-priority fixes
- M-8: Added doc comment on `EventBus.combat_resolved` warning about `is_instance_valid`.
- L-1: Renamed `required_survivor_names` → `required_survivor_ids` in `map_001_data.tres`.
- L-3: Fixed misleading `is_natural_weapon` docstring in `WeaponData.gd`.
- L-4: Removed `"required_survivor":bool` from `MapData` doc + all 8 enemy placements in map_001.

### GDD-4 — Simplified leveling system
Replaced 4-method leveling (growth_rates/point_buy/coin_flip/dice) with 2:
- `growth_random` (default): probabilistic, handles `rate > 100` correctly (guaranteed gain + remainder %).
- `growth_fixed`: deterministic accumulator in `UnitData.growth_accumulators`; carry included in GameState snapshot/restore.
- SettingsManager, GameState defaults updated to `"growth_random"`.
- `Unit.level_up` dispatches to `_level_up_random`/`_level_up_fixed`; no more warning.
- 3 new tests: carry-persist, rate-150 pattern, rate-250 guaranteed minimum.

### ARCH-03 + ARCH-04 + ARCH-10
- ARCH-03: `SkillHandler.apply_trigger` + aura skills now check `is_instance_valid`.
- ARCH-04: `ConditionManager` stubs push_warning (visible in dev output) instead of silent pass.
- ARCH-10: `SkillData.validate()` checks for empty id/effect_id/trigger; called by `DataManager._ready()`.
