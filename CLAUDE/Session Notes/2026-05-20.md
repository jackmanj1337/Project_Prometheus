### 3. M14 stage 2 — alliance-group hostility (commit `c5c9c32`)

Replaces the literal "same team = ally" comparisons with a
data-driven alliance-group hostility check. Still 2 factions on
existing maps, so still behaviour-neutral.

`GameState`:
- `const _DEFAULT_ALLIANCE_GROUPS = {blue,green→"allies",
  red→"foes", yellow→"rogues"}` per the GDD relationship matrix.
- `var _alliance_groups` runtime-mutable (stage 3 populates from
  MapData.factions; for now mirrors the const).
- `are_hostile(a_id, b_id)` — two units are hostile iff their ids
  resolve to different groups. Equal ids never hostile (matches the
  stage-1 binary). Empty / unmapped id is its own one-faction group.
- `get_alliance_group(id)` — exposed for tests + stage 3.

`GridManager._hostile(a, b)`: the single chokepoint, routes through
`GameState.are_hostile` when the autoload is live; falls back to
`a.team != b.team` in headless tests so existing fixtures stay valid.
Four same-team checks all routed through it (is_passable,
dijkstra_costs, get_attackable_enemies_from_tile, get_healable_allies).
`get_enemy_danger_tiles` kept player-facing — filters in only
hostile-to-blue.

`MapCursorTargeting._is_target_hostile`: same shape, reads GameState
via the grid Node's tree handle (the slice itself is RefCounted).
Routes the attack + heal target gates.

### 4. M14 stage 3 — N-faction data + scheduler (commit `0c68254`)

The meaty one — full N-faction core and the activation scheduler.

**FactionData Resource** (`scripts/resources/FactionData.gd`):
- Fields: id, display_name, color, alliance_group, controller.
- `get_label()` falls back to title-cased id so default cycles render
  right with no per-map authoring.
- Class-cache entry added in `.godot/global_script_class_cache.cfg`
  (tracked per `.gitignore` — `!.godot/global_script_class_cache.cfg`).

**MapData additions:**
- `factions: Array[FactionData]` — fallback to default.
- `turn_order: Array[String]` — overrides the derived order. Cycle
  skips zero-unit factions at runtime.
- `activation_mode: String` — `"WHOLE_PHASE"` (default) or
  `"ALTERNATING"` (Decision 9).

**GameState — per-faction buckets:**
- `_units_by_faction: Dictionary[String, Array[Node]]` replaces the
  binary `_player_units` / `_enemy_units` pair.
- `get_living_units_of(faction_id)` is the canonical filter.
- `get_living_player_units` / `get_living_enemy_units` kept as thin
  wrappers (blue / hostile-to-blue) so MapCursor, EnemyAI, TurnManager
  and the existing tests work unchanged. Stage 4 retires both callers.

**TurnManager — activation scheduler:**
- State: `_turn_order`, `_active_faction_idx`, `_activation_mode`.
  Default cycle `["blue","green","red","yellow"]` per GDD_10 § M14.
- `active_faction()` returns the current id.
- `_advance_faction()` advances one slot, skipping zero-unit factions
  (Decision 2); returns `true` iff the cycle wrapped (= new round).
- `start_map` derives turn_order from MapData.turn_order, then
  MapData.factions, then the default. Same fallback chain for
  activation_mode.
- Legacy `start_player_phase` / `end_player_phase` / `start_enemy_phase`
  keep their WHOLE_PHASE behaviour — start_player_phase syncs
  `_active_faction_idx` to blue via `_jump_active_faction_to`;
  start_enemy_phase advances from blue past empties.
- **`_begin_phase` mode-aware** (Decision 9):
  - WHOLE_PHASE: per-army-phase (today's behaviour).
  - ALTERNATING: round-boundary only — fires from
    `end_alternating_activation` on the wrap event, and from
    `start_map` for the initial round.
- New primitive `end_alternating_activation()`: the controller calls
  it after one committed unit; advances + refreshes + bumps
  turn_number at the wrap. No-op in WHOLE_PHASE.
- `start_map` non-blue-first path sets the phase but does NOT auto-
  loop via AI / call_deferred — stage 4 plumbs the controller dispatch.

**What stays for stage 4 / follow-up (still inside M14 scope):**
- Player controller branching on activation_mode (cursor returns
  control after one committed unit in ALTERNATING). The primitive
  exists; wiring MapCursor's auto-end / End Turn into it lands later.
- `EnemyAI.run_enemy_phase` → `run_ai_phase(faction)`.

Tests:
- `test_game_state` +2: per-faction bucket separation + legacy aliases.
- `test_turn_manager` +6: default cycle, MapData override, zero-unit
  skip, cycle wrap, ALTERNATING per-unit + wrap refresh, mode no-op,
  FactionData-derived turn_order.
