## Recommended Work Order

### 1. Design Doc

Lock the display model before code:

- Whether Menu Scale becomes a theme/font/metric scaler, a custom-minimum-size scaler, or a
  hybrid. Recommendation: avoid `Control.scale` for menu/modal text; use a per-target Theme
  or theme overrides plus minimum-size metrics so raster text stays crisp.
- Whether HUD Layout panel scale is also replaced now or staged. V021-18 says Menu/HUD; if
  HUD remains on `panel.scale`, document that limitation and keep V021-04 open.
- Resolution list and labels. Minimum v0.2.3 requirement: add native 1440p and 4K windowed
  options (`2560x1440`, `3840x2160`) with confirm-or-revert.
- Steam Deck/mobile safe-area policy. Recommendation: do not pretend mobile is supported
  yet; define safe-area margin plumbing/default-zero behavior and document mobile as
  deferred unless actual touch safe-area APIs are wired.
- If the debug Web playtest path is approved, keep it explicitly scoped as a private
  Web channel: emulator-style HTML shell, 16:9 game canvas, touch controls outside
  the canvas, single-threaded Web export, and no PWA on the first pass.
- Migration behavior for existing saved `menu_scale_index` and `hud_layout` scale entries.

### 2. Crisp Menu Scale

Test first:

- Update `test_menu_scale.gd` so centered modal panels do not rely on `Control.scale != 1`
  for the scaled visual result.
- Preserve V021-08: tall menus still fit top/bottom at the largest supported Menu Scale.
- Preserve contextual-menu anchoring for Action/Item/Weapon menus.

Implementation shape:

- Refactor `MenuScale.apply_to()` to apply crisp font/metric sizing and leave `scale` at
  `Vector2.ONE` for modal/menu text surfaces.
- Keep `_fit_factor()` or an equivalent requested-factor clamp so large menus remain
  reachable.
- Be careful with Theme mutation. If using Theme objects, clone per target or use local
  overrides so one menu does not mutate another menu's baseline.

### 3. HUD Layout / Terrain Corner Follow-Up

Decide during the design doc whether this lands in v0.2.3 or remains live-verify:

- If HUD scale is migrated away from `panel.scale`, add/update tests in `test_hud_layout.gd`
  and verify `current_layout()` still round-trips existing saved data.
- Use this chance to close `V021-04` if the new scale path can keep bottom-right terrain
  corner snap stable.
- If not closing it, keep `V021-04` explicitly deferred in GDD_10 and the check-back doc.
