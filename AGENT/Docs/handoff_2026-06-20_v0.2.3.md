## Recommended Work Order

### 1. Design Doc + Signoff (done)

The display model is locked in `display_scaling_resolution_design_2026-06-20.md`:
D1 renderer-first, D2 font/metric Menu Scale (no `Control.scale` for text), D3 staged HUD
scale, D4 add 1440p/4K (keep 16:9), D5 safe-area plumbing (mobile deferred), D6 no
destructive save migration. Get user signoff on the D1-D6 recommendations, then implement.

### 2. Renderer + Foundation (D1, E1, E5) — do this first

Cheap, web-load-bearing changes that let the web track branch off a clean foundation:

- Add `renderer/rendering_method="gl_compatibility"` to `project.godot` (D1).
- Make `window/stretch/aspect="keep"` explicit (E5); leave `content_scale_factor` global at 1.
- Gate the resolution apply + `DisplayConfirmDialog` confirm/revert to desktop only (E1) so
  Web never inherits a dropdown/dialog it can't honor.
- Add the `check_docs.py` guards for `rendering_method` and `stretch/aspect` (DoD#2).
- Re-run the full suite + `check_docs.py`; live-smoke the desktop build (touches every
  render path) and do a quick headless Web export sanity check if the web preset already
  exists from the web track.
- DoD#1: update GDD_01 Rendering. This commit is the shared seam with the web build, so
  coordinate ordering if both tracks are active in the same session.

### 3. Crisp Menu Scale

Test first:

- Update `test_menu_scale.gd` so centered modal panels do not rely on `Control.scale != 1`
  for the scaled visual result.
- Preserve V021-08: tall menus still fit top/bottom at the largest supported Menu Scale.
- Preserve contextual-menu anchoring for Action/Item/Weapon menus.

Implementation shape:

- Refactor `MenuScale.apply_to()` to apply crisp font/metric sizing and leave `scale` at
  `Vector2.ONE` for modal/menu text surfaces.
- Keep `_fit_factor()` or an equivalent requested-factor clamp so large menus remain
  reachable.
- Be careful with Theme mutation. If using Theme objects, clone per target or use local
  overrides so one menu does not mutate another menu's baseline.

### 4. HUD Layout / Terrain Corner Follow-Up

Decide during the design doc whether this lands in v0.2.3 or remains live-verify:

- If HUD scale is migrated away from `panel.scale`, add/update tests in `test_hud_layout.gd`
  and verify `current_layout()` still round-trips existing saved data.
- Use this chance to close `V021-04` if the new scale path can keep bottom-right terrain
  corner snap stable.
- If not closing it, keep `V021-04` explicitly deferred in GDD_10 and the check-back doc.
