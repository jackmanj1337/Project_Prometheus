## The content families get their first look at real content

`IMPL-ZERO-CONTENT-FAMILIES` does not close on a display — its exit is the families still
unbuilt (skills, pair-up, the remaining registry documents, then campaigns and
`map_registry` last). But ten registered kinds were each built against **synthetic
fixtures**, and this is the first bundle where a real extracted pack drives them in front
of a person. Checklist §5a hits the specific cases the pack was authored to reach: two
packs sharing content ids, the four-faction map, all five objective condition types,
promotion, and the terrain consolidation.

That section is worth its space because of the failure mode this work keeps hitting. A
Godot typed-array export assigned from raw JSON is left **silently empty** — no error, no
warning — and it has now been caught five separate times, most recently on `MapData.factions`,
where an authored four-faction map would have quietly become the two-faction default.
Fixtures did not catch those; authored content did.

## Not a row, but the reason the round is worth running on this build

`SIZE-CLASS-SEAM-2026-08-06` is **closed** — nothing waits on your verdict. But the seam
landed after the previous bundle was frozen, so this is the first build it can be looked
at in, and its live behaviour (debounced republish, boundary hysteresis, state survival
across a class change) is unreachable headless: the test harness pins the logical
viewport at 1280×720. Eleven screen conversions are about to be built on top of it.
Checklist §2a covers it. A defect found there now is much cheaper than the same defect
found underneath eleven converted screens.

## The one worth more than its own line

`IMPL-FILEDIALOG-ESCAPE-TEXTINPUT-2026-07-29` claims `SettingsManager.gd`,
`SettingsScreen.gd` and `SettingsScreen.tscn`. Closing it releases a claim that **three
other pieces of work are queued behind**:

- the Settings screen conversion to the size-class model;
- Menu Mode and information density becoming persisted settings (`ResponsiveLayout`
  holds them in memory today precisely because that file is claimed);
- dropping `system` from the text-entry vocabulary (`TEXT-V1-S06`, currently blocked);
- and flipping the retired 1280×720 constant in
  `SettingsManager.fit_content_scale_factor_for_size`, which is the direct cause of
  2.7 CSS px body text in phone portrait.

That is why §4 of the checklist is the section this whole round exists for.

## Deliberately absent from both rounds

`IMPL-FOG-RENDER-2026-08-02` needs a visual pass and is in neither bundle. Fog computes
and draws nothing today, so there is nothing to look at. It is not a regression and
should not be reported as one.

`IMPL-VIEWPORT-ANCHORING-2026-07-31` was **closed as superseded** on 2026-08-06 and its
visual pass cancelled — what it would have validated is the retired 1280×720 floor. What
it shipped is still in this build and still exercised (the Viewport Scale setting,
`aspect=expand`, the `MenuScale` reconciliation); it simply has no row waiting on your
verdict. Do not re-add it.
