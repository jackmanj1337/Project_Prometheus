# Windows — start here

Written for someone who has not been in the repository. You need a Windows machine, a
controller, and about two hours.

## 1. Unzip

Unzip the bundle anywhere with a normal path — your Desktop or Downloads is fine.
Avoid a path with unusual characters, and do not run it from inside the zip viewer:
Windows will hand the executable a temporary directory and the save location will not
be where this document says it is.

## 2. Verify you have the right build

In PowerShell, from the unzipped folder:

```powershell
Get-FileHash .\Project_Prometheus_v0.7.0.exe -Algorithm SHA256
```

Compare it with the matching line in `SHA256SUMS.txt`. `BUILD_INFO.json` records the
same digest alongside the source commit and the BUILD STAMP baked into the binary.

Then launch the game and read the first lines of the startup log (see §5 for where the
log lives). The log prints a **BUILD STAMP**. It must say `version=0.7.0`. That stamp
is the only authoritative identity of a build — the filename is not. A previous round
shipped executables named v0.6.1 that carried a v0.6.0 stamp, and every returned
report was misattributed as a result. If the stamp disagrees with this document, stop
and say so; do not test further.

## 3. Which executable for which items

Two executables ship, and they are **not** the same binary:

| Executable | What it is | Use it for |
|---|---|---|
| `Project_Prometheus_v0.7.0.exe` | release build — what a player would run; debug controls are inert | everything the checklist does not mark otherwise |
| `Project_Prometheus_v0.7.0_debug.exe` | debug build — debug keybindings, debug actions, dev-only campaigns and the DEBUG MODE HUD banner are all live | any checklist item marked **debug**, and anything you want a full trace of |

The checklist names the executable each item wants. When in doubt, run the item on the
release build first: a bug that only reproduces under debug is a different bug.

## 4. Install a campaign pack

The bundle ships the packs in `campaign-packs/`. There are three:

- `proving_grounds_public` — the public pack. This is the one to play.
- `proving_grounds_internal` — **internal only. Do not forward this bundle or this
  folder to anyone.** It preserves the current live balance and its manifest is marked
  `private_only`.
- `proving_grounds_invalid` — deliberately broken, for the "invalid pack is refused"
  checklist item. See its own README for the expected error.

Install through the game's Campaign Library screen. A pack is a folder with a
`manifest.json` and a `data/` directory; point the installer at the folder.

This is the first round where an installed pack actually **plays**: earlier
extractions produced maps with terrain and start tiles but no enemies and no
objectives, and rosters whose units carried no weapons. Every map now has an encounter
and every unit an inventory. If you install the public pack, select it, and the battle
opens with no enemies on the board, that is a serious regression — say so.

## 5. Where your data lives

```
%APPDATA%\Godot\app_userdata\Project Prometheus\
```

Saves, settings, installed packs and logs are all under there.

**This is a rename.** It used to be `Fire Emblem RPG`. The first launch migrates the
old directory if you have one, and that migration is itself a checklist item — so if
you have played a previous build on this machine, run the migration item **first**,
before you create any new saves.

## 6. What to return

- The completed `PLAYTEST_CHECKLIST.md`.
- The completed `DECISION_SHEET.md` — every "Answer:" filled in.
- **The whole log directory**, not a summary and not the lines you thought were
  relevant. The interesting line is routinely one nobody expected to need.

Bugs are most useful with: the BUILD STAMP, which executable, what you did, what
happened, what you expected.
