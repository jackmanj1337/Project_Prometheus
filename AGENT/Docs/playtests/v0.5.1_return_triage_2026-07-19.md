## F-1 — Victory screen softlocks the run (BLOCKING)

Reported by the tester as *"After achieving victory on any map even the old single
maps I was unable to continue or return to the main menu."*

Reproduced in the evidence on **three different maps**, so this is not map-specific.

The victory overlay presents a results panel and a single button. Before the button
is pressed the panel reads `Save: writes after Continue`. After pressing it, the same
panel reads `Save: could not validate the next battle` and the button renders
disabled (its border box disappears and the label dims). No other exit is offered —
the overlay covers the map and no menu is reachable, so the run cannot be continued
or abandoned without killing the process.

Transcribed panel contents:

| Field | Proving Grounds | Faction Demo | Promotion Validation |
| --- | --- | --- | --- |
| Phase banner | `RED - AI PHASE` | `ALLIES - PLAYER 1 PHASE` | `BLUE - PLAYER 1 PHASE` |
| Turn | 7 | 13 | 4 |
| Debug banner | `force-levelup, growth+300` | plain `DEBUG MODE` | plain `DEBUG MODE` |
| Rewards | None reported | None reported | None reported |
| Gold earned / total | 500 / 500 | 500 / 500 | 0 / 0 |
| Casualties | None reported | None reported | None reported |
| Progression | Resolved | Resolved | Resolved |
| Save (before press) | writes after Continue | writes after Continue | — |
| Save (after press) | could not validate the next battle | could not validate the next battle | could not validate the next battle |
| Button label | `Finish Campaign` | `Finish Campaign` | `Finish Campaign` |
| Selected unit panel | `Unit_05 cleric Lv 2 HP 14/19 Heal` | `Unit_04 mage Lv 2 HP 16/16 Fire` | `M950_Mage mage Lv 9 HP 20/20 Fire` |
| Terrain panel | `Plain Tile (9,9) DEF +0 DODGE +0` | `Plain Tile (11,13) DEF +0 DODGE +0` | `Plain Tile (5,6) DEF +0 DODGE +0` |

Objectives in all three read `Win: Rout all hostiles` / `Lose: Rout allies`, and the
ranking block reads `1. Allies (you)` / `2. Foes`.

### Probable root cause — unresolved, two hypotheses

`godot2026-07-18T16.05.47.log` contains **62 `ERROR:` lines**, every one of the form:

```
ERROR: SaveManager: slot 'Start_of_proving_grounds' failed validation:
  SaveData roster.units[N].inventory.entries[M] weapon 'iron_lance' not found
   at: push_error (core/variant/variant_utility.cpp:1024)
       [0] _push_validation_errors (res://scripts/autoloads/SaveManager.gd:692)
```

Every weapon and item id fails to resolve: `iron_lance`, `iron_sword`, `iron_bow`,
`fire`, `heal_staff`, `vulnerary`. This is almost certainly what surfaces as
`could not validate the next battle`, and it plausibly also explains the separate
tester note that *"No units in the two map skirmish has a weapon or proficiency."*

Two candidate causes, neither confirmed:

1. **Export-time enumeration.** The `resource_manifest.json` hazard — content
   enumerates in-editor but goes missing in an exported build. *Evidence against:*
   `data/weapons/resource_manifest.json` on `agent/integration` is exactly in sync
   with the folder (all 12 `.tres` present, including every id above). If v0.5.1's
   `d96d035` was also in sync, this is not the cause.
2. **Initialisation order.** Validation running before `DataManager` finishes
   populating would make *every* id resolve as missing, which matches the observed
   all-or-nothing pattern better than a partial manifest gap would.

Hypothesis 2 fits the evidence better and should be checked first. Confirming either
requires reproducing against `d96d035`, not against `agent/integration`.

## F-2 — Campaign list loses every built-in map after a suspend (HIGH)

Reported as *"After suspending two map skirmish map the new game map selector was
acting funny and not showing all the available maps until the game was relaunched."*

Two screenshots 22 minutes apart make this precise.

**Before (15:40), New Game > Campaign open — 12 entries:**

```
Map 001 - Faction Demo          Map 900 - Hotseat Validation
Map 001 - Rout                  Map 950 - Promotion Validation
Map 002 - Seize                 The Proving Grounds            <- selected
Map 003 - Defeat Boss           The Crossroads  -- two_map_skirmish 1.0
Map 004 - Escape                River Pass      -- two_map_skirmish 1.0
Map 005 - Defend                Two-Map Skirmish -- two_map_skirmish 1.0
```

**After suspending a Two-Map Skirmish map (16:02) — 6 entries:**

```
River Pass                                  <- unqualified
The Crossroads                              <- unqualified
Two-Map Skirmish                            <- unqualified
The Crossroads  -- two_map_skirmish 1.0
River Pass      -- two_map_skirmish 1.0
Two-Map Skirmish -- two_map_skirmish 1.0    <- selected
```

So the post-suspend list does two wrong things at once: it **drops all eight built-in
maps plus The Proving Grounds**, and it **adds three unqualified duplicates** of the
imported package's chapters alongside their correctly-qualified entries. A relaunch
restores the correct list.

Both states show `0 compatible record(s) found` and `Carry Forward: None -- start clean`.

## Observations not reported by the tester

- **Victory can resolve during the enemy phase.** The Proving Grounds capture shows
  `RED - AI PHASE` behind a `Victory!` overlay on turn 7. Worth confirming this is
  intended rather than a victory check firing mid-AI-phase.
- **`Rewards: None reported` and `Casualties: None reported` in all three captures**,
  including a Proving Grounds run whose filename claims a casualty occurred. Either
  reporting is broken or both fields are unimplemented placeholders.
- **The button reads `Finish Campaign` on single validation maps** (Faction Demo,
  Promotion Validation), which are not campaign completions, while the adjacent text
  says `Save: writes after Continue`. The label and the copy disagree.
- **The Promotion Validation map renders mostly black** outside a small terrain
  patch, unlike the other captures which show full terrain. May be expected for that
  fixture; flagged because it is visually distinct.
