## Stage 6 — Documentation validation checks (DOC-011)

### Goal

Add a lightweight script (no prose interpretation) that catches structural doc drift
locally and/or in CI. The master checklist §6.1 lists the required checks:

1. Verify repository-relative Markdown links and file paths
2. Reject links to known renamed/deleted paths
3. Detect duplicate active roadmap IDs
4. Verify required headers on active plans and superseded docs
5. Verify feature-index targets exist
6. Flag stale `Last verified` only when a status-bearing file changed
7. (Optional) Flag legacy field names outside explicitly historical sections

### Recommended approach

Create `AGENT/Docs/check_docs.sh` (or a Python script if path/link parsing is
easier). Wire it into `run_tests.sh` or keep it a separate `bash check_docs.sh`
call — whichever is less disruptive to the pre-commit hook timing.

### Known deleted paths to block

These were renamed or deleted during Stages 4–5 and should cause the check to
fail if found in any non-historical file:

- `GDD_10a_Overview.md`
- `GDD_09_Checklist.md`
- `GDD_Assumptions.md`
- `GDD_Manual_Tasks.md` (moved to `AGENT/Docs/manual_test_playbook.md`)
- `effective_level` (field renamed to `internal_level`; see `GDD_03`)
- `s_rank_mastery` (retired; see `GDD_04`)

### Required-header checks (active planning docs)

Every file in `AGENT/GDD/GDD_0*.md` that is not marked Historical should have:
- A `# Status:` or status block near the top
- A `Last verified:` date in at least one section

Every file in `AGENT/Docs/*.md` that is an active guide (not historical) should
have a `Last verified:` line.

### Feature-index target check

`AGENT/GDD/GDD_Feature_Index.md` lists code paths, test files, and GDD section
anchors. A grep/find check that each listed file path exists avoids silent drift.

### What to test

Because this is a doc-tooling addition (no game code changes), `run_tests.sh` will
still be the integration gate. The doc check can be a separate script that the
developer runs manually or as a pre-push hook rather than pre-commit (since it reads
many files and may be slower than the 38-suite runner).
