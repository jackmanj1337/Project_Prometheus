The rules every frame obeys

  1. Consequence before action. The verb ends the detail column; nothing docks ([DSX-S3], single-scroll 2026-08-12).
  2. The reason leads. Whatever else scrolls, the reason a commit was refused is the first thing in the step ([DSX-S11]).
  3. Disabled, never hidden, for transactional failure — focusable, not activatable, reason stated (TSV-13, RPD-15).
  4. Caps render identically everywhere, with an after-action projection whenever an action changes one ([DSX-S19], [DSX-S20]). An uncapped pool draws a hatched bar, because "uncapped" has no denominator.
  5. No confirmation invented here. Confirmation is EPUX-06's authored raise-only predicate; the shell states a reversibility class instead ([DSX-S6], [DSX-S27]).
  6. On-map surfaces take the canvas region only, never the control band ([DSX-S16]).
  7. --row is a floor, not a height ([DSX-S22]).

12 · Findings from drawing

Three things the frames surfaced that no DSX ruling covers. They are findings, not rulings — options for the approval pass, in the manner of EW-1..10.

  1. Nothing caps the row measure at Expanded. The pool is 1240 px wide at 1920×1080, so an operation row puts +1 Might and 480 g roughly 1200 px apart, and the eye has no way to associate them. Every consumer has this; the forge shows it worst because its end slot is a price. The editor album met the same problem and answered it with a capped measure. Suggested: a max measure on the row's content, so extra width becomes margin rather than gap.
  2. The verb cap of two is a maximum, not a target. Battalions ship one verb and the slot looks correct with a single full-width button, so the shell must not reserve space for a second. Worth stating because a fixed two-slot row is the easy implementation and it would leave a permanent hole on the consumer with the simplest job.
  3. The segmented control is doing two different jobs, and nothing decided which. Read across the adapters: convoy is Take / Give, provider convoy Deposit / Withdraw, shop Buy / Sell — those are directions. But loadout is Held / Convoy and skills is Equipped / Earned — those are sources. One control, two meanings, chosen per adapter, in a shell whose whole point is that a control means one thing everywhere. No DSX ruling covers it because every adapter was drawn against its own ratified vocabulary. Suggested: the segmented control means source, and direction is implied by which side the player takes from — drawn below, because a proposal of this shape should be measured rather than asserted. It also answers a question that arrives immediately after: a roster-wide "see and take anything anyone holds" view is a third source, not a mode and not a screen, and EPUX-08 ("Manage Roster carries the global item-first view") plus CNV-4 (unrestricted unit↔unit movement across the controlled faction in prep) already ratify both the view and the permission.
  4. Taking a battalion from another unit is not ruled. BAT-10's pool is unassigned battalions, so reassignment has no home. The mechanism is free — it is the dependent-choice layer's counterpart case — but it carries a consequence BAT-10 did not consider: a battalion supplies stat bonuses and a granted skill, so taking one silently restats the unit it came from. If it is adopted, [DSX-S20]'s projection must name both units. Recorded here rather than opened as a question, because it belongs to whoever picks up battalion assignment.
  5. A pool scrolling past one screen is normal and is not what [DSX-S11] measured. The convoy pool is 2.37 screens at the Compact floor and Trade's grouped pool is 2.63 — those are lists, and lists scroll. The ~1.9-screen figure that ruling accepted was the detail column, where the consequence and the verb live. Recording it so the two numbers are never conflated in the build.

Finding 3 drawn: scope as a source

The proposal under finding 3, at the reference viewport and at the Compact floor. If the segmented control means source, then convoy-only, roster-wide and single-unit are three values of one control, the holder becomes a group header in the pool — the shape [DSX-S15] already ruled for Trade — and "see everything anyone is carrying" needs no new screen, no new mode and no new permission.
