# UI/UX Art-Asset Inventory & Reuse Map — For the Eventual UI/UX Pass

**Started:** 2026-07-02.
**Status:** Reference / research (not a spec). A compiled inventory of everything in the project that
will likely need an art/audio asset, the **special requirements** each class has (9-slice, atlas,
tint-able, animation, font metrics…), and **where assets can be reused** across surfaces. Companion
to `ui_ux_art_asset_research_2026-07-02.md` (genre/pipeline research) and the internal architecture
stance in `AGENT/Code Reviews/band_ui_initial_designs_review_2026-06-30.md`. It decides nothing;
it is the checklist the UI/UX pass and the theme/asset-resolution work should be measured against.

Grounded in the live tree as of 2026-07-02: 15 UI scenes in `scenes/ui/`, board layer in
`scripts/core/GridManager.gd`, and the current **placeholder** asset set under `assets/sprites/`
(generated by `scripts/tools/generate_placeholder_assets.gd`). Almost all real art is unbuilt —
UI is default Godot theme today, units/terrain are solid-color placeholders.

Constraints that shape every row below (from project memory / decisions):
`TILE_SIZE = 64` with a `SPRITE_SOURCE_SIZE` seam (32px @2× first release → 64px later);
committed art must be CC0 / OGA-BY (FE art is placeholder-only); all campaign art is **raw-loaded
by id/path** from `user://` per `[ICO-5/6]`; theme + assets resolve through the proposed
`UiThemeDef` registry + `AssetResolver`, never a closed enum.

**Art importer (`B6-SPRITE-IMPORTER`, `[IMP-1..6]`).** The tool that turns an FE-style character
sheet into the per-class map sprites (§2) and feeds the `ClassData.sprite_id` seam is specified in
`registers/map_sprite_importer_open_questions_2026-06-21.md` (OPEN, HELD) with the technique in
`guides/fe_map_sprite_importer_guide.md`. It is the *ingestion* side of the unit-sprite rows below
and owns the animation/`SPRITE_SOURCE_SIZE`/frame-slicing decisions this note flags as open — so the
"animation scope" gap in §Gaps resolves **there**, not here.

## Legend — "special requirements"

- **9-slice** = nine-patch stretch frame (crisp corners, stretched edges/center).
- **atlas** = pack into one padded sprite sheet for batching; pad to avoid MIP bleed.
- **tintable** = author white/greyscale source, recolor at runtime via `modulate` (one asset → many colors).
- **states** = needs normal / hover / pressed / disabled / focused variants.
- **anim** = multi-frame sprite sheet or animation.
- **SDF** = signed-distance-field font/glyph for clean scaling (matters for display-scaling + web).

## The high-value reuse levers (read this if nothing else)

1. **One white overlay tile + `modulate`** replaces the 4 colored overlay PNGs and covers every
   range/threat/target/AoE highlight; colors become theme tokens. (Board layer.)
2. **One 9-slice panel frame + one button state-set + one tooltip skin** skins *every* screen and
   every unbuilt PHB panel. This is the single biggest art-quantity reducer.
3. **One class sprite tinted per faction** (via `FactionData.color`) instead of ally/enemy/NPC
   copies — same trick for HP bars, nameplates, selection rings, phase banner.
4. **One icon per registry entry, rendered from metadata everywhere** — weapon types, conditions,
   stats, resources, skills draw identically on unit panel, forecast, shop, forge, level-up.
5. **One portrait per unit + one silhouette fallback** reused across detail / dialogue / recruit /
   arena / PvP.
6. **One `StagePresentation` (frame + portrait + background)** for dialogue *and* activity intros.
7. **One font family (SDF, with a tabular-figures variant)** for all text and all numbers.
8. **One shared VFX/SFX "reward stinger"** across level-up, promotion, arena, and forge results.

Every one of these is enabled by the already-proposed `UiThemeDef` token registry + `AssetResolver`
+ registry display metadata. Building those seams first is what makes the reuse real instead of
aspirational — matching the internal review's "define shared theme/asset resolution before Band 4-6
panels multiply."

## Gaps / open questions for the UI/UX pass

- **Animation scope:** are unit map sprites static or idle/move-animated? Drives whether §2 is one
  frame or a sheet, and the whole 32px→64px pipeline cost. **Owned by the art importer**
  (`B6-SPRITE-IMPORTER` / `[IMP-1..6]`, `registers/map_sprite_importer_open_questions_2026-06-21.md`)
  — settle it there; this note just consumes the output.
- **Autotile:** do terrain tiles need edge transitions, or flat per-type is acceptable for v1?
- **Icon authoring source:** ship a CC0/OGA-BY starter atlas for the default campaign, or text-only
  until authors supply icons? (`[ICO]` allows text-only.)
- **Which surfaces are "required art" vs placeholder-OK?** Recommendation (per band_ui review):
  almost none required; validation warnings + fallbacks everywhere.
