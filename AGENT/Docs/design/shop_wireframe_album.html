Findings raised by drawing this

Five constraints that were not previously recorded. Each is visible in a frame above, marked FINDING.

  1. Docking the action bar inverted TSV-6, so Compact no longer docks anything. The first cut pinned the purchase button and the status bar to the bottom of the step while the content clipped above them — the action was reachable before its own cost was readable, which is the opposite of what TSV-6 exists to guarantee. Compact now composes as a single scrolling column: header and back strip stay, and everything below — stats, price, quantity, consequence, warnings, the action itself — is one unit that scrolls together. The action sits after the consequence by construction, not by reminder.
  2. The failure reason is the worst casualty of the fold. In the blocked state the shortfall figure sits below it. Whatever else scrolls, the reason a commit was refused must not.
  3. 852×393 is the tightest transaction surface in the set. The 4:3 rect is 524 logical px, and a list plus detail pane leaves the detail 240px at touch tokens — the same 524px that UUI-19 already found too narrow for six Settings tabs. Two independent surfaces have now hit this number.
  4. The complex item killed the docked action everywhere — now a rule. Compact was rebuilt first, but Expanded still pinned the action to the bottom of the detail pane, and Sunder exposed what that costs: at 1024×768 and 1280×720 the pane clipped after Weapon triangle, so the price, the consequences and both warnings — including “cannot be sold, permanent for the campaign” — sat below the fold while the Buy button stayed permanently on screen. A player could commit an irreversible purchase the warning for which had never rendered. Ruled: single-scroll is the composition at every size class. The detail surface flows, the action is the last thing in it, and nothing is pinned beside content it contradicts. Consequence before action is then structural rather than a thing reviewers have to remember.
  5. 4K at 1.0 content scale is not a usable configuration. The 14px controller token is 0.36% of display height. The bounded workspace keeps the layout correct and unreadable at the same time, which is an argument for content_scale_factor defaulting by display size rather than to 1.0 — and that setting already carries reachability_risk under UUI-18.

Reading the frames

  • Dashed outline is the reserved control region — the game view's leftover, per UUI-1/2/3. Present on the four touch viewports, absent on desktop.
  • Single-scroll everywhere. Every detail surface flows and ends in its own action; nothing is docked. The hairline on a pane's right edge is the scroll thumb, and every extent quoted in a caption is measured from the rendered layout, not estimated.
  • The left column at Expanded is the shopper's character sheet, because the question in a shop is not what an item costs but what it does to this unit — so the sheet carries the equipped-weapon comparison for whatever is selected.
  • Dashed ring on a row is focus; filled with a left bar is selection. The two are never the same state — a highlighted row must never carry a generic buy action (TSV-8).
  • Hatched fill at 1440p and above is deliberate dead space. The workspace is bounded and centred; nothing stretches (UUI bounded-workspace rule).
  • Monospace values are metrics read from ResponsiveLayout.DENSITY_TOKENS, not invented.

What this album does not decide

  • TSV-10..24 remain open; frames drawn against a recommendation carry the ID in grey.
  • SHP-1..5 are still open in their own register — prices shown are illustrative.
  • Paint is not specified here. Under UUI-16 the shop sits inside the pack theme boundary, so every surface in these frames is repainted by the active pack.
  • No engine seam is proposed. ResourceLedger.quote/commit already exists; the checkpoint participant registry in TSV-3 does not.
