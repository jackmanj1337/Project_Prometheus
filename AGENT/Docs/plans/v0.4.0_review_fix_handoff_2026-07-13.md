## Work items, in the order to do them

### 1. Death funnel — F1 + F3 (RC blocker)

One commit; the test is what proves the fix.

- `scripts/core/CombatResolver.gd:954-963` — delete both
  `elif ...has_method("handle_death")` branches. If `/root/DeathLifecycle` is
  null, `push_error` and return without processing death.
- `scripts/units/Unit.gd:491-497` — leave as a pure delegate. Do **not** restore
  an inline disposition (D2).
- New test at the `CombatResolver` level for mutual death: both contexts share a
  `simultaneous_group_id`; each snapshot captured tile and inventory before
  *either* unit was freed; the defender's disposition ran first.

Why F1 is real: the fallback is circular. `Unit.handle_death()` is itself a
delegate to `DeathLifecycle`, so the `elif` only fires under exactly the
condition that makes it a no-op. With the autoload absent, a unit at 0 HP is
never unregistered, never emits `unit_died`, and is never freed — it keeps taking
turns and rout objectives can never complete.

Why F3 is what let F1 through: `simultaneous_group_id` and `responsible_actor`
appear in **zero** test files. `test_combat.gd:585` asserts mutual kill only on
result-dictionary flags computed *before* the death block — deleting the whole
snapshot/ordering rework would still pass. `MockUnit.handle_death()`
(`test_combat.gd:125`) is now dead code, so the broken branch is never exercised.

### 2. Map-start placement — F2 (RC blocker)

- `scripts/core/GameMap.gd:350` — `_place_and_spawn` default policy
  `require_empty` -> `nearest_free`.
- `push_warning` when `result.fallback_used`, naming unit, authored tile, and
  landing tile.
- Drop `all_placed` (`:216,245`). `_spawn_units()` returns false only for
  structural failures (missing `map_data`, missing `GameState`, empty roster). A
  placement failure skips the unit and the map still boots.
- `scripts/autoloads/DataManager.gd` — add the missing bounds check for enemy
  placement tiles. Player starts and `camera_start_tile` are bounds-checked;
  enemy tiles are not.

Watch: `nearest_free` tie-breaking is distance, then y, then x — a total order
over distinct tiles, so it is deterministic without needing source order. Players
spawn before enemies, so on a collision the player keeps the authored tile.

Do not weaken DataManager validation to compensate. The occupancy fallback is a
runtime safety net; authored duplicate starts and enemy/player overlap must still
hard-error at boot.
