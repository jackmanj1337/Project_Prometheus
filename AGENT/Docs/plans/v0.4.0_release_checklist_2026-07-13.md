# v0.4.0 Release Checklist

## Release definition

v0.4.0 is the **Band 2 shared authoring/runtime contracts release**. Its purpose
is to establish tested extension seams that later campaign, economy, tactical,
and AI features can consume without adding private mutation paths or closed
content switches.

This is a foundation release, not a promise that every later consumer of each
contract ships in v0.4.0. A row passes when its stated v0.4.0 slice is sound,
integrated with its first production consumer where required, documented, and
covered by regression tests.

## Included feature slices

The next-session review must assess each row against its design contract,
implementation plan, production wiring, failure behavior, and tests.

### 1. `B2-REGISTRY` - registry manifest foundation

- [ ] Registry entries/catalogues/managers preserve deterministic ordering.
- [ ] Duplicate ids, missing handlers, malformed schemas, and invalid
  composition references fail clearly.
- [ ] Starter families (`action_primitives`, `resource_types`,
  `occupancy_policies`) are export-safe and data-defined.
- [ ] Adding content to an open family does not require a new engine `match`.
- Evidence: `test_registry_manager.gd`, DataManager registry validation.

### 2. `B2-ACTION-EFFECT` - action/effect primitive runner

- [ ] Request, context, and result contracts report structured validation and
  execution outcomes.
- [ ] Unknown/malformed/dry-run requests do not mutate live state.
- [ ] Handler lookup is registry-backed and mutating primitives declare their
  save-field ownership.
- [ ] `ItemHandler.stat_buff` remains behaviorally equivalent through
  `apply_active_modifier` delegation.
- Evidence: `test_action_effect_runner.gd`, `test_skill_item_handler.gd`.

### 3. `B2-RESOURCE-LEDGER` - fixed-wallet transaction groundwork

- [ ] Quote and reserve are non-mutating; commit is atomic across wallets.
- [ ] Refund uses recorded deltas rather than recalculating costs.
- [ ] Party/unit wallet bindings and unknown-resource failures are correct.
- [ ] Victory gold uses the ledger; guarded code contains no unauthorized direct
  `party_gold` writes.
- Evidence: `test_resource_ledger.gd`, `test_turn_manager.gd`, documentation
  check 28.

### 4. `B2-OCCUPANCY` - map-start placement groundwork

- [ ] `require_empty`, `nearest_free`, `delay`, and `skip` return structured,
  deterministic results.
- [ ] Nearest-free tie-breaking is distance, then y, then x, then source order.
- [ ] Reserved policies fail as not implemented rather than silently placing.
- [ ] Map-start spawning and duplicate-placement validation use the service;
  public spawn paths do not bypass it.
- Evidence: `test_occupancy_service.gd`, `test_game_map_scene.gd`,
  `test_data_manager.gd`, documentation check 29.

### 5. `B2-DEATH-LIFECYCLE` - combat death funnel groundwork

- [ ] Death contexts snapshot identity, tile, inventory, and simultaneous group
  facts before disposition begins.
- [ ] Mutual death preserves defender-first handling after both snapshots exist.
- [ ] Classic/casual incapacitation, Pair Up release, unregister, event emission,
  and queue-free behavior remain correct.
- [ ] Compatibility calls delegate to the lifecycle and inventory disposition is
  an explicit no-op in this slice.
- Evidence: `test_death_lifecycle.gd`, `test_combat.gd`,
  `test_pair_up_registry.gd`, `test_turn_manager.gd`.

### 6. `B2-PROJECTION` - combat forecast adapter

- [ ] Projection context/result shapes match the shared forecast contract and
  unknown kinds/invalid targets return structured failures.
- [ ] Combat projection delegates to `CombatResolver.preview_combat()` instead
  of re-deriving combat math.
- [ ] Attack Preview consumes the projection service.
- [ ] Projection preserves unit state, resource fields, and committed RNG
  history while reporting odds with zero committed draws.
- Evidence: `test_projection_service.gd`, `test_combat.gd`, Attack Preview
  selector/position suites.

### 7. `B2-DATAMANAGER-SEAMS` - load/validate/replace-load seams

- [ ] `_ready()` composes explicit clear, load, validate, and report phases.
- [ ] Default loading remains behaviorally equivalent.
- [ ] Alternate self-contained sources replace rather than merge catalogues, and
  all map/Pair Up cross-references resolve against that source.
- [ ] Missing catalogues fail loudly and campaign source selection remains inert
  and unsaved until a real selector owns it.
- Evidence: `test_data_manager.gd`, `test_data_layer.gd`.

## Deliberately deferred from v0.4.0

The review must not turn these into release blockers unless the included slice
accidentally claims or partially implements them:

- Requirement predicates, formula terms, custom resource pools, and persistent
  reservations (`B3-REQ`, `B3-RESOURCE-POOLS`).
- Action UI and broad producer migrations.
- Occupancy `swap`, `overlap_hidden`, and `object_unit`; persistent delayed spawn.
- Non-combat death producers, key-item/inventory custody, battalions, and object
  teardown.
- Effect, condition, AI, predicate, and perception projection adapters.
- Campaign browser/selector UI and persisted campaign-source choice.
- Band 3 campaign rules, MET, PHB, text, movement/vulnerability, and extensible
  stat storage.

## Next-session code review procedure

- [ ] Review the complete v0.4.0 delta from the agreed base commit, not only the
  last slice.
- [ ] Trace each included service from public API to at least one production
  consumer or explicitly documented foundation-only boundary.
- [ ] Check mutation atomicity, failure paths, deterministic ordering, autoload
  order, missing-autoload behavior, save/F1 ownership, and registry openness.
- [ ] Compare implementation with all seven Band 2 design contracts and Slice
  1-7 plan requirements; record mismatches by severity and file/line.
- [ ] Audit tests for false-positive fixtures that bypass production wiring.
- [ ] Write the review under `AGENT/Code Reviews/` and route every actionable
  finding to a fix, explicit deferral owner, or accepted-risk decision.
- [ ] Re-run this checklist after the fixes; no High or Medium findings may remain
  open for the release candidate.

## Release-candidate gates

- [ ] Review gate: all seven included slices checked; no open High/Medium finding.
- [ ] Scope gate: deferred items remain accurately documented and do not have
  misleading partial UI/content exposure.
- [ ] Test gate: `bash run_tests.sh` passes.
- [ ] Documentation gate: `python3 AGENT/Docs/check_docs.py` passes.
- [ ] Determinism gate: `bash scripts/ci/check_rng_usage.sh` passes.
- [ ] Import gate: headless Godot boot/import reports no script/resource errors.
- [ ] Metadata gate: project/build metadata is bumped to `v0.4.0` only after the
  review and fix gates pass.
- [ ] Build gate: create the v0.4.0 debug build and record source commit, file
  size, SHA-256, and export result in `playtest_build_v0.4.0.md`.
- [ ] Smoke gate: boot, start a map, open Attack Preview, complete one combat,
  verify victory gold, suspend/continue once, and retain the log.
- [ ] Handoff gate: write a v0.4.0 playtest/reviewer handoff describing the
  foundation nature of the release and the deliberately deferred consumers.

## Exit condition

v0.4.0 is release-candidate ready when every release-candidate gate above is
checked with evidence. Marking the seven control-plane rows Implemented is not,
by itself, sufficient evidence for release.
