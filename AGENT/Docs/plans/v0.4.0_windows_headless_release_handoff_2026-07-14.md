# v0.4.0 Windows Headless Build and Smoke-Test Handoff

## Outcome

Produce a traceable Windows x86-64 debug build of v0.4.0 entirely through the
headless toolchain, document its exact identity, and hand it to the owner with
the full Windows playtest checklist below. The returned playtest is the v0.4.0
smoke test; do not create a second, overlapping smoke pass.

The desktop-Web/itch.io release stream is on hold. Do not add a Web preset,
export a Web artifact, configure itch.io, or reopen mobile/browser decisions in
this slice.

Release ownership and the seven Band 2 rows remain in the
[`Project Control Plane`](project_control_plane_2026-06-29.md); this handoff is
the Windows build-and-validation execution source for that release gate.

- Start from clean branch `agent/codex/2026-07-14/v0.4.0-integration` at
  `d32715665408539994782d524a10f141e537fa9e` or a verified descendant that
  contains the accepted v0.3.6 fixes and closed v0.4.0 review gate.

  `agent/**` branch. Never push directly to the integration or main branches.

  `Project_Prometheus_v0.4.0_debug.exe`.

- Do not sign, publish, upload, or commit the generated executable.

## Required headless work

### 1. Establish the baseline

Record the starting commit, branch, dirty/clean state, and Godot version. Run:

```bash
bash scripts/check_env.sh
python3 AGENT/Docs/check_docs.py
bash scripts/ci/check_rng_usage.sh
bash run_tests.sh
git diff --check
```

Run the repository's normal headless Godot import/boot validation as well. Do
not continue past an unexplained script/resource error or failing release gate.

### 2. Lock v0.4.0 metadata

Update the existing Windows preset and release-facing metadata together:

- preset name: `Project Prometheus v0.4.0`;
- preset export path: `./builds/Project_Prometheus_v0.4.0_debug.exe`;
- `application/product_version`: `0.4.0`;
- Main Menu version label: `v0.4.0`;
- environment/setup guide current-version text and commands: `v0.4.0`;
- versioned checklist: `AGENT/Docs/playtests/playtest_checklist_v0.4.0.md`;
- release metadata coverage for the same name, path, product version, label,
  checklist, guide, and development-file exclusions.

Copy the complete checklist in this handoff into the versioned checklist. Keep
the Windows preset's existing x86-64 debug, embedded-PCK, compatibility, and
development-file exclusion contract. Do not add a Web preset or change signing.

Run all baseline gates again and commit the metadata/checklist slice before
baking the build stamp. The artifact must identify a committed source state.

### 3. Bake and export the build

From the clean committed source state:

```bash
bash scripts/tools/prepare_build.sh

godot --headless --path . \
  --export-debug "Project Prometheus v0.4.0" \
  builds/Project_Prometheus_v0.4.0_debug.exe
```

Confirm `build_info.json` contains version `0.4.0`, the intended short commit,
and a current UTC timestamp before export. `build_info.json` is a generated,
ignored build input; do not commit it.

### 4. Prove and record the artifact

The export is not accepted merely because Godot returned zero. Verify:

- the expected executable exists and is non-empty;
- `file` identifies a PE32+ x86-64 Windows GUI executable;
- the baked version, commit, and timestamp match the intended build;
- the source commit and whether the source tree was clean are recorded;
- exact byte size and SHA-256 are recorded;
- Godot version, preset name, platform, debug/release mode, and embedded-PCK
  choice are recorded;
- export stdout/stderr contains no release-blocking error.

Create `AGENT/Docs/playtests/playtest_build_v0.4.0.md` with those values and
state `Exported - pending live Windows smoke`. The executable remains under
`builds/` and outside Git. Regenerate `AGENT/Docs/INDEX.md` after adding the
manifest and checklist.

### 5. Final headless closeout

Run the full gate set once more after all documentation is present. Update
[`v0.4.0_release_checklist_2026-07-13.md`](v0.4.0_release_checklist_2026-07-13.md)
only for facts actually proven:

- close the metadata gate when its tests pass;
- close the build gate when the artifact and manifest are proven;
- leave the smoke gate open until the completed checklist and log return;
- leave the final handoff gate open until the returned smoke evidence is
  incorporated, unless the gate wording is explicitly adjusted to distinguish
  build handoff from accepted playtest return.

Write a session note and index it. Commit the manifest/documentation closeout.
Hand back the ignored executable together with the manifest and versioned copy
of the checklist below. Do not claim Windows runtime behavior from headless
tests and do not mark the smoke PASS in advance.

The headless session is done when the v0.4.0 metadata gates are green, the
ignored executable exists and matches its manifest, all automated gates pass,
