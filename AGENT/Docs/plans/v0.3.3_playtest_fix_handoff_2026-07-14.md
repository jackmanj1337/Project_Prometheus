## Implementation order

Keep each numbered slice in a narrow commit with its behavior docs and tests.

### 1. Analog trigger input has one owner

Primary files:

- `scripts/core/MapCursor.gd`
- the existing MapCursor/zoom test suite; add a focused fixture if the current
  suite cannot inject both joy-axis events and polled strength clearly

Change:

- Prevent `InputEventJoypadMotion` for `zoom_in`/`zoom_out` from taking the
  immediate `_unhandled_input()` path.
- Keep keyboard, mouse wheel/button, and discrete action presses immediate.
- Let `_poll_held_zoom()` exclusively apply analog-trigger activation and repeat.
- Preserve the first step at threshold, `0.65s` delay/rate, release-to-rearm, both
  directions, persistence, and Action Menu re-anchoring.

Required tests:

- ramp `0.0 -> below 0.85 -> 0.85 -> full` gives `0 -> 0 -> 1 -> 1` steps before
  repeat delay;
- holding through the delay gives only the expected repeat;
- release then repress gives one new immediate step;
- LT and RT take the same temporal path;
- keyboard/mouse immediate zoom remains unchanged.

### 2. Threat view belongs to the controlling faction

Primary files:

- `scripts/core/MapCursor.gd`
- `scripts/autoloads/GameState.gd`
- `scripts/save/SaveData.gd` and the owning save codec/manifest if required by
  the repository's F1 contract
- `scripts/tests/test_mrd_scene.gd`
- `scripts/tests/test_suspend_map_runtime.gd`

Resolved contract:

- Own `{watch_set, danger_mode}` by faction id.
- On `set_controlling_faction()`, save outgoing view state, load/default incoming
  state, and render only the incoming faction's markers/overlays.
- An allied or friendly unit must never remain marked merely because another
  faction watched it.
- Pruning uses the owning faction's hostility relationship, not only liveness.
- Action/Map Menu threat composition continues to use the active faction view.
- Enemy-phase locks may hide paint, but must not merge or overwrite faction state.

Persistence:

- Replace the single suspend representation with a versioned
  `threat_views_by_faction` shape.
- Decode the old `watch_set`/`danger_mode` fields as the saved controlling
  faction's view for backward compatibility.
- Do not add player/seat identity or allied sharing policy.

Required tests:

- blue, red, and green maintain independent set/mode pairs across handoffs;
- only the active faction's markers render;
- an incoming faction can add/remove its own hostile watches normally;
- alliance/hostility changes and unit death prune invalid members;
- suspend round-trip retains every faction view and legacy single-set input loads;
- the already-passing menu-retention, phase cleanup, and `dual_outline` tests stay
  green.

### 3. Action Menu width follows scaled content

Primary files:

- `scripts/ui/ActionMenu.gd`
- `scenes/ui/ActionMenu.tscn`
- `scripts/tools/ui_inspection_preview.gd`
- `scripts/tests/test_action_menu.gd` or a focused layout test

Change:

- Keep 128 px as the unscaled design floor.
- After visibility and Menu Scale are applied, calculate the widest visible
  label's minimum width plus effective horizontal style/content margins.
- Set the menu minimum width from that result before `_place_menu_near()` reads
  its final size.
- Do not clip, truncate, globally shrink the font, or hardcode around `Pair Up`;
  `Separate` and future registry-driven labels must fit through the same rule.

Required tests:

- every visible label fits its button content rect at all seven Menu Scale factors;
- opening near both viewport edges still flips/clamps using the final width;
- changing which rows are visible recomputes width without stale expansion bugs.

### 4. Focus lookahead measures visual rows

Primary files:

- `scripts/ui/ModalScreen.gd`
- `scripts/ui/SettingsScreen.gd` only if a clean owner-row hook is needed
- Settings and Unit Details UI tests

Change:

- Resolve a focused leaf control to its direct visual list row under the scrolling
  VBox/content owner.
- Use the next three visible sibling row heights when available; fall back to the
  owner row height instead of the leaf slider height.
- Preserve the below-half-viewport cap, end clamping, reachability, and no-
  horizontal-scrollbar behavior.

Required tests:

- mixed HSlider/OptionButton rows at 2x show the available upcoming context;
- 0.5x and 1x behavior does not regress;
- both list ends clamp cleanly;
- Unit Details custom selector, paired entry, and Back remain reachable.
