## Recommended next slice: `B2-ACTION-EFFECT` contract groundwork

Build only the portion that does not require the unfinished `B3-REQ` predicate
system:

1. Define small structured action/effect request, execution-context, and result
   types at the paths named by the Band 2 plan.
2. Resolve primitive handlers through `RegistryManager`; do not add a closed
   enum or `match` over author-facing primitive ids.
3. Validate the primitive id and parameter schema before any mutation.
4. Guarantee invalid requests return a structured failure and mutate nothing.
5. Add focused headless tests for unknown primitive, malformed params,
   deterministic handler lookup, success result, and no-mutation-on-invalid.
6. Use `apply_active_modifier` as the behavior-preserving proof primitive only
   if the existing modifier lifecycle can be reused without changing player
   behavior or save state.

Explicitly defer:

- requirement-gated action availability/execution (`B3-REQ` owns predicates);
- promotion recovery UI or a new `ActionMenu` row;
- MET, dialogue, SAC, Source/Style, shops, objectives, or activities;
- persistent action state not already represented in the F1 manifest;
- broad `ItemHandler` migration if the proof primitive exposes hidden behavior
  differences.

If the proof primitive cannot remain behavior-neutral, stop after the typed
contract, registry resolution, validation, and no-mutation tests. Record the
blocker instead of widening the slice.
