# v0.7.0 pre-bundle handoff (non-fog scope)

## Purpose

This is the work order for the next tester bundle after v0.6.1. The candidate
base is the consolidated `agent/integration` line described in
`AGENT/Session Notes/2026-08-04-21-00-00Z-v070-consolidation.md`.

The goal is a coherent bundle that tests the mobile/web controller and PWA
path, responsive UI, browser transfer, and the self-contained campaign-pack
architecture. Do not expand this bundle into unrelated roadmap work.

## Explicit exclusion

**Fog is not part of this handoff.** Do not gate the bundle on fog rendering,
enemy hiding, fog visual validation, discovered-unit persistence, or authored
reveal tools. The existing fog tracker rows remain authoritative for that work.

## Must do before cutting the bundle

### 1. Close the consolidated candidate

- Confirm all already-built product branches intended for v0.7.0 remain
  reachable from the exact candidate commit: terrain variants/runtime terrain,
  crossing resolver, responsive UI, PWA integration, dedicated touch controls,
  browser transfer, viewport anchoring, text entry, and the mobile controller.
- Resolve any remaining review rows against their actual merged content rather
  than re-merging content that is already present under different hashes.
- Freeze the candidate once these checks pass; later feature work starts from a
  new branch and does not silently enter the bundle.

### 2. Finish and validate the self-contained tester pack

- Complete `IMPL-ZERO-CONTENT-BASE-PACK`: the engine must not rely on hidden
  `res://data` defaults, and the tester campaign must be a normal,
  self-contained pack.
- Run the base-pack extractor and pack validator against both the private FE
  preservation pack and the public Proving Grounds pack.
- Resolve the recorded numeric/provenance dispositions before distributing an
  affected pack. Do not treat similar-looking assets or values as sharing one
  provenance conclusion.
- Prove the tester flow from a genuinely inactive state: no pack installed,
  install pack, select it, launch its bundled map, save, exit, reload, continue.

### 3. Finish the mobile/web release path

- Complete `MOBILE-WEB-CONTROLLER-2026-08-04`, including its remaining layout,
  settings, shell, input-mode, and old map-overlay cleanup slice.
- Complete `MOBILE-WEB-UX-GAPS-2026-08-03`: `web_ios`/`web_android` touch-mode
  detection, JavaScript-provided safe-area insets, portrait handling, and a
  readable mobile-web default scale.
- Complete `IMPL-WEB-FILEDIALOG-SHIM-2026-07-31` so campaign-pack and save
  import/export reach the user's real device instead of only browser `user://`.
- Close the FileDialog/text-entry first-Escape and ownership behavior on the
  candidate, including controller and hardware-keyboard paths.
- Serve the PWA through HTTPS. A plain-HTTP page rendering successfully is not
  evidence that installation, service workers, offline launch, or durable
  storage work.

### 4. Reconcile release identity and carry-forward requirements

- Close `VERSION-DRIFT-INTEGRATION-2026-08-03`. Update the release version,
  export preset names/paths, main-menu label, metadata tests, checklist, setup
  guide, and BUILD STAMP inputs together.
- Reconcile `PP-V060-CHECKLIST-CARRYFORWARD-2026-07-29` against returned
  evidence. Anything not actually proven must appear explicitly in the new
  checklist; do not close it merely because it appeared in the v0.6.1 bundle.
- Give the new checklist stable sections for Windows, controller, web/PWA,
  mobile device, campaign-pack lifecycle, save recovery, and artifact/log
  return requirements.

### 5. Validate the exact candidate and assemble reproducibly

- Run the full automated suite on the exact candidate commit.
- Export the intended platforms from that same commit and reject stale export
  artifacts.
- Regenerate the complete labeled Playwright responsive album and compare it
  with the v0.6.1 reference. A passing navigation count alone is insufficient;
  review frame dimensions and visual changes.
- Perform the outstanding Windows visual pass for responsive layouts and
  terrain variants. Fog remains excluded from this pass.
- Record each artifact's filename, size, SHA-256, version, baked commit, build
  mode, and build timestamp.
- Assemble the tester bundle through the bundle tooling and verify its manifest
  names the exact exported artifacts and checklist.

## High-value work to include if it does not destabilize the cutoff

These improve what the bundle can prove. They are below the must-do boundary:
if one expands materially or destabilizes the candidate, leave it tracked and
cut the focused bundle without it.

### A. Transactional package registry composition

Implement `DESIGN-IMPLEMENT-PACKAGE-REGISTRY-COMPOSITION-2026-08-02` far enough
to prove that engine registry primitives survive pack activation, valid pack
contributions appear only while that pack is active, invalid contributions fail
atomically, and switching/unloading restores the exact baseline. Preserve the
one-active-self-contained-pack rule; do not introduce cross-pack collision or
load-order semantics.

### B. Save-package provenance and recovery UX

Implement `IMPL-SAVE-PACKAGE-RECOVERY-PROVENANCE-2026-08-02` with the existing
pack-save schema work: snapshot informational package identity/provenance in the
save, distinguish missing/version/hash/invalid/incompatible failures, and give
the player escaped, actionable recovery text. The snapshot must never activate
or substitute for an installed pack.

### C. Physical-device PWA validation before wider tester distribution

Complete `IOS-DEVICE-PWA-VERIFICATION-2026-08-03` on real WebKit hardware:

- install and offline relaunch;
- at least a 30-minute memory/play soak;
- cache size and persistence behavior;
- save durability across close/relaunch;
- import and export of a save and campaign pack;
- portrait and landscape behavior, notch/home-indicator safe areas, and
  physical text/control legibility;
- audio after the first gesture and mute-switch behavior.

If this is impossible before the bundle is assembled, keep distribution to the
owner and label the PWA path unverified rather than presenting Chromium results
as iPhone acceptance.

### D. Candidate-facing recovery diagnostics

Where failures remain possible, prefer bounded player-facing diagnostics over
raw logs: identify the missing/invalid pack, state that progress was not
modified, and offer Manage Campaigns, Retry, or Back where appropriate. Keep
filesystem paths and underlying technical diagnostics in logs.

## Cutoff rule

Cut the bundle when every must-do item above has either passed or is represented
as an explicit, testable checklist item that genuinely requires the tester's
hardware. Do not keep adding roadmap features once the candidate is frozen.
High-value items may be deferred; hidden gaps in pack activation, transfer,
release identity, exact-commit evidence, or bundle reproducibility may not.
