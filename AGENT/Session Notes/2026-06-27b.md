## 1b. Thread (b) deep-dive — VAL-6 vocabulary + VAL-11 dancer-timing (same session)

**`[VAL-6]` forecast term-sources = REQ-15 applied to combat (RESOLVED).** The decisive finding: combat
outcome must be **delegated, not composed in a term tree** — `_run_strike_series` (`CombatResolver.gd:640`)
stops the instant a side dies + Vantage/follow-up reorder, so `per_hit × attacks × hit%` **overcounts** a
kill (the same reason REQ-15 delegates condition outcome to F5). Resolution: **(a)** a new
`CombatResolver.forecast_outcome(atk, def, ctx)` projection API (probabilistic, fixed-point — also the home
for a player "likely to kill" preview + action-preview, the REQ-15 "one projection the UI uses"
principle); **forward-req: `preview_combat` gains a hypothetical `ctx = {from_tile, weapon}`** (today reads
live tile/equipped weapon, `:553`). **(b)** term-sources delegate to it (`forecast_expected_damage`/
`p_kill`/`damage_taken`/`p_self_death`/`overkill`/`hit_chance`/`crit_chance`); `would_kill` = a named
composition `ge(max_damage, hp)` with **no floor-delegation** (combat just kills — cleaner than REQ-15).
**(c)** forecast terms are **context-scoped** — bound to a candidate action by the AI/preview context,
exactly as REQ-3 `speaker`/`participant` subjects are context-resolved; a validator rejects them elsewhere.
`post_move_exposure` (threat-range aggregate, `[VAL-2]`) and `target_value` (`ai_target_weight`, `[VAL-7]`)
are *separate* families, not forecast sources.

**`[VAL-11]` dancer-timing RESOLVED (was PARTIAL).** Key realization: greedy `[VAL-8]` already handles the
**consequence** with **no forward-model** (a grant only re-flags an ally READY — mutates no positions — so
the refreshed ally's high-value action is scored next greedy iteration). The only gap is the dancer knowing
*in advance*. **Two-tier (owner call):** complete fix = `search_depth ≥ 1` (dancer quality scales with
depth, deferred with the forward-model); **v1 = a bounded enablement heuristic (BUILD IT)** — a grant
scores as the best static action its grantable allies could take now (1-ply peek over only the grant's
targets, no board mutation, reuses the scorer; generalizes to any `grant_action`, no dancer-only path).
