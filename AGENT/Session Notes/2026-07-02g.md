# Session Note - 2026-07-02g

## Topic
Retire the long-standing **OGG/TTF raw-load spike** — the one hard technical
unknown blocking the Tier-1 media-loader seam (and, downstream, the `UiThemeDef`
/ asset-resolution note that wants to lock font/audio tokens). Prove the runtime
raw-load API from `user://` works **outside the editor `.import` pipeline**, in a
real exported build. No production code changed; this de-risks the seam.

## What was done
Ran the spike end-to-end in **Godot 4.6.stable** (the project's exact version).
Findings, strongest first:

- **API surface (ClassDB, 4.6):** `AudioStreamOggVorbis.load_from_file` /
  `load_from_buffer`, `AudioStreamWAV.load_from_file`, `AudioStreamMP3.load_from_file`,
  and `FontFile.load_dynamic_font` / `load_bitmap_font` all present.
- **Real decode/load in the editor/headless binary:**
  - OGG: a real 6.1 s Ogg Vorbis file decoded from `user://` **and** from a raw
    byte buffer (`load_from_buffer`).
  - TTF: system DejaVu `.ttf` loaded via `FontFile.load_dynamic_font` — err 0,
    real font name + glyph metrics (ascent computed → FreeType path works headless).
  - WAV: built PCM in-memory → `save_to_wav("user://…")` → `load_from_file` round-trip.
- **Genuine exported-build proof (the part the spike explicitly demanded):**
  exported a throwaway **Linux x86_64 debug template** (templates for 4.6.stable
  are installed), pointed its main scene at a spike node, and ran the real binary
  headless. It reported `running_in_editor=false` and still loaded **OGG (6.1 s),
  TTF (err 0, DejaVu Sans), and WAV (0.045 s)** from `user://`. So the codecs
  (libvorbis / FreeType) survive templating — confirmed, not assumed.

The one honest caveat retained: PNG's `Image.load_from_file` path was already
proven-in-principle; I did not re-run it this session (it was never the open leg).
