## 1. The end-user shape (owner's richer vision)
**One full-screen overlay, two regions, ONE renderer:**
- **Scene region (top)** = a **layered stage**: a **background layer** = the **live map (toggleable
  transparency)** *or* an **authored special background**, with **animated portraits layered on top**.
- **Chat-log region (bottom)** = a **script-style** running log (`SPEAKER: text`), scrollable.
- Because the background can BE the map, **battle one-liner and story scene are the same overlay** with
  a different background — collapses the old "in-map box vs scene" fork into one renderer.

**Controls (author-configurable, all three):** manual / **skip-to-next-decision** / auto-advance.
**Branching choices** designed in now. **Portrait animations** sync to advance (`loop | once`-then-hold).

## 2. What it made obvious (the owner's goal)
- **Data format → a flat, addressable entry list.** Conversation = `{id, entries[]}` of
  `line`/`choice`/`command`/`label`. Background change = a **`command`** (so scenes shift mid-convo);
  branching = `label` + `goto`; names/text = **F13 keys**. Plain data (Dictionary/Resource).
- **Authoring → plain data now + a dedicated editor later.** The layered-animation/branching/
  scene-command richness makes hand-JSON painful → a **conversation editor (timeline/node) emitting
  the same plain data** is the dialogue-specific answer to the deferred 4a–4e GUI-vs-JSON question;
  simple linear convos stay hand-authorable in the interim.
- **One renderer**, not two (the map-as-background insight).

## 3. Three-tier effect taxonomy (owner expansion mid-walk)
- **(A) Character effects** — expression changes (per-character asset set).
- **(B) Portrait transforms** — generic, layer on ANY portrait: **flip/mirror** (simple inversion, not
  a separate asset), **move/translate**, scale.
- **(C) Scene-wide effects/filters** — **rain**, **fog drifting over characters**, **wavy flashback
  transition**, colour washes.
- Each parameterized + playback mode **`loop | once | loop_until<condition>`** — `loop_until` headline
  = **loop a mouth-flap until the line's text finishes scrolling** (owner add). Effects also carry a
  **`speed`** parameter, with a possible **global animation-speed player setting** (owner add, soft
  reserve). Composable (B on portraits, C over the scene); author-extensible vocabulary.

### DLG-11 — mid-conversation save (owner question, answered + firmed)
The entry-list format supports it **very well** — entries are an **ordered, addressable list**, so a
resume = a tiny cursor. **Granularity = entry boundaries ("between speaker")**: a save sits after a
`line` completes, before the next entry; **no mid-typewriter state** serialized. Resume state =
`{conversation_id, cursor}`; **"who last finished their line" is DERIVED** (`entries[cursor].speaker`),
not stored. **History:** linear convo → log is **replay-derivable** from `entries[0..cursor]` (store
nothing); **branching** convo → store a **`visited_trail`** (entry ids shown) which reconstructs the
log AND the branch taken (branch flags also in F6). **Format constraint:** entries need **stable
addresses** (the DLG-8 editor honors this). **Ties** L1 SaveManager + `[MET-8]` (a playing `dialogue`
joins the suspend snapshot). **F1 reserve (supersedes DLG-10's "no new field"):** a
`conversation_resume = {conversation_id, cursor, visited_trail?}` block in the suspend/save.
