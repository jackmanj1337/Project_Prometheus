### Owner decisions (2026-07-07)

1. **Human-readable cfg ([ICD-5a-i]) — confirmed in scope** as the slice-1 foundation
   (per-device-slot dict, plain-token serialization, one-version migration from the old
   `Object(InputEventKey,…)` blob form).

2. **ICD-6 AMENDED — swap → batch apply-block.** The 2026-06-21 resolution was live two-way
   swap. Replaced with a **staged pending buffer**: captures accumulate without going live;
   a same-device-slot collision marks **both rows red**; **Apply is disabled while any
   conflict is unresolved**; each conflicting row has a **per-row Clear** (a legit A↔B swap
   is a two-tap manual gesture); **Revert** discards the buffer. Rationale: revertable, no
   surprise second-action mutation, and — because staged edits never go live — the player
   **cannot self-trap mid-edit** (Apply stays reachable via still-applied bindings,
   complementing the ICD-5 always-visible Reset).

3. **ICD-8 ADDED — named control-scheme profiles.** Owner: profiles belong in **v1 but NOT
   v0.3.0**. A profile is pure data — a named map of `action → {kbd,pad}` (on-theme with the
   `[EXT]` open-registry principle) — and composes cleanly with ICD-4 slots (the slot dict
   becomes the profile's *value*). Decision = **structure-for-later now**: slice 1 nests the
   maps under an implicit `"Default"` profile (`active_profile`, `profiles[...]`) so the
   later profile-management UI is **additive with no second format migration**. Profile UI
   itself is out of scope for v0.3.0.
