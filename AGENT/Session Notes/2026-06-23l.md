## Part 4 — Effects/XP review → unified Proficiency/XP Framework `[PXP-1..8]` (RESOLVED)
Owner asked to review what benefits/effects/uses items can express + how XP is stored/gained.
**Grounded audit:** three existing effect subsystems the unified model can REUSE — stat
modifiers (`add_modifier`, any UnitData stat, `until_unequipped` wiring = on-equip add /
on-unequip remove, no engine change), weapon `effect_tags` (effective_*/heal; poison/crit-
immunity/ignores-def still unimplemented), and the skill trigger/dispatch system (~18 impl,
~12 stubs) — so accessory effects = **modifiers + skill-grants**, not a new engine. Iron Rune
crit-immunity is the one real gap (needs a combat hook or `on_defend` skill). WEXP today =
`weapon_wexp` dict + hardcoded `WEXP_RANK_THRESHOLDS` (E0..S500) + per-use gain + class caps +
hardcoded S→`s_rank_mastery`.

**Owner expanded scope** → a unified XP/rank framework for **weapons AND items**, firmed as
`[PXP-1..8]`:
- **PXP-1** one `UnitData.proficiency_xp` store (weapon_wexp migrates in).
- **PXP-2** three track kinds: weapon-family / **item-group** (skill-with-shields) / **item-bond**
  (relic); item declares its tracks, can feed both.
- **PXP-3** rank profiles = **CampaignRules** (thresholds **+ names**), named, per-track; default
  profile = E–S (non-breaking).
- **PXP-4** per-threshold **on-crossing events** (grant_skill); S→s_rank_mastery becomes a
  default-profile trigger.
- **PXP-5** author-defined **multi-source gain** (active_use / class_exp_share / per_map_carry /
  action_gated), **track-default + per-item override**; weapons default to active_use.
- PXP-6 caps (profile ceiling + preserved weapon class caps), PXP-7 GDD reconcile (revisits
  GDD_04 SET-004/RULE-004 **non-breakingly**), PXP-8 save reservation.
- **Intentionally revisits firmed weapon WEXP** (owner's call) — non-breaking via the default
  profile. IEQ-3/8 + design doc + scope-map row "WEXP & equipment legality" reconciled to hand
  proficiency/ranks/gain to PXP.
