## 2. Code-grounded substrate
- **Pair-Up already solves "two units, one tile":** `PairUpRegistry` parks the support unit at
  `OFF_MAP_TILE (-1,-1)`; snapshotted with `GameState._map_start_snapshot`. Carry mirrors this.
- `GridManager.get_unit_at` = single occupancy lookup; pathfinding respects occupants.
- **Engine already models "teleported-but-still-READY"** (`record_move_start`/`undo_move`, the "moved
  without spending its turn" guard) → the action-economy-neutral invariant matches reality.
- **Seize/Escape are unit ACTIONS** (`TileActions.is_available`), not on-entry triggers → forced
  movement can't auto-trigger objectives.
- A1 `[STY]` provides the `EffectSpec{kind,payload,target_filter,gate}` axis; DSP-7 adds a `displace`
  kind. Rescue/carry/`grant_extra_turn` are NOT built (grep clean); Pair-Up IS.

## 3. The displacement primitive (was 25e) — `[DSP-1..11]`
- **DSP-1** one `DisplacementService.relocate(unit, dest)` occupancy-mutation primitive (both carry-drop
  and every `displace` call it).
- **DSP-2** carry attach reuses the Pair-Up `OFF_MAP_TILE` sentinel + a `CarryRegistry`; snapshotted.
- **DSP-3** **Rescue DISTINCT from Pair-Up, shares the attach substrate** (no combat bonus, inert
  carried unit, droppable; **exclusivity prior** — can't be paired AND carrying).
- **DSP-4** carry gating = an **F4 `CampaignRules` "carry" profile** (capacity stat default Con/Aid,
  weight = carried Con, author while-carrying penalties).
- **DSP-5** **capture-carry = same substrate + deltas** (enemy under `[STY-6]` `sleep`; freed if carrier
  defeated; delivered to roster/jail on map-clear via `[RCR]`). **Settles `[RCR-5]`.**
- **DSP-7** push family = a **`displace` EFFECT KIND** on the A1 `[STY]` axis, usable BOTH as standalone
  skill-actions AND layered into attack sources/styles (knockback weapon, a style that adds a shove);
  **smite = shove w/ higher potency**. Modes `push/pull/swap/to_side/blink`. **Extends A1's
  `EffectSpec.kind` with `displace`** (recorded in the STY register).
- **Leans:** DSP-6 drop/Give-Take through the F10 window · DSP-9 standalone carry/push cost an action, a
  `displace` *effect* rides the parent attack. **DSP-11 reserve (F1):** `carrier_id`/`carried_id`
  pointer + `CarryRegistry` snapshot; captured/jail state.

## 4. Cross-cutting non-standard-movement ruleset (was 25f) — `[DSP-12..16]`
One ruleset for **every** position change outside the regular move action (DSP `displace`/carry, STY
`teleport`/`fetch` staves, Dance moves, trap/event movers). Taxonomy: self-post-action (F10) ·
cooperative · forced · **reactive/out-of-turn** · environmental/system · negation.
- **DSP-12** off-turn/reactive displace **allowed** (enemy gambit shoves you; on-hit knockback on a
  counter; reaction-shove) but **never interrupts an in-progress exchange** (post-resolution
  consequence). Off-turn eligibility = author flag per source.
- **DSP-13** **composable resistance pipeline:** `immobile` tag + `ignores_immobile` bypass (binary) ·
  static stat contest (potency vs weight/Con) · to-hit **accuracy** like an attack (only stochastic
  stage → `RngService`). **v1 = tag stage only.**
- **DSP-14** **non-exclusive invalid-destination outcome set:** `fail` (v1 default) · `collision_damage`
  (scaled by terrain/occupant) · `chain_push` · **`force_onto_invalid`** (place on normally-illegal
  terrain — the sanctioned ring-out / environmental-kill lever).
- **DSP-15** **six invariants:** atomic & discrete · action-economy neutral · destination default-valid
  but author-overridable · **forced entry == normal entry** (objectives never auto-fire) ·
  phase-agnostic + non-interrupting · undo parity.
- **DSP-16** the `[STY-10]` effect-forecast preview shows a `displace`'s destination + resistance
  result + accuracy %; only the accuracy stage draws RNG.

## 5. Campaign-default + override, relationship gate, "Capture" pin (was 25g) — `[DSP-17]`
- **DSP-17** every displacement rule is a **`CampaignRules` default overridable per source** (resolution
  = source → campaign → framework). Authors set sane defaults once; sources opt into spicier behavior.
- **Harmful-consequence relationship gate** (added to `[DSP-14]`): the harmful outcomes
  (`collision_damage`, `force_onto_invalid`) apply **only where the actor↔target relationship permits
  aggression** (`[STY-17]`). Pure-positional moves are relationship-agnostic. Owner examples — a
  **knockback sword** can shove a `hostile` foe off a cliff (on hit + Str>Con); a **cooperative Shove**
  cannot ring-out a `neutral`/`allied` faction member (positional-only on non-hostiles).
- **Forward-pin — "Capture" victory type:** a new `ObjectiveCondition.type = capture` ("escape with
  prisoner" — escape while carrying a `[DSP-5]` captured prisoner) + an **F6 `captured:<id>` flag** for
  MET (A4) story events + bonus chapters. Owner = objective system (M16) + `[RCR]` + F6 + **A4**;
  flag reserved at F1.

## 6. Death-inventory disposition rule set pin (was 25h) — A5
The `[DSP-14]` `force_onto_invalid` ring-out kills a unit **out of combat, no clear killer, maybe
holding a Key Item** → pinned an **optional `CampaignRules` death-inventory profile** (modes
`to_convoy`/`lost`/`drop_on_tile`/`transfer_to_killer`; a **single `handle_death` disposition path** for
ALL death causes). Edge cases: out-of-combat death · no clear killer (fallback) · **death holding a Key
Item → `[CEX-14..16]` locks override to never-`lost`** · no convoy · Casual/Phoenix returns inventory ·
PvP · simultaneous AoE deaths · enemy/droppable-item death · death while carrying (`[DSP-5]`). **Owner =
A5** (F4 + permadeath path); composes `[IEQ]`/`[CNV]` + `[CEX-14..16]` + #12 + `[DSP-14]`. Pinned in the
atlas A5 bullet. (Today death funnels through `unit.handle_death()` but disposes of no inventory, and
non-combat deaths route through no shared path — a real gap.)
