# Session Note 2026-07-06f - B1-SUSPEND active-map restore foundation

## What was done

Built the first **`B1-SUSPEND` active-map suspend** slice on
`v0.3.0-features`.

- Added an I/O-free suspend capture path through `GameState.capture_suspend_save()`
  and `SaveData`.
- `SaveData` now normalizes `map_runtime.map_id`, `map_runtime.map_path`,
  `map_runtime.turn`, and suspend UI fields.
- `map_runtime.rng.map_seed` and `history_hash` now persist as decimal strings
  so Godot JSON cannot round 64-bit RNG state.
- `GameState.configure_suspend_resume()` stages a suspend payload for the next
  map load and rebuilds the blue roster from runtime unit data.
- `GameMap` can resume from `map_runtime.units` instead of authored placements,
  so live enemy HP/position/state are restored.
- `TurnManager` captures/restores turn number, phase, turn order, active faction
  cursor, activation mode, per-unit activation states, and objective records.
- `MapCursor` captures/restores free cursor tile, MRD watch set, and danger mode.
- PairUpRegistry and `RngService` restore from the suspend payload.

Tests updated:

- `test_save_data.gd` now locks the normalized suspend watch-set and stringified
  RNG payload shape.
- Added `test_suspend_map_runtime.gd` for live enemy restore, alternating
  scheduler restore, mixed unit states, Pair Up, RNG, cursor tile, and MRD
  watch state.

Docs/tracking updated:

- `GDD_01` records B1-SUSPEND Slice 1 as Implemented and keeps disk
  SaveManager/Continue lifecycle as Target design.
- `GDD_07` records MRD watch-set/danger-mode suspend restore.
- `GDD_10`, Feature Index, Project Control Plane, and the F1 manifest now point
  at the concrete `map_runtime` fields and remaining B1-SUSPEND work.
