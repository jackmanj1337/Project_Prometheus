## 1. The question + finding
User: "We should probably have general hooks long term to trigger events on any specific unit's
death. Do we have that already made or planned anywhere?"

**Finding — partial mechanism, no authoring layer, not planned as a general system:**
- `EventBus.unit_died(unit)` exists (broadcast, post-`handle_death`) — but every reaction is
  **hardcoded in GDScript** (`TurnManager._on_unit_died` runs victory checks).
- `ObjectiveCondition` is data-authored and watches `unit_ids` (`defeat_boss`/`protect`) — but
  feeds **only win/lose evaluation**, not arbitrary actions.
- **No flag store** (GameState has only debug flags); **no mid-map spawn seam** (GameMap spawns at
  init only). No general "on event → run actions" framework anywhere.

**Key insight (drove the whole design):** the unit-death hook is the *trigger half* and DTR-5's
`on_break` is the *action half* of the SAME system. User chose (AskUserQuestion) to **draft the
full Map Events / Triggers framework now** rather than a narrow per-unit hook.

## 3. Resolved shape
`MapData.map_events` = list of `{ id, trigger:{type,…}, condition:{flag,…}?, actions:[…], once }`.
A `MapEventManager` connects the `EventBus` substrate signals once, matches fired signals to
authored events, checks the optional flag guard, runs the action list at a **deferred safe point**
(reusing TurnManager's existing pattern), and latches `once` events into `map_events_fired`.

**This unifies three previously-scattered hooks:** DTR's `on_break` (→ `object_broken` action
list), [CST-11]'s story-flip (→ `flag` action + flag store), and DTR's reinforcement-spawn
sub-feature (→ `spawn` action + the extracted `GameMap.spawn_unit` seam).
