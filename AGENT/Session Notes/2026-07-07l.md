### 2. Selector adoption — HUD terrain pager (`2b7e3fc`)

### 3. Prompt swapping + gamepad-brand research (`5a7f2fe`)

**Research finding that shaped the code:** Godot 4.5+ uses SDL, which normalizes
button **position** — `JOY_BUTTON_A` is always the physical **bottom** face button on
every brand — so our bindings are brand-correct with **zero per-brand code**. The
brand problem is purely **labels/glyphs**: Nintendo physically swaps the A/B and X/Y
positions vs Xbox, and PlayStation prints ✕ ○ □ △. Godot has **no native
controller-type API**; the community-standard workaround is heuristic string-matching
on `Input.get_joy_name()`. A wrong brand guess is therefore cosmetic, never a
mis-input. (Sources: Godot controllers doc; godot-proposals#8519.)

Implemented in `InputDisplay`: `detect_brand` / `active_pad_brand`,
`joypad_button_label` (brand face-label swap, non-face buttons defer; PS shoulders →
L1/R1), `action_prompt` (key in keyboard/touch, brand-correct pad label in gamepad,
key fallback), `live_action_prompt`, and `more_info_hint(_for)` (mode-appropriate hint
sentence). Wired the four live prompt sites to re-render on `input_mode_changed`:
`LevelUpScreen` "Press _X_ to continue", and the More Info hints on `AttackPreview`,
`UnitDetailsScreen`, and the `HUD` compact terrain panel. `ModalScreen` gained a
`_refresh_input_prompts(mode)` virtual (called for every mode) so any modal hint
re-renders on a switch. New `test_input_display.gd` (7/0).
