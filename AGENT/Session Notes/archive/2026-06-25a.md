## What the STY context revealed (why the old resolution needed a revisit)
- **Styles never fire on counters** — they are per-attack + `player_activated` (`[STY-2]`/`[STY-8]`), so a
  counter is always `equipped_source` + null style. The fallback only needs a usable **source**, not a
  style → the old "don't auto-swap away from an intended art" worry mostly dissolves.
- The flat **inventory-slot → granted** order was a provisional placeholder; replaced by a player-driven
  order + equip history.

## Refined `[CEX-22]` (designer call)
- **Persistent auto-equip stays** (FE-style — the swap sticks for the counter AND the next own turn).
- **Fallback order = a player-orderable source priority**, falling *through* sources that are listed but
  currently unavailable (greyed, not removed). **Default ordering = most-recently-equipped still-usable
  source (equip history / MRU)**; explicit player ordering overrides MRU; universal infinite **fists**
  floor last; nothing usable + no floor → counter with nothing.
- **Not range-aware by default** — the picked source may be out of range and **deny a counter** (an
  intentional build consideration).
- **Opt-in skill = range-aware fallback:** a skill makes the resolver pick the highest-priority (most-
  recent) source that *would permit a counter* (usable AND in range). Build content (GDD_05), a passive
  flag the fallback resolver reads. Supersedes the old `[CEX-23]`-deferred range note for the counter case.
- **Save (F1):** reserve per-unit **equip history (MRU)** + **player source-ordering** (new state beyond
  `equipped_source`).
