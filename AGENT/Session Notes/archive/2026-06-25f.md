# Session Note — 2026-06-25f  (Non-standard movement & displacement — cross-cutting ruleset `[DSP-12..16]`)

**Topic:** Deepened the A2 displacement work into the **general category of position changes that happen
outside the regular move action** (incl. out-of-turn / reactive movement) — worked the player-facing
edge cases and the campaign-author levers. Branch `docs-reorg-2026-06-23`.

**Outcome:** Extended register **`[DSP]` to DSP-1..16** (added the cross-cutting ruleset DSP-12..16;
subsumed the old DSP-8/10 leans) + a new companion design doc
`design/nonstandard_movement_and_displacement_2026-06-25.md`.

---

## 1. Frame — one ruleset, many features
"Move a unit without a normal move action" spans rescue/carry, shove/swap/pivot/smite, Warp/Rescue
staves, Dance-granted moves, trap/event repositioning, terrain collapse. **All resolve through one
`DisplacementService` (`[DSP-1]`) and obey one shared ruleset.** Taxonomy (6 categories): self
post-action (F10) · cooperative · forced · **reactive/out-of-turn** · environmental/system · negation.

## 2. Two engine facts that sharpened the rulings
- **Seize/Escape are unit ACTIONS** (`TileActions.is_available`), not on-entry triggers → a unit
  *placed* on an objective tile by force can't auto-trigger it (no shove-to-win exploits, by existing
  design).
- **The engine already models "teleported-but-still-READY"** (`record_move_start`/`undo_move`, the
  *"moved without spending its turn"* guard in `EnemyAI`) → the action-economy-neutral invariant matches
  engine reality.

## 3. Owner decisions (forks 2026-06-25f)
- **DSP-12 off-turn timing:** displacement **may fire on any phase** (enemy gambit shoves you; on-hit
  knockback on a counter; reaction-shove) but **never interrupts an in-progress exchange** — resolves as
  a post-resolution consequence. Off-turn eligibility = an author flag per source.
- **DSP-13 resistance pipeline (owner wants ALL three, composable):** `immobile` tag + `ignores_immobile`
  bypass (binary) · a **static stat contest** (potency vs weight/Con) · an optional **to-hit accuracy**
  like an attack. Any subset; deterministic except the accuracy roll (rides `RngService`). **v1 = tag
  stage only**; stat-contest + accuracy reserved.
- **DSP-14 invalid-destination (owner wants a NON-EXCLUSIVE set):** author selects any of `fail`
  (v1 default) · `collision_damage` (scaled by terrain/occupant) · `chain_push` · **`force_onto_invalid`**
  (place on normally-illegal terrain — the sanctioned ring-out / environmental-kill lever). **v1 = `fail`
  only**; the rest reserved.
- **DSP-15 invariants (6):** atomic & discrete · action-economy neutral · destination default-valid but
  author-overridable (via DSP-14 `force_onto_invalid`) · **forced entry == normal entry** for tile
  consequences (objectives never auto-fire) · phase-agnostic + non-interrupting · undo parity.
- **DSP-16 preview/RNG:** the `[STY-10]` effect-forecast shows a `displace`'s destination + (when set)
  resistance result + accuracy %; only the accuracy stage consumes `RngService`.

## 4. Author-lever catalog produced
carry profile (F4) · `displace` payload (mode push/pull/swap/to_side/blink, distance/potency, direction)
· resistance stages (tag/stat/accuracy) · destination outcomes (fail/damage/chain/force-illegal) ·
off-turn eligibility · `target_filter` (ally vs enemy) · F10 second-move eligibility.

## 5. Notable design shift
Owner made invariant "destination must be valid" **author-overridable** — `force_onto_invalid` is the
one sanctioned way to create an illegal placement, enabling environmental kills (shove into deep water/
chasm) that then interact with on-entry hazard terrain. Reserved, not v1.
