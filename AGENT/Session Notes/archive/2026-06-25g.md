# Session Note — 2026-06-25g  (Displacement: campaign-default+override rules, relationship gate, "Capture" victory pin)

**Topic:** Refined the A2 displacement ruleset per owner: make every rule a **campaign default with
per-source overrides**, add the **harmful-consequence relationship gate**, and pin a new **"Capture"
victory type** + capture story flag. Branch `docs-reorg-2026-06-23`.

**Outcome:** `[DSP]` extended to **DSP-1..17**; companion design doc updated.

---

## 1. DSP-17 — campaign defaults + per-source overrides (owner call)
The whole displacement ruleset (resistance stages `[DSP-13]`, invalid-destination outcomes `[DSP-14]`,
off-turn eligibility `[DSP-12]`, accuracy) is a **`CampaignRules` displacement default** that **any
source overrides per-rule**. Resolution = per-source `EffectSpec` override → campaign default → framework
default (`[DSP-15]`). Authors set sane defaults once; individual sources opt into spicier behavior.

## 2. Harmful-consequence relationship gate (the cliff example)
Added to `[DSP-14]`: the **harmful** outcomes (`collision_damage`, `force_onto_invalid`) apply **only
where the actor↔affected-unit relationship permits aggression** (`[STY-17]` matrix: target `hostile`, or
friendly-fire explicitly enabled). **Pure-positional** displacement onto a valid tile is
relationship-agnostic. Worked owner examples:
- **Knockback sword** (`accuracy: weapon_hit`, `stat_contest: Str_vs_Con`, `on_invalid:
  force_onto_invalid`, target enemy) → **can** shove a `hostile` foe off a cliff when it hits and
  Str > Con.
- **Cooperative Shove** (`accuracy: auto`, `resistance: none`, target ally/any) → auto-succeeds
  positionally but **cannot** push a `neutral`/`allied` faction member off the same cliff (harmful
  outcome gated by relationship); it may only relocate them to a valid tile.

## 3. Forward-pinned — "Capture" victory type + `captured:<id>` flag
Compose a new **`ObjectiveCondition.type = capture`** ("escape with prisoner"): like `escape` but the
escaping unit must be **carrying a captured prisoner** (`[DSP-5]`); on success prisoners extract to the
roster/jail. Each extraction sets an **F6 flag `captured:<unit_id>`** consumed by **MET (A4)** story
events + **bonus-chapter** unlocks. **Ownership:** `[DSP-5]` + objective system (M16,
`ObjectiveCondition`/`TurnManager.check_victory_conditions`) + `[RCR]` + F6 + A4. **Firm with those
builds, not now**; reserve the flag at the F1 lock (added to `[DSP-11]`).

## 4. Grounding
`ObjectiveCondition` is a typed resource with a `type` string + catalogue (rout/defeat_boss/seize/
escape/survive/protect/turn_limit) on `MapData.victory_conditions`, evaluated by
`TurnManager.check_victory_conditions` — so `capture` is a natural new `type`. Seize/Escape being
**actions** (not on-entry triggers) is what makes "escape with prisoner" require the carrier's own
Escape-equivalent action, consistent with `[DSP-15]` inv. 4.
