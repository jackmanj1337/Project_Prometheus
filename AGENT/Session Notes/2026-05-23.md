## Decisions recorded
- Weapon identity and WEXP progression should be separate runtime concepts.
- Canonical WEXP tracks should be:
  - `sword`
  - `lance`
  - `axe`
  - `bow`
  - `elemental_magic`
  - `light`
  - `dark`
  - `staff`
  - `beaststone`
  - `dragonstone`
- Fire, thunder, and wind variants should share the `elemental_magic` WEXP
  track.
- Light magic should remain its own WEXP track.
- Hybrid weapons should keep combat-behavior metadata separate from the WEXP
  track they train.
- Legacy runtime/content data should migrate as:
  - `fire` -> `elemental_magic`
  - `thunder` -> `elemental_magic`
  - `wind` -> `elemental_magic`
  - `light` -> `light`
  - `dark` -> `dark`
  - `staff` -> `staff`
- `ClassData` should move toward explicit numeric class-side weapon baseline and
  cap dictionaries keyed by WEXP track.
- `ClassData` should store optional explicit combat-family allowances, with
  derivation from WEXP-cap data as the default when no override is authored.
- `WeaponData` should split combat identity from progression identity using
  separate family/track metadata.
- `UnitData` should store one authoritative numeric WEXP dictionary keyed by
  WEXP track, with rank labels derived when needed.
- Repo migration should be a one-time authored-data conversion only; no legacy
  load-time compatibility layer is needed.
- Staff behavior should be split so metadata stays in `WeaponData` while effect
  resolution moves into a dedicated staff resolver.
- Hybrid and special weapon behavior should use explicit family/track/damage
  metadata, with descriptive subtype data and separate effect tags/override
  fields for special behavior.
- The next implementation pass should include schema changes, repo migration,
  validators, and unit tests together.
- Combat refactor should be tracked as the immediate follow-up pass.
- Pair Up-related skills should get explicit alternate effects or stay disabled
  until real Pair Up mechanics exist.
- Pair Up scaffolding should be included in the first combat refactor, but the
  actual Pair Up mechanics should be campaign-configurable so campaigns can
  disable them in settings.
- Markdown-corpus import tooling should be tracked as a later to-do item after
  schema and combat foundations are stable.
