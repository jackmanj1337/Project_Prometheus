### The ledger object (commit `4654f64`)
- **New `scripts/save/MapLedger.gd`** — a preloaded, no-`class_name` object
  (mirrors `DeploymentPlan.gd`). A single reason-tagged entry list;
  `prune(keep_activations, keep_rounds)` retains `(last A activations) UNION (last R
  round-starts)` plus the always-kept round-0 boundary. Tiers are DATA (a `reason`
  tag + two budgets), not a mode `match` — open-registry principle. `-1` = infinite
  tier; `0` = none beyond round-0. `peek()` hands back a deep copy.
- `GameState` now holds a `_map_ledger` instance instead of the raw `_map_history`
  array; `push_history` gained a `reason` arg (default round-start), `peek_history`/
  `history_size` delegate, and a new `prune_history()` reads the campaign budgets.

### Party economy folded PER ENTRY (DECIDED 2026-07-15)
- `_capture_map_runtime_entry()` now adds a `party` block (gold + items + a
  roster snapshot in roster order) to every entry, so a Retry — and a future
  mid-map rewind — rolls party rewards back with the board. Sibling to
  `map_runtime`/`suspend`, so `capture_suspend_save` (which merges only those two
  sub-blocks) stays byte-identical.

### Retry-on-ledger + the scrap
- **`restore_history(index)`** reapplies roster-in-place + gold + items + PairUp +
  RNG from an entry, validating the whole entry first (`_validate_restore_entry`) so
  a bad entry leaves the running game untouched. `index 0` = round-0 boundary.
- **Retry is now `GameState.restore_history(0)`**, called from `GameOverScreen`.
- **SCRAPPED:** `_map_start_snapshot`, `_snapshot_party_gold/items/pair_up_registry/
  rng` fields, `restore_map_snapshot`, `validate_restore_snapshot_state`.
  `take_map_snapshot()` is now just the round-0 ledger seed. `PairUpRegistry`'s
  header comment updated (it no longer references `_map_start_snapshot`).
