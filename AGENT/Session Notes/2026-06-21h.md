## 4. Headline design (resolved)
A breakable = a `map_objects` entry that at map-load **spawns a real `Unit`** with an "object"
`UnitData` (weaponless ⇒ no counter, immobile, neutral faction, forced-hit ⇒ no dodge), tagged
`is_destructible_object`. Attacking it runs the **full unit damage pipeline** ([DTR-2]) — any
weapon ([DTR-4]) — and the AttackPreview forecast works with ~zero combat-code change (the pipeline
is already Unit-method duck-typed). At 0 HP the object Unit is freed, the tile flips to
`reveals_terrain`, and the `on_break` event list runs.

**Main build risk surface:** every "for each unit" iteration (turn order, rout liveness, EXP,
pair-up/support/rescue, save) must add the `is_destructible_object` skip guard. Enumerate them all
during the build.

**Forward sub-features [DTR-5] surfaced** (not v1-blocking; the breakable just fires typed events):
- `reveal_tiles` (bridge) = the passability overlay run in reverse over a span — lands here, cheap.
- `spawn` (reinforcements) = needs a **mid-map reinforcement-spawn seam** (today `enemy_placements`
  is initial-only) — its own small forward design.
- `flag` = reuse the [CST-11] story-flip seam; `loot` = reuse DCH's loot path.
