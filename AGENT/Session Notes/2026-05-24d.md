## Locked-in decisions this session
Captured into the plan doc before coding began:

- `more_info` is a new InputMap action bound to `F`. Adding the action (not
  hardcoding KEY_F at each consumer) keeps the future rebind-keys feature
  cheap.
- Detail view is a **side panel** attached to each host UI, not a separate
  modal.
- **Every** entry on each host UI is selectable, not just stats — items,
  skills, weapon ranks, combat-preview fields, terrain rows, tile actions.
  The side panel always shows a short description; stats additionally show
  modifier rows.
- Tile actions are surfaced via a shared helper (planned
  `scripts/shared/TileActions.gd`) so HUD and `ActionMenu` agree by
  construction. Not yet extracted — that is part of step 7.
- Descriptions live in `scripts/shared/MoreInfoContent.gd` with a fallback
  string for missing entries, so the side panel never crashes on a key that
  has not been authored yet.

## What was done
Build-order steps 1–5 of the plan are complete:

1. **Shared `StatBreakdown` helper** — `scripts/shared/StatBreakdown.gd`.
   Static API: `build(unit, stat_name)`, `label_for_stat`,
   `label_for_source`, `format_signed`, `format_duration`. Returns the
   locked dict shape (base / effective / total_delta / grouped mods with
   source_label + duration_type + remaining). Math authority stays in
   `Unit.get_effective_stat()`; the helper only formats the result. Same-
   source duplicate mods are grouped (longest remaining duration wins).
2. **`MoreInfoContent` description source** — `scripts/shared/MoreInfoContent.gd`.
   Dict-of-dicts keyed by `(category, key)` with `describe()` falling back
   to a placeholder so missing copy never crashes the panel. Covers the
   Phase 1 surfaces (stat / inventory / skill / wexp / combat_field /
   terrain / tile_action).
3. **`more_info` InputMap action** — added in `project.godot` bound to KEY_F.
   Verified at runtime via a one-shot script.
4. **`UnitDetailsScreen` migration** — scene restructured from `Panel/VBox/...`
   to `Panel/HBox/{VBox, InfoVBox}/...` so the side panel sits alongside the
   sheet without resizing the main column. Every stat / inventory item /
   skill / weapon-rank row is now a clickable `[url=...]` BBCode link
   (`Inventory` and `Skills` were upgraded from `Label` to `RichTextLabel`
   to support meta links). Side panel renders description (always) +
   modifier block (stats only). The `more_info` action cycles through
   entries in declaration order and wraps; `_close()` clears local state.
5. **Combat preview content** — `CombatResolver.preview_combat()` now also
   returns `attacker_triangle` / `defender_triangle`,
   `attacker_effective` / `defender_effective`, and the corresponding
   effectiveness multipliers. `AttackPreview` shows coloured marker labels
   (green ▲ Advantage, red ▼ Disadvantage, amber `Effective ×3`/`×4` for
   Giantkiller). Neutral rows render empty so the panel height stays stable
   across targets.
