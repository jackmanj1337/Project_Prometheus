### M14/M15/M16 open questions — Decisions 1–6
1. Next session = **playtest first**, then pick the build direction.
2. M14 empty-faction HUD: hide never-present factions, grey out wiped ones.
3. M16 condition list: 7 types confirmed as-is.
4. M16 seize: a dedicated **Seize action** (ActionMenu entry), not passive occupation.
5. M16 escape: a **zone** of tiles, units removed-on-entry.
6. M15 per-phase keybindings: later polish; ship hotseat with shared keys.

### Three new design decisions — Decisions 7–9
7. **Hybrid victory checking** for the N-faction cycle — phase-boundary sweep +
   event-driven (death/Seize/escape) + round counter. Decoupled from phase count.
8. **Per-group victory/defeat** — decoupled from blue-centric. Each aggression
   group has victory + defeat conditions; ranked-standings results screen.
   Supersedes feasibility §6. Fixes a real gap: blue-centric left red/yellow with
   no win state, which breaks online PvP.
9. **Per-map `activation_mode`** (`WHOLE_PHASE | ALTERNATING`, default whole-phase).
   I-Go-You-Go is a special case of an activation scheduler — one engine, pluggable
   policy. M14 stage 3 builds the scheduler.

### Dependency audit — Decision 10
Audited M8–M16 against Decisions 7–9; found **five dependencies the roadmap did not
account for** (M16 now depends on M14; M10 needs M14 stages 1–5; M8 condition
ticking is activation-coupled; M14 stage 4 AI scoring reads M16 data; doc staleness
from Decision 9). Revised dependency-clean order:
**M14 stages 1–3 → M16 → M14 stages 4–5 (+content) → M8 → M9 → M10 → M11 → M12 →
M13 → Phase 3.**
