## Design takeaways
- Activity logic should remain template-specific and validated; do not push card/game/puzzle mechanics
  into DLG commands.
- Dialogue should launch activities and resume with result-aware branches.
- Shared presentation is useful: stage elements, layers, backgrounds, and effects can serve both dialogue
  scenes and activity intros/outros.
- First build path remains: ActivityRegistry + launch_activity + ActivityRunner + result bridge, then
  template prototypes.
