# Session Notes — 2026-06-15b (Display & Accessibility controls: zoom, resolution, UI scale)

Plan-first implementation of the **Near-Term — Display & Accessibility Controls**
roadmap block (the one upcoming item that had no implementation-ready plan). Scoped
to items 1–3; item 4 deferred. Plan approved in plan mode, then built in 3 commits.

## Decisions taken (with the user, before building)
- **Item 4 (per-panel HUD scale/reposition) deferred** to a separate spec.
- **UI scaling uses `Window.content_scale_factor`, not a font-only `Theme` scalar** —
  it scales the whole GUI uniformly (fixed-size nodes included → nothing clips) and is
  resolution-independent across desktop / Steam Deck / web. Best multi-platform lever.
- **Zoom + UI scale are stepped sliders** (HSlider whose value is an index into a
  level array); resolution/window-mode stay OptionButton dropdowns.
- **Zoom range 0.25×–4×** (8 power-of-two-friendly stops) per the user's "faked
  continuous slider" ask. Aspect policy stays `keep` (already ratified).

## What was done

### Commit `a0e81da` — CameraController zoom-aware (item 1a)
Root-caused the retrofit risk: every tile/pan method sized the view from raw viewport
**pixels**, correct only at zoom 1. Added `_visible_world_size()` (`viewport_px /
zoom`) and routed `keep_cursor_in_view`, `clamp_tile_to_view`, `nudge_by_tiles`,
`pan_by_pixels` through it. `pan_by_pixels` now treats its arg as **screen** px and
converts by `1/zoom`. Behaviour-neutral at zoom 1 (full suite green). New
`test_camera_controller.gd` — 10 asserts (zoom-1 parity + 0.5×/2× framing/pan),
viewport-size-agnostic, uses the `root` + `await process_frame` pattern.

### Commit `c6316d6` — Zoom API + input + persistence + AttackPreview (items 1b–1d)
- `CameraController`: `ZOOM_LEVELS` = `[0.25..4.0]` (8), `set_zoom_index` /
  `step_zoom` / `reset_zoom` (re-frame on a focus tile) + `set_zoom_index_silent`
  (level-only, used at map load) + centering when a low zoom makes the map smaller
  than the viewport.
- Input actions `zoom_in` (`=`/wheel-up), `zoom_out` (`-`/wheel-down), `zoom_reset`
  (`0`) in `project.godot`; `MapCursor._unhandled_input` maps them onto `step_zoom` /
  `reset_zoom` and persists `SettingsManager.map_zoom_index`; `GameMap` applies the
  saved level on load.
- `AttackPreview._reposition_for` now offsets by the on-screen tile size
  (`TILE_SIZE × zoom`) instead of the raw world constant.
- Settings: stepped **Map Zoom** slider sized from `ZOOM_LEVELS`.
- Camera test grew to 18 asserts (zoom API + clamping + too-small-map centering).

### Commit `74fc0ea` — Display settings: window mode, resolution, UI scale (items 2–3)
- `SettingsManager` `[display]` section: `window_mode`
  (Windowed/Borderless/Fullscreen via `DisplayServer`), windowed `resolution`
  (1280×720 / 1600×900 / 1920×1080; `_parse_resolution`), and `ui_scale_index`
  (`UI_SCALE_LEVELS` 0.75×–2.0× via `Window.content_scale_factor`). Full
  load/save/reset + clamps; `_apply_display` / `_apply_ui_scale` run at `_ready`.
- `SettingsScreen`: two OptionButton rows (window mode, resolution) via the existing
  schema + a new optional per-row **`apply`** hook so changes take effect live; a
  stepped **UI Scale** slider. New scene nodes under a "Display" section.
- Tests: display defaults/reset + `_parse_resolution` in `test_settings_manager` (11).
