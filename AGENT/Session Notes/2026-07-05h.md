### Q1 — `[V027-02]` action menu far-edge anchor (`5446882`)

`MapCursor._place_menu_near` now offsets by `tile_px + 4` (the AttackPreview
model) instead of the V025-03 whole-offset cap that left the menu inside the
magnified tile at zoom > 1. The V025-03 test was rewritten to assert far-edge
placement at 1× and 4× (menu fully clear of the zoomed tile, gap constant),
side stickiness preserved.

### Q2 — `[V027-03a]` forecast first-open dead space (`dbf3568`)

`show_preview` runs a deferred second `_size_panel_to_content` +
`_reposition_for` pass one frame after every show, holding the panel
transparent for that frame (the `apply_to_deferred` mitigation). A generation
counter (`_deferred_show_id`) keeps overlapping shows from clobbering each
other's alpha. Contract test in `test_attack_preview_position.gd`.

### Q3 — `[V027-03b]` left-wall repro → root cause found (`9e3d566`)

**Repro-first paid off.** The new headless wall sweep (both walls × 2-4× zoom
against a real current camera) shows the placement geometry is SOUND — but the
same-frame case fails: `keep_cursor_in_view` was the ONE camera write without
`_flush_scroll()`, so a placement in the same frame as a cursor-driven scroll
read a stale canvas transform and stranded the panel (wall-agnostic; the
tester's left-wall symptom). Fixed with the flush + the decided belt-and-braces:
`_reposition_context_menu_anchor` re-runs once one frame later (coalesced via
`_reanchor_queued`) — the automated "zoom past max" heal. Both repro cases kept
as regression tests.

### Q4 — `[V027-04a]` resize hook (`95d33d1`)

`SettingsManager._ready` connects viewport `size_changed` → deferred, coalesced
`_apply_menu_scale()`. Gotcha discovered: `Window.set_content_scale_factor`
emits `size_changed` even for a same-value write, which re-queued the hook
forever — the reset now only writes when it changes something. Test asserts
one re-apply per settled frame across many same-frame emits (and had to use
the live autoload: a second SettingsManager double-connects the hook).

### Q5 — `[V027-04b]` full write-back + Custom W×H + handbook fix (`2f75659`)

Owner decision B: while windowed, an OS resize (drag/maximize) writes the
actual client size into the saved `resolution` via
`SettingsManager.apply_resize_write_back` (persists immediately, emits
`resolution_written_back`). Programmatic resizes are excluded by comparing
against `_requested_window_size` (what `_apply_display` asked for), so a
clamped request never self-overwrites. The Resolution dropdown renders a
non-preset value as a trailing display-only `Custom (WxH)` item
(`_sync_resolution_dropdown`); confirm-dialog keep/revert re-sync through the
same helper. NO drag-triggered recentre — the display guide's
recentre-on-each-resize sentence corrected + a new write-back section (DoD#1).
Write-back core / persistence / dropdown tests added.

### Q6 — `[V027-05c]` Resolution gray-out (`d31aabc`)

Outside Windowed the Resolution dropdown is disabled (saved request preserved
underneath, re-enables intact) and the applied readout pins to
`native WxH`. Guide updated; round-trip test added.
