# Session Notes — 2026-05-23c

## Focus
Implement the next Awakening compatibility schema pass after the weapon/WEXP
split: replace `effective_level` with `internal_level`, add class-side
availability/vulnerability metadata, and surface stored WEXP progress in the
unit details screen.

## Decisions recorded
- `effective_level` is fully replaced by `internal_level`.
- Special-class handling should be driven by explicit per-class data, not a
  generic boolean shortcut.
- Canonical vulnerability groups for now are:
  - `mounted`
  - `flying`
  - `armoured`
  - `dragon`
  - `beast`
  - `monster`
- `class_availability` controls in-game menu visibility only and remains a soft
  filter that map/campaign creators can bypass by direct assignment.
- Stored WEXP must be preserved even when a class cannot currently use that
  weapon track.
- The character sheet should show every weapon track with any stored WEXP,
  including:
  - current derived rank
  - current stored WEXP
  - the next threshold needed for rank-up
  - a dimmed presentation when the current class cannot use that track
- Pair Up refactor is the next planned implementation pass after this schema
  pass.
