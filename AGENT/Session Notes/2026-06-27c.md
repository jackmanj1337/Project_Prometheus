## 1. What was done

**Researched the spatial layer (the blast-radius finding).** Map geometry is unusually well-centralized,
which is the whole reason hex is feasible:
- **Neighbours are single-sourced:** `GridManager.DIRS` (`GridManager.gd:255`) is the only neighbour list,
  and **every** reachability/path/AI-distance calc flows through one function, `dijkstra_costs()` — the
  keystone seam.
- **Move cost is already topology-agnostic** (keyed per terrain string, not geometry — no change needed).
- **Distance is the messy part — NOT centralized:** Manhattan (`absi(dx)+absi(dy)`) is inlined in ~8 sites
  (GridManager `_tiles_in_range` + 3 range checks, `CombatResolver:383`, `EnemyAI` ×3, `MapCursor._manhattan`,
  `SkillHandler._manhattan`). Must consolidate behind one `tile_distance()` first.
- **Pixel conversion assumes square** (`world_to_tile`/`tile_to_world`, `Unit.gd:63` = `tile * TILE_SIZE`).
- **Rendering is mostly free** — Godot 4 `TileMapLayer` supports `tile_shape = hexagon` natively.
- **Storage survives** — `MapData.grid: Array[String]` + `Vector2i` placements are offset coords; only the
  *adjacency interpretation* of the same ints changes.

**New register `[HEX-1..9]`** — `registers/grid_topology_hex_open_questions_2026-06-27.md`, **RESOLVED**
(all 9 settled; **build PARKED** for the project re-evaluation/triage phase). Recommended path = two phases:
**Phase 1** centralize geometry (`tile_distance()` + neighbour accessor — low-risk, standalone value);
**Phase 2** add a `HexTopology` behind the seam (axial/cube internally, offset at the edges).

**The 9 decisions (owner-walked, one at a time):**
- **HEX-1 — scope:** topology is **authored content, campaign-default + per-map override** (mirrors the
  resolved `[DSP-17]` pattern). **NOT** a live runtime flip of the same map data (square terrain doesn't map
  1:1 onto hex → would mean dual-authoring every map). A player "Hex Mode" is only ever *selecting a
  separately-authored hex campaign variant*.
- **HEX-2 — coords:** **offset `Vector2i` stays the stored tile identity** (Unit/MapData/dict keys/saves
  untouched; square = offset-with-no-shift → zero change); axial/cube lives **only inside the `GridManager`
  seam**. Rejected axial-as-native-identity and pure-offset parity-branch math.
- **HEX-3 — build scope:** **park BOTH phases** into the project re-evaluation/triage backlog (not
  special-cased ahead of the other recently-walked systems); **only HEX-9 acts now**. Phase 1 is the
  designated first build step IF/WHEN triage greenlights. (Revised the initial "Phase 1 now" rec — a
  speculative refactor amid heavy in-flight work adds churn for no near-term payoff, equally cheap later.)
- **HEX-4 — range:** stays `tile_distance ≤ N`; **hex is its own balance pass**. The 6-vs-4 melee coverage
  shift (hex disk `3R(R+1)+1` vs Manhattan `2R(R+1)+1`) is inherent, not a bug; no per-topology range tables.
- **HEX-5 — toggle home (by HEX-1):** `CampaignRules.grid_topology = "square"` default +
  `MapData.grid_topology = ""` override (`""` = inherit). Save state, not a `SettingsManager` setting.
- **HEX-6 — input:** **pointer-primary now** (mouse/touch already topology-agnostic → hex not input-blocked);
  native 6-key cursoring deferred to `[ICD]` as a Phase-2 detail.
- **HEX-7 — art:** **separate hex tileset; art + pointy/flat-top orientation deferred** to the build's art
  pass (orientation couples to art + the HEX-2 offset layout). Noted lean: pointy-top, not pinned.
- **HEX-8 — maps (by HEX-1):** authored fresh, **no auto-convert**; a converter is a later nicety, never a
  prerequisite.
- **HEX-9 — forward-ward (the only action taken now):** keep new direction-based work from hard-coding
  4-way. **Applied:** (1) a seam comment at `GridManager.DIRS` marking it the single geometry seam +
  instructing direction features to read neighbours through it; (2) a `[HEX-9]` forward-note in the `[DSP]`
  register (shove/swap/pivot/carry directions must source from the seam). Catalog check: `[DSP]` is the only
  live direction-based design, so no broader sweep.
