Walked the review with the actual code open (not just the rollup) and locked in

- **H1 (release blocker) — approach confirmed.** Seed RNG on the fresh
  (`not is_resuming`) branch of `GameMap._ready()` via
  `get_node_or_null("/root/RngService")` (null-guarded for headless), **before**

  `start_map`) and asserts `map_seed != 0` + `history_hash == 0` at the start of a
  second same-session map.

- **M1 — fix shape = Option A (signal).** The wrinkle: `_on_enum_setting_changed`
  (`SettingsScreen.gd:365-370`) does `sm.set` → `sm.call("save")` → optional
  `sm.call(apply_hook)`, and the `apply` hook names a method **on
  SettingsManager**, so it cannot reach InputModeManager directly. Decision:
  SettingsManager emits a `settings_changed` signal after `save()`;
  `InputModeManager._ready()` connects it to `_refresh_active_input_mode` (already
  private + idempotent). Covers `reset_section_to_defaults("controls")` for free.
  SettingsManager already uses this pattern (`resolution_written_back`).
  Rejected Option B (public `refresh_from_settings()` + a SettingsManager proxy) —
  more surface, misses the reset path.

- **M2 — scope = derive editable set from the live InputMap** (minus `ui_*` +
  debug actions) with a display-label override map, replacing the hand-maintained
  closed `_KEYBIND_LABELS` (`SettingsScreen.gd:630`). Fixes both the 5 missing
  rows AND the conflict-scan blind spot durably, and matches the `AGENTS.md`
  open-registry principle. (Chosen over just adding the 5 rows.) Care needed on
  display-label/ordering handling.

- **M3 — defer.** DataManager closed `_VALID_*` vocabularies are pre-existing
  registry debt tracked under `[TCV-4]`/`[AIP]`/`[STM]`; fix belongs to those
  register resolutions, **not** a v0.3.0 blocker or a point patch.
