## Decisions settled (register §3c/§3d/§3e — authoritative)
- **v1 slice grew from the earlier "+N stat bump" lean.** v1 ships **point
  allocation** (author total-point max + per-stat max + per-stat step size), **live
  durability + repair**, **permanent**, **resource-gated only**, **gold-only** via an
  author `REQ-16` formula (default flat), a **standalone two-mode PHB forge panel**, and
  **player-renamable, non-mergeable** instances.
- **`forged_mods` = operation overlay** (ops + params; registry derives deltas). New
  saved `custom_name` field on `InventoryEntry` for rename.
- **Load-bearing seam:** one **effective-weapon-stat resolver** (`base + forged deltas`);
  no combat/range/UI path reads raw `weapon.mt` after migration.
- **Repair** is a distinct UI action (reuses the transform "item-op" UI); cost = author
  formula over base item, current uses, max uses, item value, current mods.
- **Per-forge-instance capability envelope:** a forge may clamp caps **below** the item's
  own limits (total point + per-stat, fixed or predicate). Effective cap = **min(item,
  forge-instance)**.
- **Target-item predicate context (the one new gating dimension over shops):** forge
  offering/hide predicates read the **candidate item instance** (def, tags, current forge
  level) — so a smith can refuse a key item or an over-upgraded item.
- **UI = two-pane, inline forecast** (shop-consistent, `FocusedDetailPane`); tabs
  `[Upgrade]` (allocation grid) / `[Modify]` (repair + reserved transform). Collapses to
  stacked on narrow/mobile.
- **Deferred (registry accommodates, not authored in v1):** transform (overlay per-op:
  rebase|reset), effect-bundle grants (v2, **always stackable / cap-gated**, via Band 5
  Q5), materials + item-as-cost (`item` CostSpec scope, `[FRG-19]`), on-map/dialogue
  entry points, per-map forge allowance tied to shop refresh cadence, shop-folding
  (`[FRG-20]`).
