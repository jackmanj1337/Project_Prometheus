- **`B1-CST` Slice 2 (prep/results flow) is Implemented.** Slice 1 built the
  progression graph; nothing walked it. The runtime layer now exists:
  - `scripts/autoloads/CampaignManager.gd` (registered after `DataManager`) owns
    the campaign runtime position — `active_campaign_id`, `current_node_id`,
    `cleared_node_ids` — and the prep -> map -> victory/defeat -> results ->
    next node flow. It resolves a node's `map_id` to its registry entry, drives
    `GameState.configure_next_map`, and routes results off the existing
    `EventBus.map_victory` / `map_defeat` / `map_resolved` signals.
  - `DataManager` caches the map registry in the catalogue pass and exposes
    `get_map_registry_entry` / `has_map_registry_entry`, closing the id -> entry
    lookup gap the handoff named. An unknown map id is a loud error, never a
    fallback launch. `collect_map_registry_ids` now derives from the same cache
    loader instead of parsing the file a second way.
  - `GameOverScreen` gained the campaign **"Next Battle"** route (hidden for a
    bare single-map launch and for a defeat; "Finish Campaign" on the terminal
    node). It takes focus when shown; otherwise Retry keeps focus as before.
- **One deliberate deviation from the handoff's recommended shape.** The handoff
  said "victory -> mark cleared + advance". A win instead **records** a pending
  result, and the position advances only when the results surface **commits** it
  (`commit_pending_result`, called by "Next"); Retry calls `clear_pending_result`.
  Advancing on the victory signal breaks the handoff's own retry landmine: Retry
  replays the SAME map, so the campaign would sit on node N+1 while node N is
  replayed, and a second win would clear N+1 and skip a node. Tested both ways
  round.
- **Roster continuity, not in the handoff but required for correctness.** The
  first node of a run seeds the party from the map registry's authored
  `roster_policy`; every later node launches with `keep_current_roster`. Without
  this each node would reload the default roster `.tres` files and wipe earned
  levels and gold.
- Slice 2 **persists nothing** — the position is runtime-only until Slice 3, so
  the F1 manifest is unchanged. With no campaign active every handler no-ops, so
  the bare single-map launch from `NewGameScreen` is unchanged.
- The `godot --import` pass migrated 13 `*.png.import` files to Godot 4.6.3's new
  default keys (`compress/uastc_level`, `process/channel_remap/*`). No behavior
