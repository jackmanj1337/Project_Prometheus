# Session Note 2026-07-07k - B6-INPUT focus seam continued

## What was done

Continued the `B6-INPUT` input-mode/focus seam from the 2026-07-07j handoff, landing
the two pieces that note flagged as next: the Settings gray-state selector and the
focus-grab subscribers.

1. **Settings gray-state input-mode selector.** Added an `Input Mode` row
   (`HBoxInputMode/OptInputMode`) to `SettingsScreen.tscn` and a schema entry in
   `_ENUM_SETTINGS` with an `"availability": true` marker. `_apply_mode_availability`
   reads `InputModeManager.available_modes()` and DISABLES (does not hide) the items
   whose mode is unsupported on the platform — e.g. `touch` on desktop shows grayed but
   visible, keeping the vocabulary self-documenting. The resolver still falls back at
   runtime, so a stale saved mode is safe. Moved the Input Mode entry in `GDD_07` out of
   "Hidden / not yet implemented".

2. **Focus-grab subscribers (`ModalScreen` base).** The shared `ModalScreen` now
   subscribes every modal to `input_mode_changed`. While a modal is visible: a switch
   **to gamepad** grabs a default focus (`_focus_default()`, overridable — base picks
   the first focusable Control, `SettingsScreen` → Back, `UnitDetailsScreen` seeds its
   `SelectionCursor`); a switch **to touch** drops the stale focus highlight
   (`_release_stale_focus()`); a switch to `mouse_keyboard` is deliberately left alone
   because that mode lumps mouse+keyboard together and keyboard nav still wants the
   highlight. Hidden modals ignore the switch. `NewGameScreen` / `PromotionScreen` /
   `ReclassScreen` inherit the base default with no per-screen override.

Updated DoD#1 docs in `GDD_01`, `GDD_07`, `GDD_10`, `GDD_Feature_Index`, and the
Project Control Plane; regenerated INDEX/REGISTERS.
