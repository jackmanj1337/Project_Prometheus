# Session 2026-07-11 — Art-style research + Viewport-Expand scoping

**Historical record.** Research/discussion + one documentation commit on `v0.3.0-features`.
No engine/gameplay code changed.

## What was done

Discussion-first session on game art and display scaling, ending in a scoping doc wired
into the control plane.

1. **Art-style research (discussion only).** Covered pixel vs vector vs HD, pixel-perfect
   rendering in Godot 4, texels vs pixels, small icons/text, combining multi-source art,
   colour schemes + palette-swap shaders, and UI/unit animation. Grounded against the
   existing `design/ui_ux_art_asset_research_2026-07-02.md` (which already owns genre UI
   conventions, nine-slice, atlases, fonts) so nothing was duplicated. Net recommendations:
   `canvas_items` stretch (pixel board + crisp/SDF HD UI), palette-swap recolour as a
   data-driven registry (one grayscale sprite → N factions/classes), uniform 32px sourcing
   (LPC is 64px → later tier only), `AnimatedSprite2D` for units + `AnimationPlayer` for
   synced UI/combat.

2. **"Bigger display shows more tiles" scoping.** Verified in code that the **camera is not
   the blocker** — `CameraController` uses a discrete manual player zoom decoupled from
   window size and sizes all its math from a live `get_visible_rect().size`, so it already
   adapts to a larger viewport. The blockers are `project.godot` `stretch/aspect="keep"`
   (letterbox + fixed 1280×720 base) and UI that is imperatively centred against that base
   (`MenuScale._recenter`, plus the 16:9-only `RESOLUTION_CHOICES` curation that exists
   *because* of `keep`). Also flagged: `snap_2d_transforms_to_pixel` is unset (only the
   *vertices* snap is on) — that's the one relevant to whole-sprite motion shimmer.

3. **Key finding — no new register needed.** The open decision already lives in the control
   plane as the `UI-VIEWPORT-ASPECT` row ("Open decision"), which had already named the
   `CenterContainer` / delete-`MenuScale._recenter` refactor (~11 scenes) as the cost driver.
   So the scoping doc was linked *into* that row rather than minting a redundant `[XXX-n]`.
