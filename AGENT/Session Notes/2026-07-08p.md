## Confirmed root causes (details in the triage plan's workstream sections)

- **V030-SUS-01 (a)** — `TurnManager._restore_unit_states`
  (`TurnManager.gd:184-194`) fills `_unit_states` directly, bypassing
  `set_unit_state` (`:582-593`), so restored DONE units never get
  `set_done_appearance()`: they LOOK ready but are correctly gated. The
  "unable to move" symptom is a stale-visual bug, not a state bug.
- **V030-SUS-01 (b)** — pairing hides the support at `OFF_MAP_TILE (-1,-1)`
  (`MapCursor.gd:1203-1204`); resume spawns every payload unit visible via
  the normal `_spawn_unit` path (`GameMap.gd:240-258`) and
  `PairUpRegistry.restore` (`PairUpRegistry.gd:193-195`) is dict-only —
  nothing re-hides the support.
- **V030-SUS-01 (c)** — `start_map_from_suspend` (`TurnManager.gd:112-135`)
  restores a non-blue phase (locks the cursor, `MapCursor.gd:214-217`) but
  never re-enters the awaited faction-scheduler loop
  (`TurnManager.gd:~430-486`): no controller drives the phase, no unlock ever
  comes. Debug latch also re-derived from current (off) flags at `:135`.
  Fix decision open: gate Suspend & Quit to blue phase (cheap) vs re-enter
  the scheduler on restore.
- **V030-SUS-01 (d)** — restore assigns `gs.turn_number` (`:131`) without
  emitting `turn_changed` (only `_complete_round` emits); the HUD label
  updates only via `_on_turn_changed` (`HUD.gd:374`, `:663`).
- **V030-GP-01 (scroll)** — SettingsScreen's `ScrollContainer`
  (`SettingsScreen.tscn:35`) lacks `follow_focus = true`; only
  Promotion/Reclass have it (the V026-05b fix class, recurring).
- **V030-GP-02 (menu stick cadence)** — custom menus (`ActionMenu.gd:162-167`,
  `UnitDetailsScreen.gd:621+`) navigate via stateless per-event
  `event.is_action_pressed("cursor_*")` with `cursor_*` bound to the stick
  axis: every analog fluctuation above threshold steps again ("too fast"),
  stabilized values deliver no events ("stops weirdly"). Settings (engine
  focus nav) steps once per press, no repeat. One owned menu repeat/deadzone
  policy fixes both halves.
- **V030-GP-03 (triggers)** — `_poll_held_zoom` (`MapCursor.gd:1909-1924`)
  has NO activation threshold (`strength <= 0.0` is the only gate) and the
  repeat lerps to 0.12s at full pull; the lightest graze zooms immediately.
- **V030-INP-02** — already confirmed at triage
  (`InputDisplay.active_pad_brand()` brands from `get_connected_joypads()[0]`).
