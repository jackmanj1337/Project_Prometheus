### While-we-wait build: [B5-VICTORY-PROGRESSION-SEQ] (Q6) — IMPLEMENTED

With the playtest out, pulled Q6 forward (owner-selected). Root-grounded the flow:
`CombatResolver` awards EXP (→ `level_up_started`, and a queued `promotion_available`
under auto-promote) at lines 792-795 **before** `handle_death` (804-807) fires
`unit_died` → `TurnManager.check_victory_conditions` → `map_resolved` — so a result
always lands while a progression flag is already set. `GameOverScreen` now holds the
result and presents only once the level-up/promotion queue drains: tracks the four
started/finished signals; a plain victory still presents synchronously; and because a
promotion queued behind a level-up starts **synchronously during `level_up_finished`**
(connection order not guaranteed), the re-check is deferred a frame so the cascade sets
`_promotion_active` first. `test_game_over_sequencing.gd` (new, +its `.uid`) covers
kill → level up → queued promote → THEN victory and **fails on a naive synchronous
present** (verified). Control-plane row flipped Planned → Implemented; GDD_07 Game Over
Screen section documents it (DoD#1). Full suite (50) + 21 doc checks green.
