# Session Note 2026-07-07d - v0.2.8 triage owner decisions (Q1-Q3)

## What was done

Ran the owner walkthrough of the v0.2.8 triage review questions and recorded the
decisions, including a root-cause diagnosis of the recurring menu-recenter bug.

- **Q1 (custom-size readout) -> Option A:** structured display-size status API in
  `SettingsManager` (preset request vs. custom observed client size); Settings label
  renders from the structure, custom values not re-run through the 16:9 clamp. Keep
  the single saved field for now (defer the Option B data-model split). Guide +
  handbook to define the size vocabulary.
- **Q2 (maximize recenter) -> ROOT-CAUSE fix + Option A write-back:** owner asked
  why this keeps returning. Diagnosis: `MenuScale._recenter()`
  (`scripts/ui/MenuScale.gd:218-238`) is a one-shot imperative offset-bake -
  hard-sets `target.size` then `set_anchors_and_offsets_preset(PRESET_CENTER,
  PRESET_MODE_KEEP_SIZE)`, baking absolute offsets against the size *at that
  instant*. Godot resizes the panel in a *later* deferred layout pass, so the offsets
  go stale -> off-center until a re-apply. Same bug patched per-trigger four times
  (V025-05a first show, V026-01a 2.0x apply, V027-04a edge drag, V028-03 maximize).
  No `CenterContainer` in scenes; no reactive `resized` hook. Decision: section 1.6
  fix = connect each `menu_scale_targets` panel's own `resized` signal to a guarded
  re-center (re-entrancy guard so the emitted resize doesn't loop), then retire the
  deferred/coalesced timing crutches. Structural `CenterContainer` refactor deferred
  to the broader UI pass. Write-back: stop persisting maximized client size as saved
  `resolution` (`SettingsManager.gd:392-396`), restore prior windowed size on
  unmaximize; edge drags still write back (orthogonal to the centering fix).
- **Q3 (aspect/black-bars) -> Option A:** route to `UI-VIEWPORT-ASPECT`, do not block
  section 1.6. Attached the Q2 structural CenterContainer refactor to that same row.
