### Fixes implemented (all review findings the user approved)
- **#1 / #7 — combat preview accuracy.** `CombatResolver.preview_combat` now restores
  unit state *after* computing the forecast, so deterministic skill modifiers (Resolve,
  Wrath, Faire) are reflected. `_collect_combat_modifiers` takes a `preview` flag that
  `SkillHandler.apply_trigger` uses to exclude any skill with a random activation roll —
  the forecast is now fully deterministic (per the user's policy: guaranteed effects in,
  random procs out, even at 100%+).
- **#4 — `max_uses_per_combat`.** Was a declared-but-never-read `SkillData` field.
  `SkillHandler` now enforces it via a `_combat_skill_uses` counter, reset by
  `reset_combat_uses()` which `CombatResolver` calls at the start of every combat.
- **#6 — skill use accounting.** Skill handlers now return a `fired: bool`;
  `apply_trigger` consumes a per-map/per-combat use only when the effect actually
  committed (a Miracle proc on a non-lethal hit no longer burns a use).
- **#2 — staff attack gating.** Added `WeaponData.is_healing_staff()` (keys off the
  `heal_10_plus_mag` tag, not `weapon_type`, so future offensive/debuff staves stay
  attack-capable). `GridManager` attack helpers and `CombatResolver.can_counterattack`
  now exclude healing staves.
- **#3 — Retry reward duplication.** `take_map_snapshot`/`restore_map_snapshot` now
  cover `party_gold` and `party_items`, so a replay (incl. Retry after victory) can't
  re-grant map rewards.
- **#5 — Settings entry.** `MainMenu` instances `SettingsScreen`, exposes a Settings
  button, and binds a new `open_settings` input action (O). The settings UI was
  previously unreachable.
- **#8 — unenforced caps.** `GameState.max_skills`/`max_inventory` marked NOT ENFORCED
  with a pointer to a new `GDD_updates.md` Phase-3 roadmap item.
- **#9 / #10 / #12 — polish.** `MapCursor._enter_targeting` snaps via `_set_tile`;
  `Unit.perform_staff_heal` uses `get_effective_stat("magic")`; `damage_taken_this_map`
  counts HP actually lost, not pre-clamp damage.

### Bug discovered while building the #1 test — Resolve
While writing the preview-with-Resolve regression test, found that `_apply_resolve`
used a single shared source `"resolve"` for all four stat modifiers. `Unit.add_modifier`
calls `remove_modifier(source)` first, so each call wiped the previous — **Resolve only
ever applied the speed boost**. Fixed: distinct source per stat (`resolve_strength`,
etc.); all four are `duration_type "combat"` so `clear_combat_modifiers()` still clears
them together. Surfaced to the user; fix approved.

### Flaky test fixed
Tracked down the flaky `test_combat` RNG assertion open since Session C: the
mid-combat weapon-break test forced `hit:100` but left crit unpinned — attacker crit
rate 5 vs defender crit avoid 3 gave a 2% crit chance, and a crit tripled the damage
so the `hp == 35` assertion failed ~1 in 50 runs. Fixed by raising the defender's luck
to 5 (crit avoid 5 ≥ crit rate 5 → crit% clamps to 0). Assertion is now deterministic.
