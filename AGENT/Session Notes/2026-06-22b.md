## 1. The framing
Grounded the "casual campaign builder" intent in campaign-save **branch I** (users author +
distribute homebrew campaigns; content stays data-driven / human-readable JSON / mod-friendly /
load-validated; formal pack format I3 deferred but unblocked). So AI authoring must let a non-
coder compose behavior without touching code.

**Unifying idea:** a unit's AI = composition of **three axes** (Activation / Disposition / Engagement)
+ **two cross-cutting layers** (Grouping, Difficulty). Profiles become **presets** over the axes;
each §8 gap = "extend one axis," never "rewrite the dispatch."

## 2. Owner's vision (the answers that shaped it)
- **Difficulty = author-defined bands, not an engine setting.** Each campaign declares the
  difficulty levels it supports (0..N); the player picks. A band = a **modifier overlay** (stat
  mods, extra units, more/earlier reinforcements, AI-option swaps) applied to the base encounter
  at load. Authors get full manual control (level, stat mods, skills, every AI option); we ship
  recommended presets in docs + the eventual GUI editor. **Ties FOW-2 encounter layer + §2.**
- **Legibility:** danger zones **+ per-enemy disposition/profile shown by default**; an opt-in
  **action-preview** ("what would this unit do now?") gated for tutorial/easy. Caveat (owner):
  the preview is **non-binding — recomputes as earlier AI units act this phase**.
- **Authoring:** presets-first over data files; eventual GUI editor on the same data.
- **Architecture:** composition engine — yes.
