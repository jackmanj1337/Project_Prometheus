# Session 2026-07-11d - Theme rollout to Item/Weapon/Settings/Main (playtest branch)

Branch: `agent/claude/2026-07-11/ui-theme-rollout`, cut from `v0.3.0-features` right
after 2026-07-11c's `MenuScale` fix landed there. Resumes the theme rollout
2026-07-11b deferred until the fix was in.

## What was done

- **Wired `assets/themes/manasoul_ui.tres` into the four remaining
  `menu_scale_targets` screens:**
  - `ItemMenu.tscn` / `WeaponMenu.tscn` — theme assigned directly on the root
    `PanelContainer`, same pattern as `ActionMenu.tscn`. Both scripts call
    `MenuScale.apply_to(self, factor, false)`, i.e. MenuScale targets that exact
    root node — this is now safe post-2026-07-11c-fix (the scaled Theme derives
    from the captured base instead of replacing it).
  - `SettingsScreen.tscn` / `MainMenu.tscn` — theme assigned on the root
    `Control`, NOT on the `Panel` child that `MenuScale` actually targets
    (`ModalScreen._menu_scale_target()` returns `"Panel"` for Settings;
    `MainMenu.gd` calls `MenuScale.apply_to($Panel, ...)` explicitly). Same safe
    "ancestor fallback chain rescues it" pattern 2026-07-11b established for
    `UnitDetailsScreen`. `SettingsScreen.tscn`'s `Panel` had a hardcoded
    `theme_override_styles/panel = StyleBoxFlat_panel` (bg_color `(0.12, 0.12,
    0.16, 1)`) that would have permanently shadowed the theme regardless of
    MenuScale — removed it, mirroring the `UnitDetailsScreen` treatment.
    `MainMenu.tscn`'s `Panel` had no such override, so no removal was needed
    there.

- **Verified with an ad-hoc headless check** (same effective-theme-resolution
  technique as `ui_inspection_preview.gd` — `get_theme_stylebox()` on the live
  node after `apply_menu_scale(1.0)` — written to a temp script, run once, then
  deleted; not committed). All four screens resolved the real
  `20250420manaSoul9SlicesA-Sheet.png` `StyleBoxTexture` for
  `PanelContainer/panel` at factor 1.0. Did not extend the permanent
  `ui_inspection_preview.gd` tool to cover these four scenes this session
  (scope was the rollout itself); worth doing in a follow-up so regressions on
  these screens get caught the same way `ActionMenu`'s was.

- Confirmed `NewGameScreen.tscn` (a `MainMenu.tscn` child scene) is unaffected
  by `MainMenu`'s new root theme — it has its own hardcoded
  `theme_override_styles/panel` override on its `Panel`, which always wins
  over any ancestor Theme regardless of this change, so it keeps its existing
  flat style exactly as before. Scope stayed at the four intended screens.

- Updated the `UI-INSPECTION` row's "Next action" cell in
  `AGENT/Docs/plans/project_control_plane_2026-06-29.md` describing the
  rollout and explicitly noting it does NOT resolve the separate `V027-05a`
  open decision (MainMenu Menu-Scale exemption) — `MainMenu` still scales like
  every other target; it just doesn't lose its theme while doing so anymore.
