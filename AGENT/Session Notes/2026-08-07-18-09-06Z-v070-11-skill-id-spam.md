## What was done

Built V070-11 from
`AGENT/Docs/plans/v070_11_datamanager_skill_spam_handoff_2026-08-07.md`.

**The handoff's step 1 was the whole job.** It said to establish coverage before
touching `get_skill()`, because the return's volume suggested a path the activation
validator does not walk. It does not, and the reason is sharper than a missing check:
`select_tier2_campaign_source` never sets `session.skills`, and the adapter has no
skills catalogue to set it from — the skills family is still unregistered in the
zero-content schema work. **Under any active campaign pack `_skills` is empty**, so
every unit skill id misses. That is the ~3,200 lines: eleven distinct ids, `wrath`
802 times, none of them typos. Separately, `collect_unit_validation_errors` never
looked at `skills`/`earned_skills`/`mastery_skills` at all — it walks class ids,
levels, WEXP tracks and growth keys — while `_check_class_refs` only covers
`ClassData.skill_unlocks`. Unit-level skill references, the arrays `SkillHandler`
actually resolves, were walked by nothing.

**That ruled out the handoff's step 3 as written.** It proposed recording the fact in
`_activation_errors`, but `_commit_session` clears that list, so a non-empty
`_activation_errors` means "activation failed" — the compat path returns `false` on
it. Putting a survivable authoring gap there would either be erased on commit or
refuse to activate the content. Since every pack would trip it, the second reading
would make every pack unlaunchable.

So the fix adds the missing channel rather than overloading the fatal one:

- **`content_status()["warnings"]`** — content-authoring facts about the content that
  IS live, separate from `"errors"` (why activation failed). Scoped to one
  activation.
- **`_report_unknown_id(kind, id, context)`** — dedupes on `<kind>:<id>`, appends to
  the warning list, and emits one `push_warning`. `get_skill`, `get_item`,
  `get_weapon` and `get_class_data` all route through it. All four had the identical
  shape; the handoff named the first two.
- **`_report_unresolved_unit_skills`** — the activation-time coverage, run after
  commit on the units the committed content carries: a pack's rosters plus its inline
  enemy placements, and project data's default roster. Non-fatal by design.

Lookups still return `null` and callers still null-check; only the report's
cardinality changed. Nothing goes silent — an id on a path no validator walks is
still reported by the first lookup that misses it, then suppressed.

**Not touched, deliberately.** `scripts/tools/validate_pack.gd` prints
`content_status()["errors"]` and would be the natural consumer of the new warnings
key, but it is claimed by `PACK-FEATURE-COVERAGE-WARNINGS-2026-08-07`.
`NewGameScreen` does not read `content_status()` on this line at all — the V070-05
fix that renders it is still on `agent/from-integration/v070-blocker-fixes`.
