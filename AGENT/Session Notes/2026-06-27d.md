## 2b. Side check — can a dialogue trigger victory/defeat? (asked this session)
**No — not built, not designed.** Objective system EXISTS (`ObjectiveCondition`, `TurnManager.
check_victory_conditions` → `EventBus.map_victory/defeat`) but the **`type` enum is CLOSED**
(`rout/defeat_boss/seize/escape/survive/protect/turn_limit` — no flag/event/predicate type) and is
**polled only at phase boundaries**. Four gaps block a DLG-driven win/loss: (1) no flag/predicate
condition type — the *same* closed-enum blocker `[DTH-10]` hit; (2) **no F6 flag store** (designed,
unbuilt; `GameState` has only debug flags); (3) **MET unbuilt + has no "end map" action** (v1 actions =
`reveal_tiles`/`flag`/`spawn`; DLG `command` can fire a MET action but none ends the map); (4)
event-timing (a mid-dialogue flag wouldn't re-check until the next phase boundary). **Two paths offered:**
(A) declarative — migrate the objective enum toward **F16 predicates** / add a `flag_set` type + build
F6 (also unlocks `[DTH-10]`); (B) imperative — a direct `end_map: victory|defeat` DLG/MET action.
**PINNED (owner 2026-06-27d):** a `[DTH-10]` forward-pin (design content) + the **atlas A4 objective
keystone** (scheduling), framed as an **objective-system-extensibility define-all-sweep item that MUST
precede the F1 lock (Phase B) — hence before the Phase C evaluation/triage session** (it's
schema-affecting, can't wait for triage). **Later this session this pin was CONSOLIDATED into `[TCV-4]`
(§2c).**
