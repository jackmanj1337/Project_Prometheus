# Session Note - 2026-07-04c

## Topic
Make the engine log land next to the build exe and self-identify: self-contained mode
+ a startup BUILD STAMP with git commit and timestamp.

## What was done
Owner asked (this session) to (1) produce `godot.log` in the same folder as the build
exe and (2) have the game write the SHA + timestamp to the log to prove it is written.
Two design calls taken: **self-contained mode** for the location, **git commit baked at
build** for the SHA.

- **Self-contained logging (location):** shipped builds get a `._sc_` marker next to the
  exe, which redirects `user://` (logs/godot.log + settings.cfg) to a folder beside the
  exe instead of `%APPDATA%`. No `project.godot` change — the marker is the trigger. The
  marker is created by the new build-prep script and MUST be included in the release zip.
- **Build stamp (proof + identity):** new `scripts/shared/BuildInfo.gd` (no `class_name`,
  per the headless class-cache gotcha) + a call from `Boot.gd` print a framed
  `=== BUILD STAMP ===` block as the FIRST lines of every `godot.log`: version, git
  commit, built_at, a fresh per-launch `started_at` (UTC Z — proves the log was written
  this run), and the resolved `exe=` / `user_data_dir=` / `log=` paths (so the log
  self-reports where it is — no more guessing the self-contained subfolder).
- **SHA source:** `scripts/tools/prepare_build.sh` (run before export) bakes
  `{version, commit, built_at}` into `res://build_info.json` (git is unavailable at
  runtime in a shipped build) and drops `builds/._sc_`. `build_info.json` is gitignored
  (per-build artifact); the editor falls back to the live git commit tagged `-dev` when
  the file is absent, so dev runs still stamp a real commit. `prepare_build.sh` lives in
  `scripts/tools/` (excluded from exports) so it never ships in the pck.
- **Docs:** `environment_setup.md` build section gains the prepare-build step + a
  "SHIP THE MARKER" subsection; `display_and_settings_guide.md` godot.log section updated
  — shipped builds are self-contained (log next to exe), the stamp reports the exact
  path, dev/editor runs stay at the OS appdata path.
- **Test:** `scripts/tests/test_build_info.gd` — structure-based (passes with or without
  a baked build_info.json), asserts load_info populates all keys, stamp_lines is framed
  with the identity/timestamp/log-location fields, and started_at is a UTC (Z) stamp.
