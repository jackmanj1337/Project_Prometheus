## Notes
- Existing deletions in the older `AGENT/GDD/Content Expansion/` files were left
  untouched.
- The folder was originally created as `New_Contet_expansion`; it was renamed
  to `New_Content_Expansion` during the 2026-06-11 alignment migration.
- Design decisions settled this session:
  - Awakening corpus is now the gameplay canon where it conflicts with the old GDD.
  - `level` stays as displayed level.
  - `internal_level` will be added as explicit hidden progression state.
  - repeated Second Seal pressure will be tracked separately from `internal_level`.
  - base classes use `internal_level = level`.
  - promoted classes use `internal_level = 20 + level`.
  - promotion resets displayed level to `1` and internal level to `21`.
  - special classes should use explicit data-driven rules.
  - any unit can access any playable class by default.
  - there will be no gender-locked or gender-differentiated classes.
  - `special_qualities` stays for movement and broad trait behavior.
  - `vulnerability_groups` will be added for combat effectiveness targeting.
  - `mounted` and `flying` may appear in both fields.
  - numeric `wexp` is the source of truth and displayed rank is derived.
  - WEXP thresholds should live in shared constants for now.
  - class-side numeric weapon baseline data should replace implicit proficiency
    ordering, with both kept temporarily during migration.
  - supported weapon types for now should cover swords, axes, lances, bows, the
    five tome/staff types in current code, plus beaststones and dragonstones.
- Open questions left for next session:
  - whether weapon `type` and WEXP track should always be the same thing
  - whether the five tome types should remain distinct WEXP tracks long-term or
    collapse into fewer progression tracks with separate combat-family metadata
  - exact schema shape for class-side numeric weapon baseline data and
    class-side maximum WEXP data
  - how much of staff behavior should remain inside `WeaponData` versus a
    dedicated resolver subsystem
