# Session Notes — 2026-05-20c

## Context

User asked to fix the updated Docker container so one image can support both
Claude Code and Codex without juggling separate containers.

## What Was Done

- Confirmed the image builds when Docker has access to the host Docker config.
- Reproduced the runtime issue: `godot --version` reported
  `libfontconfig.so.1: cannot open shared object file`.
- Added `libfontconfig1` to the Docker runtime dependencies.

  the current `agents-godot` service and include Codex login/use.

  keys.

## Follow-up

User reported `ai-codex` and `ai-codex-yolo` were not found after rebuilding.
Root cause: the existing `developer-home` Docker volume preserved the old
`~/.bashrc`, hiding aliases written during image build. Follow-up fix moved

`/etc/agents-godot/bashrc`, outside the persisted home volume.
