## 1. The framing verdict (`[BAT-1]`) — neither pole, a hybrid
The battalion is **not** an equippable `InventoryEntry` (merge pole) and **not** a ground-up subsystem
(bespoke pole). It is a **thin `BattalionData` + `BattalionRegistry`** over **four reused substrates**:
- **attach** → the `PairUpRegistry` *pattern* (id-keyed dict, GameState map-start snapshot + retry-
  restore, campaign-gate) — a **sibling** registry (`unit_id → battalion_id`), not the same instance,
  because a battalion is a **data entity, not a roster unit** (`[BAT-2]`).
- **passive bonus** → the `PairUpBonusResolver`/`StatContributions` pipeline (stat dict → combat
  modifiers; grows the drift-guard test) (`[BAT-3]`).
- **gambit source** → already firmed A1 (`[STY-7]`, `[CEX-20]` granted union + charges) — reconcile,
  don't relitigate (`[BAT-4]`).
- **rank ladder** → reuse the **pure `weapon_rank_for_wexp` threshold helpers**, but **store progress on
  the entity** (not `unit.weapon_wexp` — it's not a weapon track); EXP award rides the `[AGT §6]`/A5
  non-combat-action EXP rule (`[BAT-6]`).
Net-new state = only the **endurance counter** (`[BAT-5]`, draws the `[AGT §5]` rate-limit/charge
primitive) and the **on-entity EXP/rank** field. Same call `[DSP]` made (reuse Pair-Up attach, don't
reinvent).

## 2. The pattern + the altitude ladder (the spine of the pass)
Reframed "the battalion" as the canonical config of a generic **attached-augment entity**: *an entity
attached to a host via a snapshot/restore registry, conferring {passive bonus · granted source/style ·
optionally granted skills}, gated by a charge/endurance resource, on its own rank ladder.* **Five
composable axes.** Discriminator that stops it swallowing solved systems = **(1)** needs the attach
lifecycle AND **(2)** confers >1 axis. The ladder:
```
pure passive item ............ equip / accessory_component                 [IEQ]
  + a granted skill .......... equip + skill-grant path                    [IEQ §2f] (Knight Ring)
  + granted source+charge+rank ATTACHED-AUGMENT (battalion, Emblem)        [BAT]
attach a real *unit* ......... Pair-Up / adjutant                          PairUpRegistry [BAT-8]
positional, not attached ..... aura skill (charm/anathema/daunt)           GDD_05/M9
on the map, takes turns ...... summon / roster unit
mount / shapeshift ........... class / form toggle
```

## 3. The two trope tests the owner raised
- **Emblem/Bond rings (`[BAT-7]`/`[BAT-9]`):** the **Emblem** is the *maximal config* of the same entity
  (flip the granted-skills axis on, "endurance"→"Engage gauge") — **validates the abstraction's altitude**
  (Engage-style = content, not code). Emblems are **NOT on the roadmap** (no GDD mention) — a stress-test,
  not a build. A **bond ring** = a single-axis passive → stays in `[IEQ]` as an `accessory_component`
  (bonus + item-proficiency track). Don't pull single-axis tropes into the entity.
- **Adjutant (`[BAT-8]`):** the trap. It *looks* like "a battalion that's a person" but attaches a **real
  roster unit** → that's **Pair-Up** (it already has lead/support roles + `OFF_MAP_TILE` + snapshot). So
  adjutant = a Pair-Up mode (off-map support + an intervention flag) on the **actual `PairUpRegistry`
  instance**. Resolves the open question flagged last pass ("actual instance or just the pattern?" →
  **the actual instance**).
