## Plan Scope To Write

### Slice 1 - `B2-REGISTRY`
Plan the minimum registry manifest foundation before any author-facing
vocabulary conversion.

The plan should name the initial registry loader/validator shape, where built-in
developer presets live, how unknown/duplicate ids fail, and how entries declare
handler/schema/projection/save metadata.

Recommended first conversions to plan against:
- one small primitive/action registry entry,
- one resource type registry entry,
- one occupancy/death/projection-adjacent registry stub if needed for tests.

Do not plan a broad conversion of every vocabulary in one slice.

### Slice 2 - `B2-ACTION-EFFECT`
Plan the shared mutation primitive runner.

Focus on:
- `ActionContext`,
- `ActionResult`,
- validation vs commit behavior,
- safe points,
- RNG policy through `RngService`,
- ResourceLedger delegation,
- save side-effect reporting back to F1 rows,
- one primitive callable from at least two domains.

Do not merge all vocabularies. Keep MET/DLG/SAC/STY vocabularies separate while
sharing the primitive execution contract.

### Slice 3 - `B2-RESOURCE-LEDGER`
Plan the transaction API before shops/training/source costs consume it.

Focus on:
- resource registry entries,
- `quote`, optional `reserve`, and `commit`,
- party/unit/source-scoped wallets,
- atomic multi-resource failure,
- refund from recorded transaction data,
- save manifest fields for persistent wallets and transient counters.

### Slice 4 - `B2-OCCUPANCY`
Plan the shared placement service.

Focus on:
- transaction context,
- `require_empty`, `nearest_free`, `delay`, `skip`, `swap`,
  `overlap_hidden`, and `object_unit` policies,
- deterministic nearest-free tie-breaks,
- map-start validation and public spawn paths,
- no direct public spawn bypass.

### Slice 5 - `B2-DEATH-LIFECYCLE`
Plan the death funnel and disposition integration.

Focus on:
- `DeathContext`,
- single `handle_death(ctx)` entry,
- DeathDisposition inventory/key-item custody hooks,
- simultaneous death snapshot ordering,
- object-unit exclusion from roster disposition,
- objective/event notification.

This slice depends on `B2-ACTION-EFFECT` for scripted/hazard death producers,
but combat death can be the first funnel consumer.

### Slice 6 - `B2-PROJECTION`
Plan the dry-run/projection service after action/effect terms are firm.

Focus on:
- no live mutation,
- no committed RNG draws,
- projection context/result shape,
- combat preview as first adapter,
- later AI/predicate/perception consumers,
- no-save guard tests.

Keep this slice behind action/effect in the implementation order unless the plan
finds a smaller combat-preview extraction that is safe to do first.

### Slice 7 - `B2-DATAMANAGER-SEAMS`
Plan the DataManager load/validate/default-roster phase refactor and campaign
source seam.

Important: use the post-ICO interpretation from the DMR register. The old
base+overlay merge language is provenance only; the current content model is
self-contained replace-load. The plan should avoid building a merge engine.

Focus on:
- `_load_all(source)` phase,
- `_validate_all() -> Array[String]`,
- `_report(errors)`,
- `select_campaign(campaign)` replace-load seam,
- first-run seed-copy and `user://` enumeration as later campaign-sharing work,
  not a Band 2 requirement unless explicitly pulled forward.

## Decisions Not To Reopen
- Author-facing extension points are open registries, not closed enum+match
  additions.
- F1 owns saved-field manifest rows before features add new saved state.
- Action/effect runners share a mutation context/result contract but do not
  collapse every feature vocabulary into one vocabulary.
- Resource spending goes through a ledger; feature code should not mutate
  wallets directly.
- Non-standard placement goes through occupancy transactions; public spawn
  should not bypass occupancy policy.
- Death producers route through one death lifecycle funnel once the funnel
  exists.
- Projection is side-effect-free and must not advance committed RNG history.
- DataManager campaign content loading is replace-load for self-contained
  campaign packs, not runtime overlay merge.
