### Investigation (full diagnosis delivered to the user)
Root-caused all 6 defects + 3 observations against the code. **Correction:** during
triage I called Defect 3 (pair-up bonuses) a "correct code path" — that was wrong. A
follow-up unit test (see below) proved it a **real bug**: the static read missed that
`add_modifier` removes all modifiers sharing a source, and the pair-up code reused one
source for every stat, so only the last bonus survived. Lesson: write the asserting
test before declaring a pipeline correct.

### Follow-up — Defect 3 (pair-up bonuses) was a real bug, now fixed
Writing the asserting unit test (`test_combat.gd`: paired lead's `preview_combat`
damage must rise by the support's strength contribution) **failed** at first — proving
the bonus never reached combat. Root cause: `CombatResolver._apply_pair_up_bonuses`
stamped every stat under one shared modifier source, and `add_modifier` removes all
modifiers sharing a source before adding, so each stat wiped the previous one and only
the last (luck) survived. Fixed with a distinct source per stat
(`pair_up:<support_id>:<stat>`) — the same pattern SkillHandler's Resolve already used.
Committed `b53a385` with the regression test and the GDD_05/GDD_10 doc updates.
