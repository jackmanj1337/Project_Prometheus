## 1. Extensibility research (the `[EXT]` framing, explained for the owner)
Walked the three candidate directions against the two **binding** project constraints — packs are
**data + raw art, no code** (`project_campaign_content_model`) and **determinism/save-replay** (Package A):
- **A — data-composition only** (named macros over engine primitives): fits no-code + determinism + load
  validation; ceiling = the primitive set; cheapest.

  determinism a *security* problem, hard validation, web binary/perf cost.

- **Recommendation = A as an "A-plus" hybrid:** ship A; keep B as a *narrow, evidence-driven* future
  exception (one "expression-bodied term" slot) reusing A's eval tree. The A/B line is **porous** — most
  "B-only" examples dissolve into "ship one more primitive," which is exactly the A-plus loop.

## 2. `[REQ-16]` arithmetic value terms — the walk (RESOLVED 2026-06-26)
Owner asked to add basic math ("is STR+MAG > target", "ratio of A:B > C^D"). Key reframe: **this lives
inside Option A** as a **recursive compound *data tree***, not a parsed string → preserves no-code +
determinism + validation. End-shape-first walk, owner calls:
- **Number model = fixed-point ×1000** (owner pick over float/integer-only — float `pow`/`div` is not
  cross-platform bit-identical → save/lockstep desync; fixed-point is bit-deterministic across
  desktop/web/lockstep and **restores safe `==`**). 64-bit, per-node clamp to ±MAX_FIXED.
- **Operators v1:** `add sub mul div pow min max abs neg` + number-domain booleans `not and or truthy`.
  **`pow` = integer exponents only** (`0^0≜1`, neg-exp via divide); fractional-exp pow = deferred
  build-investigate (deterministic fixed-point exp/log is the hard part).
- **Rounding:** **half-up** default on every lossy op, per-node `floor|ceil` override (generalizes the
  owner's "divide round-up/round-down" idea — supersedes separate div_floor/div_ceil ops).
- **Divide-by-zero = REQUIRED explicit `on_zero`** (`to_max|to_zero|to_value`) — owner call: a single
  global sentinel is *wrong* (ratio-vs-resistance wants `to_max`, averages want `to_zero`); builder forces
  the choice, hand-authored omission = validate error. **No "undefined" propagation** (number domain stays
  total/closed; "shouldn't fire" → explicit guard predicate). Owner asked for guidebook/editor notes on
  good formula/trigger construction + `on_zero` recommendations.
- **Number-domain booleans:** rule **`>0` true / `≤0` false**, output canonical `1.0/0` (owner's spec).
  Primitives `not/and/or/truthy` only; **comparisons `gt/lt/ge/le/eq/ne` and `xor` ship as named
  compositions** (all derive from `{not,truthy,sub,abs}` — explained to owner). `eq` on computed/rounded
  values is fragile → tolerance-band guidance.
- **Logic↔predicate bridge = DEFERRED** (owner), **split by purity** (owner refinement): a future
  `from_predicate` down-bridge would admit **deterministic/pure** predicates only; **chance-based
  (`[REQ-10]`) predicates are permanently excluded** from inlining (they reach a formula solely via their
  **latched** `0/1` outcome — inlining live RNG would break determinism). v1 substitute for both = the
  **flag-upstream pattern** (a predicate writes `[F6]`; a term reads the flag as `0/1`).
- **Terms substitutable in numeric value slots (uniform):** wires **REQ-10 `chance` skew `input`/`base`**
  (subsumes `difference|ratio` → author **custom contest curves**, skew input stays pure, no new RNG
  surface) + **effect magnitudes** (FE-style scaling); DLG/F4 presentation params deferred.
- **Complexity budget = author-declared, FULL HEADROOM** (owner): F4 CampaignRules `max_formula_depth` +
  `max_formula_nodes` (node-count is the real cost proxy; **depth alone is cheap** — corrected the
  perf premise), **no universal mobile ceiling**; only an **absolute safety ceiling** + an **iterative
  (explicit-stack) evaluator**. Guardrail is **social/documentation**: warn players, **request a primitive,
  consider joining the dev team** — the primitive-request channel **doubles as a contributor on-ramp**.
- **Authoring:** tree-builder v1; string front-end later **parses to the validated tree** (still Option A).
