  - **CL-TRANSFER-02** — v1 uses **distinct compound filename suffixes on the generic containers**
    (not branded single-token extensions): `.clean-pack.zip` / `.with-runs.zip` /
    `.portable-run.zip` / `.status-record.json`. Scanner routes on the `<type>.<ext>` suffix and

    association deferred to a Windows-installer fast-follow (approval-gated; brand token matches the
    shipped store title). Current code exports generic `.zip` (packs) / `.json` (saves) with no type
    marker — this scheme adds one.
  - **Portable Save -> Portable Run (owner catch, mid-branch).** The transfer unit for playthrough
    state is the **Run**, not the save: a save is only meaningful relative to its run (inherits the
    run's rule profile + place in cumulative progress), so a run-less save is not independently
    resumable, and CL-LIFE-06 already made the *run* the export scope ("Export run(s) only").
    Portable Run = a ZIP bundling rule profile + progress + save(s); a save-level Export produces a
    Portable Run pinned to that snapshot (a one-save run) so no un-resumable bare-save format exists.
    In-browser the individual save type keeps the name **Save**; only the transfer artifact is a Run.
    Code reality: saves are currently fat/self-contained and the first-class Run is still a planned
    grouping key (Branch A), so Portable Run is realised when the Campaign->Run->Save tree is built.
  - **CL-TRANSFER-01** — contextual actions on each pack/campaign/run + a **thin Transfers hub** that
    only explains scopes (thin because full-library backup, its main draw, is deferred).
  - **CL-TRANSFER-06** — explicit **Included / Excluded** summary at **both preview and success** for
    every export scope; load-bearing because clean and with-runs share the `.zip` container, so the
    component list (not the filename) proves whether a save rode along.
  - **CL-TRANSFER-03/04/05 deferred** — restore preview / restore granularity / rollback are
    whole-library backup-restore mechanics; recorded against `BACKLOG-FULL-LIBRARY-BACKUP`. The
    per-pack import preview + atomic promote + rollback is already specified in the Branch D
