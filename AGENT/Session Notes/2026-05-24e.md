### Mid-step UX refinement — AttackPreview repositioning
Before step 6, you asked for the preview panel to anchor adjacent to the
defender on screen and pan the camera when neither side fits.

- `CameraController.pan_by_pixels(delta_px)` — pixel-granular camera shift
  with map-bounds clamping (mirrors `keep_cursor_in_view`'s clamp). Only
  writer of pixel-granular camera moves; lives next to `nudge_by_tiles`.
- `AttackPreview.setup(camera, grid, camera_ctrl)` injected from
  `MapCursor.setup` with a `has_method("setup")` guard so the existing
  `StubPreview` in `test_targeting` keeps working.
- `show_preview()` now calls `_reposition_for(defender)` after content
  updates. Right-of-defender placement preferred → left fallback → camera
  pan as last resort. Vertical position clamps to the viewport so the panel
  never clips at the top or bottom. Panel size is read dynamically
  (`_panel.reset_size()`) so the InfoBox added in step 6 just makes the
  panel wider without breaking the math.

### Step 6 — Combat preview More Info side panel + selector
The second host of the side-panel pattern from `UnitDetailsScreen`.

- Every preview row (Name / HP / Damage / Hit / Crit / Triangle /
  Effectiveness — 7 per side) is now a clickable
  `[url=combat_field:side:key]` link inside a `RichTextLabel`. Triangle and
  effectiveness markers keep their colour via inline `[color]` inside the
  `[url]` wrapper.
- New `InfoBox` column (third VBox in the HBox) with `InfoTitle`,
  `InfoHint`, and `InfoDescription`. Hint visibility mirrors the character
  sheet so the affordance feels identical across surfaces.
- `more_info` cycles all 14 rows in declaration order, including neutral
  triangle / non-effective rows that render empty but still belong in the
  cycle. `_unhandled_input` consumes the event when visible — F-chain
  priority 1 enforced explicitly.
- `MoreInfoContent.COMBAT_FIELDS` gained `name` and `hp` entries so every
  selectable row has authored copy.

### Step 7 — TileActions helper + terrain HUD expanded mode
- `scripts/shared/TileActions.gd` — single source of truth for unit-on-
  tile gates. `is_available(id, unit, tile, turn)`,
  `available_for(unit, tile, turn)`, `display_label(id)`. Seize / Escape
  delegate to `TurnManager`; Shop / Visit / Activate are wired as
  placeholders for when those systems land.
- `ActionMenu` refactored: inline `turn.can_seize` / `turn.can_escape` now
  go through `TileActions.is_available`. Behaviour-preserving — all 22
  ActionMenu tests still pass.
- `GridManager.get_move_costs_for_groups(terrain)` + `IMPASSABLE_MOVE_COST`
  — static lookup mirroring the per-unit overrides in `get_move_cost()`,
  so the HUD doesn't have to manufacture a fake unit per group. Walls
  render as `—` instead of `999`.
- `HUD` terrain expanded mode: F toggles a four-row expansion
  (description from `MoreInfoContent`, move costs per group, available
  tile actions, hint). Higher-priority guard checks `AttackPreview` and
  `UnitDetailsScreen` visibility before consuming the event — the F-chain
  priority 3 stays correct even if input-handling order changes.
