### Implementation (commit `2fb9287`)
Per stat, the inspect sheet now shows **personal base + class base + class cap**,
every **active bonus with amount + source**, and the **effective value in green**
when a bonus raises it.

- **`StatBreakdown`** — added `personal_base` / `class_base` / `cap` / `cap_state`
  / `effective_display`; merges caller-injected combat-only rows; prefix-aware
  source labels (`pair_up:…` → "Pair Up").
- **`StatContributions`** (new) — drift-safe collector for the combat-only base-stat
  sources that don't live in `active_modifiers` outside a fight: pair-up (resolver)
  + the unit's own unconditional `stat_bonus` skills. Deps injected (pure/testable).
- **`UnitDetailsScreen`** — renders the breakdown; `NO_CAP_DEFINED` for a capped
  stat with no entry, "—" for intentionally-uncapped MOV/CON/LoS, green for boosts.

### Key findings that shaped it
- **Auras are M9 stubs** (`charm`/`anathema`/`daunt` return false) and target
  hit/dodge/crit, not base stats — so they contribute nothing to this breakdown yet.
  The only live combat-only base-stat sources today are pair-up + personal stat skills.
- **All class `.tres` already populate `stat_caps`** except the **Soldier**
  placeholder (empty `promotes_to`, no skills, empty caps) — so `NO_CAP_DEFINED` is a
  loud regression signal, and Soldier is a documented intentional cap-less placeholder.

### Tests / gates
- `test_stat_breakdown` (+6) — decomposition, caps (capped/uncapped/missing/unknown),
  authored-unit personal clamp, extra_mods merge.
- `test_stat_contributions` (new) — **drift guard**: the collector's pair-up and
