### Audit

Ran all 62 existing `scripts/tests/test_*.gd` suites individually under `--verbose`,
capturing per-suite `Leaked instance: Node:` counts and `Resource still in use:`
lines. Result: **51/62 suites are leak-clean**; 11 emit the warning, led by
`test_combat` (53 nodes), `test_turn_manager` (9), `test_grid_manager` (7).

**Verdict: benign test-teardown artifact, not a production leak.** Three evidence
lines: (1) the count scales with unfreed test fixtures, not production instances —
`test_game_map_scene` instantiates `GameMap.tscn` five times yet leaks exactly one
node; (2) production has **zero `remove_child()`** (the engine's "removed but not
freed" orphan pattern can't originate there); (3) every transient production dialog
(`MapCursor` end-turn/quit/suspend/suspend-failed, `DisplayConfirmDialog`)
`queue_free()`s on all dismissal paths (confirm AND cancel). The `Resource still in
use` lines are all GDScript class-script / `ResourceLoader` cache entries, benign.

### Guard added

Because the fixture-teardown noise would MASK a real future production leak, added
`scripts/tests/test_node_lifecycle_leak.gd` (63rd suite): drives a representative
code-built production subtree (`DisplayConfirmDialog`: CanvasLayer + dim/center/
panel/vbox/labels/buttons + Timer) through the full create → `add_child` → free
cycle 12× and through a mid-countdown `free()`, asserting
`Performance.OBJECT_ORPHAN_NODE_COUNT` returns to baseline (verified precise: +1 on
an unparented `Node.new()`, back to baseline on `free()`). 3/0. The suite frees
every fixture it creates, so it is itself leak-clean (`leakwarn=0`) — the pattern
the audit recommends for retiring the exit warning entirely.
