    `factions`, `turn_order`, `activation_mode`, `victory_conditions`,
    `defeat_conditions`, `reward_gold`, `reward_items`, optional `deploy_slots` override.

    migration adapter. **Implication carried in the register:** the tactical runtime
    (`GameMap._spawn_units`, `TurnManager`) consumes monolithic `MapData` today, so the
    campaign band must compose the two defs at load OR refactor the runtime — sequencing
    is a build-track detail, the split is locked as the model.
- **`[CNC-5]` chapter → B.** `Chapter` = story-facing metadata (labels, numbering, splash
  art, save display) over one-or-more nodes; `CampaignNode` stays the sole progression
  primitive. Optional `chapter_id` per node.
- **`[CNC-6]` valid compositions → a validation matrix** owned by the campaign loader /
  `DataManager`, evaluated once at load. `battle` needs exactly one target (`encounter_id`
  XOR legacy `map_id`); `hub` forbids an encounter ref and advances by Continue; story beat

  keeps `[CNC-3]` open (open-registry principle).
- **`[CNC-9]` skirmish → C.** Same launch primitive (`[CNC-8]`) fires from a graph node OR
