## 2. The verdict (keystone)
**A village = config over four reused substrates, NOT a bespoke system:** physical village + raze =
the **DTR destructible object** (`Unit`-in-disguise, HP/Def, `object_broken`; `hp:1` = one-hit raze) ·
visit reward = the **MET trigger→action runner** · persistence/branching = **`[F6]` flags** · the
Visit action = a **`TileActions` entry firing a new _interactive_ MET trigger**.

**The one genuinely-new piece is the A4 keystone, and it's NOT village-specific:** every existing MET
trigger is a *passive* EventBus reaction (`unit_died`/`turn_reached`/`object_broken`). Village's
**Visit** and Recruit's **`talk`** (`[RCR-3]`) are a new class — **player-initiated** triggers fired
from a unit action-menu entry gated like Seize/Escape. **Code already anticipates this:**
`TileActions.gd` reserves `shop`/`visit`/`activate` placeholder ids next to wired `seize`/`escape`,
and `ActionMenu` already gates Seize/Escape through `TileActions.is_available()`. So the interactive-
trigger substrate has Visit + `talk` + reserved `shop`/`activate` as its configs — **design once.**
