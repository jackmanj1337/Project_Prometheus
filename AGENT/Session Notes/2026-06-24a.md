## What we firmed — `[SMV-1..11]` (= foundation F10)
Owner keystone call: **Secondary Movement is not a bespoke engine — it is a parameterized SKILL**
granted through the **existing** skill-grant mechanisms. Resolved:
- **SMV-1** = a `SkillData`, `effect_id="secondary_movement"`, **passive** (engine queries the
  holder's active skills at action-resolution). No new resource, no new trigger string.
- **SMV-2** movement model = a **skill parameter**: `effect_params.movement_mode ∈ {remaining, flat}`
  (+ `flat_amount`). One skill kind, two behaviors.
- **SMV-3** trigger set = **author-configurable** `effect_params.secondary_move_actions` (default =
  all turn-ending actions; **Wait never** grants it).
- **SMV-4** conferral = **existing mechanisms** — `ClassData.skill_unlocks` (mounted carry it by
  default), `[SKL-4]` grant/revoke, `[IEQ]` accessory effect_ids (**Knight Ring**), F6 story,
  `[PXP-4]` on-crossing. **Supersedes** GDD_10 M10's "automatic for all mounted."
- **SMV-5** the one new engine piece = a `UNIT_SECONDARY_MOVE` MapCursor action-flow window (reuses
  the movement-range computation + `grant_extra_turn`), ending in **Wait only** (SMV-6).
- **SMV-7** remaining = `move − tiles spent reaching the action tile`. **SMV-8** rescue/carry
  interaction **deferred to the Rescue (#6) firming**. **SMV-9** no undo once acted; window optional.
  **SMV-10** AI uses the same capability. **SMV-11** no new save field (the skill grant persists).
