# Session 2026-07-11c - Fix MenuScale theme-clobber bug (V030-BUG-01)

Branch: `v0.3.0-features`. Picked up directly where 2026-07-11b left off: fix the
`MenuScale.apply_to()` theme-clobber bug it found and confirmed, then re-run the
`ui_inspection_preview.gd` harness to verify.

## What was done

- **Fixed `scripts/ui/MenuScale.gd`.** `_apply_type_scale()` used to unconditionally
  do `target.theme = _scaled_theme(factor)`, where `_scaled_theme()` always built a
  brand-new bare `Theme.new()` — discarding whatever theme scene authoring had put on
  the target node (e.g. `manasoul_ui.tres` on `ActionMenu`'s root). Fix:
  - On a target's first touch, `_apply_type_scale` captures `target.theme` (the real
    authored theme, or `null`) into node meta (`_menu_scale_base_theme`) before ever
    overwriting it. Every later call reads the base from meta, never from
    `target.theme` itself (which by then holds the previously-assigned scaled Theme).
  - `_scaled_theme(factor, base_theme)` now derives the scaled Theme via
    `base_theme.duplicate()` when a base theme exists (falling back to `Theme.new()`
    when it doesn't, same as before), then overrides only `default_font_size` and the
    container-spacing constants on top — every custom StyleBox/font the base theme
    defines rides along unmodified.
  - The theme cache key now incorporates the base theme's instance id alongside the
    rounded factor, so different target nodes with different base themes (or no
    theme) at the same factor don't collide in the shared static cache.
  - Targets with no pre-existing theme (`UnitDetailsScreen`'s `Panel` child, the
    plain-`Control`/`PanelContainer` fixtures `test_menu_scale.gd` builds by hand)
    are unaffected — `base_theme` is `null` for them, so they still get a bare
    engine-default Theme exactly as before. No behavior change for the already-working
    path.

- **Verified with the 2026-07-11b harness.** Re-ran
  `godot --headless --path . --script res://scripts/tools/ui_inspection_preview.gd`:
  `ActionMenu` now resolves the real `StyleBoxTexture` (from
  `20250420manaSoul9SlicesA-Sheet.png` / `20250421manaSoulButtonA-Sheet.png`) for both
  `PanelContainer/panel` and `Button/normal` at **all seven** Menu Scale factors
  (0.5x-2.0x) — was FAIL at all seven before the fix, 0 FAILs on `ActionMenu` after.
  `UnitDetailsScreen` and `AttackPreview` stayed exactly as 2026-07-11b left them
  (still correctly themed / still the known harness-fidelity overflow finding,
  untouched by this fix). Full harness run: 43 OK / 15 WARN (all expected no-GPU
  pixel-capture WARNs) / 1 FAIL (the pre-existing, not-yet-investigated
  `AttackPreview` overflow finding from 2026-07-11b — unrelated to this bug, still
  open).

- Updated the `UI-INSPECTION` row's "Next action" cell in
  `AGENT/Docs/plans/project_control_plane_2026-06-29.md` with the fix summary and
  verification result (DoD#1 — behavior changed, doc updated same session).
