# Session Note 2026-07-06g - B1-SUSPEND disk lifecycle

## What was done

Finished the current **`B1-SUSPEND` active-map suspend lifecycle** on
`v0.3.0-features`.

- Fixed the stale suspend path docs from `user://suspend.sav` to the ratified
  `user://saves/suspend.json`.
- Added `SaveManager` as the disk I/O owner for suspend saves:
  - writes/reads/deletes `user://saves/suspend.json`;
  - maintains `user://saves/saves_index.json` with a `last_played` pointer;
  - validates loaded `SaveData` and returns `null` on bad JSON/version failures.
- Added Map Menu `Suspend & Quit`:
  - available only from a free local-control boundary;
  - confirms before writing;
  - keeps the player on-map with an error dialog if the write fails.
- Added Main Menu `Continue`:
  - disabled when no suspend save exists;
  - loads through `SaveManager`, stages via `GameState.configure_suspend_resume()`,
    then launches `GameMap`;
  - shows an error dialog and does not stage `GameState` on load failure.
- Added result-time cleanup: `GameOverScreen` deletes the suspend file when a map
  result is requested, not when the suspend file is loaded.
- Updated `GDD_01`, `GDD_07`, `GDD_10`, Feature Index, and Project Control Plane.
  `B1-SUSPEND` is now Implemented for the runtime fields that exist today; future
  object/AI runtime fields extend the same payload when those systems land.

Tests added/updated:

- `test_save_manager.gd` covers suspend file write/read/delete, `saves_index.json`,
  Continue availability, bad JSON, and unsupported versions.
- `test_map_menu.gd` covers `Suspend & Quit` signal/disabled behavior.
- `test_map_cursor.gd` covers the cursor-to-`SaveManager` suspend write path.
- `test_main_menu.gd` covers Continue enabled/disabled state, staging through
  `GameState`, and load-failure UX.
- `test_game_over_sequencing.gd` now covers result-time suspend cleanup.
