## 1. Code re-verification (recs were code-grounded; confirmed)
- `InventoryEntry.uses_remaining: int = 0`; `has_uses()` returns `uses_remaining != 0` (today 0 =
  unusable). Broken state can be derived from `uses == 0`, no new field.
- `CampaignRules` holds bool/string rule fields (`permadeath_enabled`, `leveling_method`,
  `pair_up_enabled`) — still loose `@export`s (§2 [CST-4] consolidation not yet landed).
- `ItemHandler.IMPLEMENTED_EFFECT_IDS = [heal_flat, heal_full, promote, reclass, stat_buff]` + a
  `match item.effect_id` dispatch (boot-validated). `effect_id`s are **not** `check_docs`-guarded.
- `CombatResolver` has the `get_equipped_weapon()` stat-assembly chokepoint + a separate
  `active_modifiers` (timed-buff) path. `WeaponData` is plain `@export` fields (`mt`/`hit`/`crit`/
  `uses`…), no `break`/`on_break` field today.

## 2. Five resolutions (owner reframed 1, 3, 4)
- **[BWN-1] representation = A's mechanism, PER-WEAPON authoring (owner reframe).** Broken stays the
  *derived* `uses_remaining == 0 && effective_break_behavior == degrade` (no new `InventoryEntry`
  field, no snapshot change). **But the switch is per-weapon, not one global bool:** add
  `WeaponData.break_behavior` (`destroy` | `degrade` | inherit) + a `CampaignRules` campaign-level
  default (default `destroy`). Designers flip plot/special weapons to `degrade`; common weapons
  `destroy`. **DoD#2:** a string-enum `break_behavior` needs a `check_docs` value-set guard at build;
  a bool encoding wouldn't but can't express "inherit" — encoding chosen at build.
- **[BWN-2] penalty = A + B hybrid.** Global `GameConstants` defaults (`BROKEN_WEAPON_MT_PENALTY` /
  `..._HIT_PENALTY`, Crit unaffected, tune-live) **plus** optional per-`WeaponData` overrides
  (`broken_mt`/`broken_hit`).
- **[BWN-3] repair = B (owner override of rec A).** Defer to the §2b/E shop/economy; **no v1 repair
  item**. Consequence: a `degrade` weapon stays at degraded stats until the economy lands (accepted —
  only the rarer `degrade`-flagged weapons are affected; common weapons just `destroy`). No
  `effect_id`/`IMPLEMENTED_EFFECT_IDS` change this slice.
- **[BWN-4] apply point = A + character-sheet visibility.** Penalty applied at the `CombatResolver`
  stat-assembly chokepoint (NOT `active_modifiers`) so forecast == resolve. **v1 UI requirement
  (owner):** degraded stats show on the **character sheet in the debuff-red styling**, via a
  weapon-derived stat-delta path (since it's not an `active_modifiers` debuff). **Forward item
  (reserved, not v1):** a **unified weapon-stat-delta display** shared with the future
  **weapon-upgrade** system (upgrades = + deltas, broken = − deltas, one mechanism).
- **[BWN-5] default-path = A.** Default break behavior = `destroy`, so an unset weapon behaves
  exactly as today; the `degrade` path is strictly additive.

## 3. Scope note
The reframe turns OPEN-5 from "one `CampaignRules` bool" into a **`WeaponData` schema addition +
`CampaignRules` default + `DataManager` validation + a character-sheet display path** — a larger
surface than the original draft, and it now *touches the future weapon-upgrade UI* (shared
stat-delta display reserved). Still gated behind §2 [CST-4] for the campaign-default field.
