## 1. The decisive finding (code-grounded)
The stat model is **already half data-driven** — so author-extensible stats are an **evolution, not a
rewrite**. The asymmetry:
- **Read path is string-keyed:** `get_effective_stat(name)` → `data.get(name)` (`Unit.gd:300`); combat
  /skills already address stats by string.
- **Growths / caps / wexp are already `Dictionary`s** keyed by stat name.
- **BUT base-stat storage is hardcoded `@export` fields** (`UnitData`/`ClassData.base_*`) and the **stat
  list is enumerated as literals in ~5 spots** (`ClassData.STAT_KEYS`, `Unit._GROWTH_STATS`,
  `LevelUpScreen._STAT_NAMES`, `StatBreakdown.STAT_LABELS`, `DataManager` validation).
- **No Charisma / Charm / Command stat exists.** `CampaignRules` exists as the author-config home.

## 2. The three answers (`[STM]`)
- **`[STM-2]` battalion command/leadership = cheap, rides existing rails.** Charm = a **stat** (`[STM-1]`
  /`[STM-4]`); Authority = a **proficiency rank** via the existing `weapon_rank_for_wexp` helpers (the
  `[BAT-6]` reuse). Battalion *consuming* it = `get` + threshold lookup (hours). *Earning* a non-weapon
  proficiency = the **`[AGT §6]`/A5** gap (shared, not new).
- **`[STM-1]` add ONE known stat (Charisma) = ~1 day.** Moderate/mechanical — ~8 hardcoded touch-points;
  the math is free (read path/caps/growths already string/dict-driven).
- **`[STM-3]` author-defined stats = a foundation pass (several days).** Migration plan: (1)
  `extra_stats` dict on UnitData + `ClassData` extra bases/caps/growths; (2) a `CampaignRules` **stat
  registry**; (3) **one** `get_effective_stat` fallback to `extra_stats` (unifies legacy + author stats
  for every reader); (4) de-hardcode the ~5 stat-list literals → `legacy + registry.stats`. **Legacy
  fields stay** (comparability, zero `.tres` migration). Gotchas: lint banning *new* direct base-stat
  field reads, stable registry iteration order, and the `extra_stats`+registry **F1 save reserve**.
- **`[STM-4]` sequencing (owner call, deferred):** if author-stats is wanted at all, do `[STM-3]` first —
  Charisma then collapses to a data row (no engine change), avoiding paying `[STM-1]`'s surgery twice.
