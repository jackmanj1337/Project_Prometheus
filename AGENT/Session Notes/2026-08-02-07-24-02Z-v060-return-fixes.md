## Problems encountered and resolutions

- **JavaScriptBridge callback return values disappeared.** Godot's JavaScript callback
  path discarded the returned Dictionary. The bridge was changed to publish a JSON
  state string on the opted-in global; Playwright parses that string read-only.
- **The harness initially read an old Web export.** `playwright-drive.sh` intentionally
  drives an existing export and does not rebuild it. Old export directories were moved
  to named `pre-*` evidence directories, `scripts/export-web.sh` was rerun, and only
  then were responsive checks repeated.
- **The first strict album reported 124/133.** Five Attack Preview results were false
  positives because a contextual bottom panel was treated as a centered modal. Frame
  containment was restricted to the explicit centered-screen set. The other three
  failures were real 1280x800/2x overflows in New Game, Unit Details, and Results and
  drove the production layout changes above. Campaign Library's legacy top-left frame
  was also normalized after visual inspection caught it despite the first loose run.
- **A broad mechanical node-path replacement touched unrelated tests.** The initial
  `Panel/VBox` -> `Panel/Scroll/VBox` substitution reached tests for other screens,
  causing timeouts/failures. The unintended edits were identified from per-file diffs,
  reversed, and reapplied only to the two New Game tests. A clean 118-suite run then
  passed.
- **One 8-worker test pass produced unrelated timeouts/failures.** Isolated changed
  suites passed immediately; rerunning the full suite with `TEST_JOBS=4` passed all
  118, and later standard 8-worker exact-tree hook/full/push runs also passed. This was
  treated as transient process contention, not hidden product breakage.
- **Pre-commit rejected two newly formatted files.** `gdformat` was run on the scoped
  GDScript files, followed by the full style/lint gate; the commit then passed.
- **Pushes were rejected for unclaimed commits.** Each product commit was added to this
  session note, and the final note-only commit used the established `Session note:`
  form. Session-claim audit passed before the final push.
- **The root tracker edit initially matched repeated JSON fields too broadly.** A
  read-only comparison against `HEAD:coordination/tasks.json` listed every changed
  task id and field. All unintended changes were restored, leaving only the experiment
  and harness completion rows; `gen_active_work.py` and `check_tasks.py` then passed.
- **The image does not contain the `zip` binary.** Bundle assembly used
  `python3 -m zipfile` instead. The archive listing, both executable hashes, JSON, and
  133/133 report were validated after creation.
- **The direct debug export initially failed because its destination directory did not
  exist.** The explicit, narrow `builds/windows-debug/` directory was created and the
  same `godot --export-debug "Project Prometheus v0.6.1"` command then succeeded.
- **The `_debug.exe` name was misleading.** Inspection showed the artifact manifest
  said `mode: release` and the exporter invoked `--export-release`; all debug controls
  are gated by `OS.is_debug_build()`. The release artifact was renamed, a real debug
  export was added, and README/checklist/build info/checksums were regenerated.
