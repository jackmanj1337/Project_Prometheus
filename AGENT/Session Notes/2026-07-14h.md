- **`B1-CST` Slice 3 save spine is Implemented; the load/save UI is not** — the
  roadmap row is deliberately **Split**, not flipped to Implemented. The campaign
  position no longer dies with the process:
  - `CampaignManager` owns the serializer seam — `capture_campaign_state` /
    `restore_campaign_state`, writing exactly the three F1 rows
    `campaign.campaign_id` / `node_id` / `cleared_nodes[]`. **Slice 3 added no new
    persisted field**: those rows were already reserved in the manifest, so this
    is wiring, not schema growth.
  - A restore validates the campaign id, the node id, and every cleared node
    against the authored graph **before writing any state** — an unresolvable id
    fails loud and leaves no campaign active, rather than half-restoring a
    position the graph cannot walk. An empty `campaign_id` is a valid save (the
    bare single-map launch), not a corrupt one.
  - `GameState.capture_campaign_save` / `configure_campaign_resume` add the
    **between-map** document: a position and a party, with **no** `map_runtime`
    and no suspend block. That absence is exactly what routes a slot load through
    the campaign launch path instead of a map resume.
  - `SaveManager` grew campaign **slots** beside the suspend save: allow-listed
    slot ids, index rows carrying the picker's label/header, `list_slots` /
    `delete_slot`, and a kind-aware Continue pointer. `MainMenu` Continue now
    routes on that kind (suspend -> live board; slot -> restore + launch the
    parked node; a completed campaign says so instead of failing into a launch).
  - **The commit is the autosave point.** `commit_pending_result` advances the
    position and then writes the `autosave` slot — the moment the party is parked
    between maps is precisely the state a slot holds, so every route that advances
    the campaign autosaves rather than each results surface remembering to.
- **The pending result is deliberately NOT persisted** (carried over from the
  Slice 2 deviation, and now load-bearing). It is discarded on quit, so a save
  taken while the results surface is up restores parked on the current node and
  the map is simply replayed. Persisting it would let a reload commit a win for a
  map that was never played that session.
- **Two bugs found and fixed while wiring, both pre-existing in spirit:**
  - `SaveManager.has_continue_save()` branched on `last_played.kind` but **both
    arms returned `has_suspend()`** — the slot branch was dead, so Continue could
    never have routed to a campaign save.
  - Slot rows ordered by `saved_at_unix`, which has whole-second resolution: two
    saves written in the same second tie and "newest first" becomes arbitrary —
    including for the Continue fallback, which takes row 0. Rows now order by a
    monotonic `write_seq` in the index; the timestamp stays for display. (Caught
    by a test that wrote an autosave and a manual slot back to back.)
