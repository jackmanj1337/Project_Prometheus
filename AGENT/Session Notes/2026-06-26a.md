## 1. `[REQ-9]` value terms + two-value `compare`
Generalizes the REQ-2 constant comparisons to compare **two dynamic values** ("is my level > yours",
"is my STR > your DEF", "more sword skill than you").
- **Value term** = `{subject (REQ-3), source}` → a number. Sources: `level` · `stat:<name>`
  (`get_effective_stat`, string-keyed → F14) · `proficiency:<track>` · `item_count:{id,location}` ·
  `skill_count` · `gold` · **literal**. Author-extensible (F4-style registry).
- **`compare`** = `{lhs:term, op:<|<=|==|!=|>=|>, rhs:term}` — both sides dynamic, **different subjects
  allowed** (the point). Deterministic/pure.
- **Generalizes REQ-2:** the constant predicates (`stat`/`class_level`/`proficiency`) are the
  literal-`rhs` special case.

## 2. `[REQ-10]` chance gate (comparison-skewed probabilistic predicate)
A **`chance`** predicate — the **one stateful/impure** predicate (all others are pure reads).
- **Shape:** `{base, skew?:{lhs:term, rhs:term, operand:difference|ratio, profile:<skew>}, latch}`;
  `success% = skew_profile.apply(base, operand(lhs,rhs))` clamped.
- **Owner calls:** skew curve = **author-configurable CampaignRules (F4) profile** (`linear` default /
  `sigmoid` / `table`), per gate · operand = **author's choice `difference|ratio`** · timing =
  **roll-once-and-latch**.
- **RNG discipline (hard req):** routes through **`RngService`/Package A `[PKGA]`** (seeded, canonical
  roll order, **rewind-safe**); never engine RNG (`check_rng_usage`). **Not built until Package A lands.**
- **Latch:** rolls once, latches the outcome into the `[DLG-11]` `visited_trail` and/or an `[F6]` result
  key → save/reload/rewind/re-eval returns the same answer (**no save-scum**, matches PKGA anti-reroll).
  Author `re_rollable` opts out for intentional retries.
- **Display vs commit:** shows **odds** ("65%"), and **evaluation IS the roll** → evaluated **on commit**,
  not passive preview (pure predicates may preview; `chance` may not).
- **General primitive:** also serves persuade/steal/intimidate/status-infliction (a contest/check gate,
  mirrors combat hit math) — surfaced in F16, not dialogue-only.
- **Save:** the latch is new state but **rides** `visited_trail`/`[F6]` (no new top-level field;
  amends REQ-7).

## 2b. `[REQ-11]` item references + item-property terms (owner add, same day)
Value terms (REQ-9) and predicates can read **properties of a referenced item**.
- **Item ref:** `equipped(subject)` (`get_equipped_weapon`/`[CEX-21]` source) · `held(subject,
  item_id|slot)` (an `InventoryEntry`) · **`targeted`** (the action's targeted item — steal/forge/
  break-event/trade; **context-resolved** like speaker/participant; false where no target, never errors).
- **Property vocab (grounded in `[IEQ]`/WeaponData, author-extensible):** numeric (`mt`/`hit`/`crit`/`wt`/
  `uses_remaining`/`cost`/`range`/`required_rank`-ordinal/`strikes_per_attack`/`forged_mods`/equip-mods)
  → `compare`; scalar-string (`combat_family`/`triangle_family`/`item_type`/`effect_id`) → `compare`
  `==`/`!=`; **set** (`effect_tags`) → dedicated **`item_has_tag`/`item_has_effect`**; identity →
  `item_is`. `compare` now does scalar (num OR string) equality + numeric ordering.
- Subject selector reused → cross-subject item compares ("my weapon's Mt > yours" =
  `compare(item_property(equipped(speaker),mt) > item_property(equipped(participant:other),mt))`).
