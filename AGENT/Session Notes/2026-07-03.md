## What was done
Wrote `AGENT/Docs/design/ui_theme_and_asset_resolution_2026-07-03.md` (Status:
Target design). Scope deliberately thin — locks the *shape*, not every future token:

- **Two seams, both open registries** (`[EXT]`): `UiThemeDef` = a flat bag of
  presentational tokens only (`PHB-6` — no mechanics in skins); `AssetResolver` =
  one `resolve(kind, id_or_path)` that every caller uses (no scene does
  `Image.load_from_file` itself). Theme ids are authored data, never a closed enum.
- **Thin v1 token schema**, grouped: colors (incl. the range/threat/target/aoe/heal/
  danger overlay tokens that drive the "one white tile + `modulate`" lever), 9-slice
  panel chrome, fonts (SDF body / tabular numeric / title), icons (theme supplies the
  default atlas; per-entry icons come from **registry `icon` metadata**), cursor/
  selection, backgrounds, stage frames, audio slots. Every token optional -> fallback.
- **id-vs-path convention:** authors reference by asset id where reuse matters (ids
  resolve to pack paths); raw path is a one-off escape hatch.
- **Fallback chain locked** (5 levels: panel override -> node theme -> campaign
  default -> shipped default -> engine fallback + placeholder + warning); per-asset
  fallbacks enumerated. Order itself is a contract.
- **Relation to menu-scale spelled out:** `MenuScale._scaled_theme` (real seam,
  `MenuScale.gd:94`) owns display scaling; `UiThemeDef` owns authored appearance;
  they compose (themed base -> menu-scale multiplies sizes). Neither replaces the other.
- **Lock-in section** (token names, fallback order, id-preferred, `PHB-6`) + required-
  vs-optional (almost nothing required) + DoD#1/#2 + 4 open questions.

Grounded against live code: verified `FactionData.color` (`:23`), `ClassData.sprite_id`
(`:63`), and the `MenuScale` runtime-Theme path exist before citing them.
