## Next-Session Review List

### M8 — Status Conditions

Already locked by the docs:
- Conditions tick at the **start of the holder's activation**, not faction phase.
- Standard conditions **refresh instead of stacking**.
- Initial implementation set is `Poison`, `Sleep`, `Silence`, `Berserk`, `Stun`,
  plus skill-driven `Hex`.
- Icon/visual priority is `Berserk > Sleep > Stun > Silence > Poison`.

Decisions to review:
- Whether Poison damage can reduce a unit to `0 HP`, or should leave them at `1 HP`.
- Exact Berserk targeting rule:
  recommended default is highest projected damage, then nearest target, then a
  deterministic tie-break.
- Confirm Silence scope:
  recommended default is "blocks tomes and staves only".
- Confirm condition schema discipline:
  recommended default is to keep standard condition storage minimal
  (`type`, `turns_remaining`) unless a condition truly needs extra fields.

### M9 — Skill Content

Already locked by the docs:
- M9 is built on the existing trigger/effect pipeline, not a new combat system.
- Pair Up-specific skill logic remains out of scope here.
- Laguz-linked skills may be stubbed/deferred until `M12`.
- The milestone already assumes shared handlers and data-driven `.tres` content.

Decisions to review:
- Whether to treat M9 internally as **M9a mechanics** and **M9b content/data** to
  keep scope under control, even if the roadmap still presents it as one milestone.
- Whether to avoid adding any new trigger types unless an existing trigger plus
  context flag is clearly insufficient.
- Which effects should be dynamic calculations versus stored modifiers:
  recommended default is dynamic for threshold/state-based effects such as
  `Resolve`, `Aegis`, and `Frenzy`.
- Confirm that Pair Up / Rescue interactions stay out of M9 and are handled later
  as campaign-rule integration work.

### M15 Part A — Hotseat

Already locked by the docs:
- Part A is scoped to `WHOLE_PHASE` maps only.
- `Blue` remains player 1; only non-blue factions can be reassigned.
- Hotseat control uses the existing cursor/controller seam, not AI.
- Remote play is deferred, but Part A should emit committed command actions from
  day one to reduce the later networking jump.

Decisions to review:
- Whether to skip per-player keybinding sets for Part A:
  recommended default is "yes, skip them for now".
- How hotseat assignment is configured in the near term:
  recommended default is per-map / test configuration first, not a full lobby UI.
- HUD wording for controller ownership:
  recommended default is an explicit `Faction + Controller` label.
- Confirm that `ALTERNATING` hotseat stays out of Part A completely until the
  extra-turn / scheduler work is settled.

### Objective-Map Followup (Maps 002–005)

Already locked by the docs:
- The objective framework is the typed `ObjectiveCondition` system keyed by
  alliance group.
- M16 itself is already shipped; this followup is content authoring against the
  implemented condition system.

Decisions to review:
- Map ordering / showcase plan:
  recommended default is one map each for `Seize`, `Defeat Boss`, `Escape`,
  and `Survive/Defend`.
- Whether to keep early authored maps to one primary objective each:
  recommended default is "yes" to validate the system without campaign-branching
  complexity.
- Allowed seizer policy:
  recommended default is explicit `allowed_unit_ids` per map, not inferred from class.
- Escape semantics:
  recommended default is escaped units count as alive, are removed from the map,
  and cannot act further on that map.
- Map-authoring standard:
  recommended default is each new objective map should include at least one
  authored defeat condition beyond simple rout pressure.
