## What was done

### Validation hardening (rolled in from prior uncommitted work)

- `DataManager.collect_map_data_validation_errors` and registry validation now
  enforce:
  - `tilemap_scene_path` exists and loads as `PackedScene`
  - `reward_items` are non-empty ids present in the items catalogue
  - `player_start_tiles`, `camera_start_tile`, enemy placement tiles, and
    seize/escape/survive `tile(s)` are inside the grid (shared
    `_tile_is_inside_grid` helper)
  - enemy placement `ai_profile` and `UnitData.ai_profile` validated against
    the new `_VALID_AI_PROFILES` constant (`basic`, `passive`, `healer`)
- `DataManager.has_item(id)` accessor added so other autoloads can ask without
  poking `_items` directly.
- `GameState.validate_restore_snapshot_state()` now sanity-checks snapshot
  count vs roster, per-entry hp/max_hp, `tile_position` typing, required
  Array/Dictionary keys, snapshot party items (via DataManager.has_item),
  and the Pair Up registry shape.
- `GameState.restore_map_snapshot()` returns `bool` and aborts (pushing
  errors, no mutation) when validation fails.
- Tests extended in `test_data_manager.gd` and `test_game_state.gd` to cover
  every new failure case (including the two new "rejects without mutating
  roster" Retry checks).

### W3 — Progression and class

- W3a: `Unit._grant_current_level_class_skills` is now retroactive — a
  directly-spawned level-20 General receives every skill_unlock at or below
  its level (bastion at 5, iron_wall at 15). Existing per-level grant path
  in `_grant_level_skills` is unaffected. Regression added in
  `test_unit_stats.gd`.
- W3b: confirmed via new regression in `test_skill_item_handler.gd` that
  `can_apply_item` reflects live `data.level` — a unit that hits class max
  becomes eligible the next time the action/item menu re-evaluates. No
  code change needed; the playtest report likely reflected a class- or
  group-restricted seal that simply did not apply to the unit's class.
- W3c: added `unit_11_lvl19_mercenary.tres` to the M950 fixture roster
  (lvl-19 Mercenary with iron_sword + master_seal). Drives the Auto-Promote
  cap test in one level-up.
- W3d: added `unit_12_hero_skill_cap.tres` — a level-14 Hero starting with
  four equipped skills (`armsthrift`, `patience`, `dash`, `discipline`).
  When leveled to 15, Hero earns `disarm` and `earned_skills` exceeds the
  equipped-skill cap.
- Updated `map_950_promotion_validation_data.tres` player_start_tiles and
  the roster manifest to host the two new fixtures.
- W3e: existing snapshot infrastructure already round-trips `class_id`,
  `class_line_id`, `is_promoted`, `internal_level`, level, stats, weapon
  wexp, equipped skills, and earned_skills. Added explicit regression in
  `test_snapshot_coverage.gd` that snapshots a Cavalier, simulates a Second
  Seal reclass, restores, and asserts every reclass-touched field reverts.
