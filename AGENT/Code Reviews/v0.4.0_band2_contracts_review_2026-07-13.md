## Verdict

### Closure outcome

The fix pass closed all three Medium and eight Low findings in commits
`9fa2453`, `1c11906`, `07b3351`, `ab05e3a`, and `859ae28`.

- F1/F3: the circular death fallback was removed and resolver-level mutual-death
  snapshots now prove shared grouping, responsible actors, pre-disposition state,
  and defender-first ordering.
- F2: normal map-start placement uses deterministic `nearest_free`; isolated
  failures skip only the unit and never abort map boot.
- L1/L3/L4/L6/L7/L8: optional action parameters, stale preview state, failed
  refund reporting, the unused DataManager seam, delayed-request cleanup, and the
  stale fixture comment were corrected or deleted with focused regressions.
- L2: actor/target HP, modifiers, counters, and inventory are byte-snapshotted in
  the projection test; the contract now states that the cheap runtime guard covers
  only RNG history and party gold.
- L5/D4: registry families strict-replace from the selected content source, while
  the exact suspend-placement bypass is explicitly documented as intentional.

All seven release-checklist slices were re-checked after the fixes. The four
automated gates and headless project scan pass; the scan emitted only container
editor-cache write warnings, not script or resource load failures.

The seven contracts are, as designed, genuinely open seams: handler lookup is
registry-backed everywhere it should be, no slice added a closed `match` over
author-facing ids, and mutation atomicity in the ledger and the death funnel is
correct. All four automated gates are green (`run_tests.sh`, `check_docs.py`,
`check_rng_usage.sh`, headless import). Checks 28 and 29 are real teeth: the
party-gold guard and the spawn-occupancy guard both enforce their DoD in CI.

Three findings block the gate. F1 is a fallback path that cannot work — the
compatibility route added for a missing `DeathLifecycle` is circular, so if the
autoload is ever absent, dead units are never removed. F2 is a behavior change
in map boot: one unplaceable unit now aborts the whole map into a half-built
scene where it previously loaded. F3 is the coverage gap that let F1 and the
headline mutual-death invariant through — `simultaneous_group_id` and
`responsible_actor` appear in zero tests.

Nothing in the deferred list has leaked into the release: reserved occupancy
policies correctly fail `not_implemented`, `select_campaign_source` is genuinely
inert, and `DeathDisposition` is an explicit no-op.

## F1 (MEDIUM) - The death-lifecycle fallback is circular and cannot fire

`CombatResolver.apply_combat_result()` resolves the lifecycle and, when it is
missing, falls back to the unit's own compatibility method
(`scripts/core/CombatResolver.gd:954-963`):

```gdscript
var lifecycle := get_node_or_null("/root/DeathLifecycle") if is_inside_tree() else null
if defender_ctx != null:
	if lifecycle != null:
		lifecycle.handle_death(defender_ctx)
	elif defender.has_method("handle_death"):
		defender.handle_death()
```

But `Unit.handle_death()` is now itself a thin delegate to the same autoload
(`scripts/units/Unit.gd:491-497`):

```gdscript
var lifecycle := get_node_or_null("/root/DeathLifecycle") if is_inside_tree() else null
if lifecycle == null:
	return DeathResultScript.failure("DeathLifecycle is unavailable")
```

The `elif` branch only runs when `/root/DeathLifecycle` is null — which is
exactly the condition under which `Unit.handle_death()` returns a failure and
does nothing. Before this delta, `Unit.handle_death()` did the work itself
(incapacitation, Pair Up release, `unregister_unit`, `unit_died`, `queue_free`).

Failure scenario: with `DeathLifecycle` absent or failing to load, a unit
reduced to 0 HP is never unregistered, never emits `unit_died`, and is never
freed. It stays on the grid at 0 HP, keeps taking turns, and rout objectives can
never complete — a soft-lock, reported as a silent no-op rather than an error.

The checklist explicitly requires missing-autoload behavior to be checked, and
this is the one path where it is unsound. The branch also reads to a maintainer
as a working safety net, which is worse than having no fallback.

Route to fix. Either delete the `elif` branches and `push_error` when the
lifecycle is missing (honest hard failure), or restore a real inline disposition
in `Unit.handle_death()` for the no-autoload case. Deleting is preferred — the
funnel is supposed to be the single mutation path, and a second implementation
would re-open the seam this slice closed.

## F2 (MEDIUM) - One unplaceable unit now aborts map boot into a half-built scene

`_spawn_units()` was changed to track `all_placed` and return it
(`scripts/core/GameMap.gd:216,245`); previously it returned `true`
unconditionally and enemy spawn failures were `continue`d. Its caller aborts on
false (`scripts/core/GameMap.gd:106`):

```gdscript
if not _spawn_units():
	return
```

That `return` leaves `_ready()` before cursor placement, the Retry snapshot, and
turn start. The map scene is already committed, so the player lands on a
half-initialized map rather than seeing a clean failure.

`_place_and_spawn` defaults to `require_empty`, which enforces passability as
well as occupancy (`OccupancyService._is_passable`, `:115-118`). So two inputs
that previously produced a playable (if imperfect) map now brick it:

- a player start tile authored on a `wall` terrain — nothing validates player
  starts against terrain;
- a roster/start-tile arrangement that collides in a way the new DataManager
  check does not cover.

The new enemy-vs-player overlap check (`DataManager.collect_map_data_validation_errors`)
closes the most likely case, and it is a good addition — but it is a
`push_error` at boot, not a load block, so a bad map still reaches `_spawn_units()`.

Failure scenario: ship a map whose first player start sits on a wall. v0.3.x
spawned the unit anyway. v0.4.0 pushes an error to the log and drops the player
into a map with no cursor, no snapshot, and no turn.

Route to fix. Decide the intended contract and make it explicit. Recommended:
keep placement failures non-fatal for the map (skip the unit, `push_error`, and
continue as before), and make authored-data soundness the job of DataManager
validation — extending it to reject impassable player start tiles. If a hard
failure is genuinely wanted, it must surface to the player, not `return` mid-`_ready()`.

## F3 (MEDIUM) - The mutual-death invariant has no test coverage

The headline behavior of `B2-DEATH-LIFECYCLE` is that both death contexts are
snapshotted before either disposition runs, and that defender-first ordering
survives (`scripts/core/CombatResolver.gd:940-953`). Nothing tests it:

- `simultaneous_group_id` and `responsible_actor` appear in **zero** test files.
- `test_combat.gd` asserts mutual kill only on the returned result dictionary
  (`mk_apply["attacker_died"] and mk_apply["defender_died"]`, `:585`) — flags
  that are computed *before* the death block and would still pass if the whole
  snapshot/ordering rework were deleted.
- `test_death_lifecycle.gd` calls `lifecycle.handle_death()` directly (5 asserts:
  classic, casual, no-op disposition, context capture, missing subject). It never
  goes through `CombatResolver`, so it cannot see the ordering.
- `MockUnit.handle_death()` in `test_combat.gd:125` is now dead code — the
  autoload is always present in headless runs, so `CombatResolver` routes to the
  real `DeathLifecycle` and the `elif` fallback branch is never exercised by any
  test. This is precisely why F1 shipped unnoticed.

Route to fix. Add a `CombatResolver`-level mutual-death test asserting both
contexts carry the same `simultaneous_group_id`, that each snapshot's inventory
and tile were captured before either unit was freed, and that the defender's
disposition runs first. That single test would have caught F1's branch as
unreachable.

## Low findings

**L1 - `_commit_active_modifier` dot-accesses optional params.**
`scripts/actions/ActionPrimitiveRunner.gd:66-69` reads `params.stat`,
`params.delta`, `params.source`, `params.duration`, `params.duration_type`. But
`validate()` (`:31-35`) skips any param whose schema does not set
`required: true`. This is safe today only because `apply_active_modifier.tres`
marks all five required — the first entry that adds an optional param crashes at
commit with an invalid-index error, after validation has already returned OK.
Use `params.get(id, default)`.

**L2 - Projection guard is narrower than its contract.**
`ProjectionService._project_combat` (`:32,49`) snapshots only RNG state and
`party_gold`. The checklist claims projection "preserves unit state, resource
fields, and committed RNG history" — a resolver that mutated defender HP would
pass the guard silently. Either widen the guard to a unit-state hash or narrow
the contract's wording.

**L3 - Stale preview entries on projection failure.**
`AttackPreview.show_preview()` returns early when `not result.valid`
(`scripts/ui/AttackPreview.gd:152`) before `_entries.clear()` (`:156`), so a
failed projection leaves the previous forecast's rows in the selector.

**L4 - Failed refunds report deltas that were never applied.**
`ResourceLedger.refund()` calls `_record_public_delta()` inside the loop (`:47`)
but can bail on overdraw mid-loop (`:43-45`), returning a failure result whose
`wallets_touched`/`deltas` describe a partial reversal that did not happen. The
wallets themselves are untouched — `_apply_records` runs only after the loop — so
this is a reporting bug, not a state bug.

**L5 - Registry presets do not follow the campaign content source.**
`RegistryManager.PRESET_DIRECTORIES` (`:7-11`) is hardcoded to
`res://data/registries/...`, so `DataManager.select_campaign_source()` (`:78`)
replaces classes/weapons/items/skills but *not* registry entries. A
"self-contained" campaign source cannot ship its own `action_primitives` or
`occupancy_policies`. Given `select_campaign_source` is inert this slice, record
it as a documented boundary rather than fixing it now — but it should be named,
because "self-contained source" currently overstates what replace-load covers.

**L6 - `is_registered_id()` has no production consumer.**
`scripts/autoloads/DataManager.gd:86` is called only from `test_data_manager.gd`.
The checklist requires every service to trace to a production consumer or an
explicitly documented foundation-only boundary; this one is neither yet.

**L7 - `delayed_requests` has no drain.**
`OccupancyService.delayed_requests` (`:7`) accumulates contexts (each holding a
subject ref) and `clear_delayed()` (`:37`) has no production caller — only tests.
Latent while no authored map uses the `delay` policy; it will grow across maps
the moment one does. Call `clear_delayed()` on map start.

**L8 - Stale fixture comment in the Attack Preview suite.**
`test_attack_preview_selector.gd:39-40` says the stub is installed so
"`show_preview`'s `get_node_or_null("/root/CombatResolver")` resolves it".
`show_preview` no longer looks up `CombatResolver` — it resolves
`/root/ProjectionService`. The stub still takes effect, but by a different route:
a node added to `root` during a `--script` `SceneTree._init()` claims the name
*before* autoloads are registered and displaces the real autoload (verified: at
`_init()` `root.get_child_count() == 0`, and afterwards `/root/CombatResolver` is
the stub, with no second node under that name). The test does now genuinely
exercise the real `ProjectionService`, which is what the checklist wanted — the
comment just documents a code path that no longer exists.

## Checklist rows that pass

- **`B2-REGISTRY`** — deterministic ordering is sound: `RegistryCatalog.ids()`
  sorts on `(priority, id)`, a total order over distinct entries, so the unstable
  `sort_custom` cannot produce run-to-run variance. Duplicate ids, unknown
  handlers, malformed schemas, and unknown composition refs all fail in
  `validate_entry()`. Mutating entries are forced to declare `save_fields` (`:54`).
- **`B2-ACTION-EFFECT`** — `ItemHandler.stat_buff` delegation is behaviorally
  equivalent: the empty-stat / zero-delta early return is preserved through the
  `non_empty` and `non_zero` schema flags, and the item is still not consumed on
  failure. Dry-run and invalid requests provably mutate nothing (`commit()`
  returns the validation result before touching a handler).
- **`B2-RESOURCE-LEDGER`** — commit is atomic: every aggregated wallet is
  overdraw-checked before any `_apply_records` write. Victory gold routes through
  the ledger with the correct sign (negative `CostSpec.amount` = credit), and
  check 28 proves no unguarded `party_gold` writes remain outside the allowlist.
  Refund reverses recorded deltas rather than recalculating (`:38-46`).
- **`B2-OCCUPANCY`** — tie-breaking is distance, then y, then x, and is fully
  deterministic without needing source order. Reserved policies (`swap`,
  `overlap_hidden`, `object_unit`) map to `unimplemented_placement` and fail
  `not_implemented` rather than silently placing. Sequential `require_empty`
  spawning works because `_spawn_unit` registers each unit with `GameState`
  before the next placement query reads `get_unit_at`.
- **`B2-PROJECTION`** — `AttackPreview` consumes the service, which delegates to
  `CombatResolver.preview_combat()` rather than re-deriving combat math, and
  reports `committed_draws: 0`.
- **`B2-DATAMANAGER-SEAMS`** — `_ready()` composes clear/load/validate/report;
  missing catalogues `push_error` loudly via `_load_directory`; alternate sources
  replace rather than merge (`_clear_content()` precedes `_load_all()`).

## Review Decisions - 2026-07-13

Owner decisions taken at review close. Each finding is routed to a fix, a
documented boundary, or a deletion. The implementation plan lives in
`AGENT/Docs/plans/v0.4.0_review_fix_handoff_2026-07-13.md`.

### D1 - F2 map boot: place at the nearest free tile, then skip

Rejected both "skip immediately" and "hard-fail". Map-start placement moves to
the existing `nearest_free` policy; only when that returns `no_free_tile` is the
unit skipped. A placement problem must never abort a map.

Rationale: the reachable failure causes are content slips, not gameplay-logic
violations. `GridManager.get_terrain_at()` returns `"wall"` as a *sentinel* for
an unpainted TileMapLayer cell, a tileset missing its `terrain_type` custom data,
or an out-of-bounds tile (`GridManager.gd:76-88`) — none of which DataManager can
see, because it validates `map_data.grid`, not the TileMapLayer scene the runtime
actually reads. Escalating an art mistake into a dead map is the wrong trade.

Decided shape:

- `_place_and_spawn` default policy `require_empty` -> `nearest_free`.
- `push_warning` on `result.fallback_used`, naming unit, authored tile, and
  landing tile, so a tileset slip stays visible instead of silently papered over.
- Drop `all_placed`; `_spawn_units()` returns false only for structural failures
  (missing `map_data`, missing `GameState`, empty roster).
- Applies to player units as well as enemies — one code path; a displaced player
  unit beats a dead map. Players spawn first, so on a collision the player keeps
  the authored tile and the enemy is moved. Deterministic, and the right priority.
- DataManager validation stays strict — the fallback is a runtime safety net, not
  a licence to author overlapping tiles. Enemy placement tiles gain the bounds
  check they currently lack (only player starts and `camera_start_tile` have one).

### D2 - F1 death fallback: delete it, fail loudly

The `elif ...has_method("handle_death")` branches come out of `CombatResolver`;
a missing `DeathLifecycle` becomes a `push_error`. `Unit.handle_death()` stays a
pure delegate.

Rationale: restoring an inline disposition would give the codebase two death
implementations that can drift — precisely the seam `B2-DEATH-LIFECYCLE` closed.
`DeathLifecycle` is an autoload; in any real build it is present.

### D3 - L2 projection guard: prove it in tests, describe the guard honestly

The per-call runtime guard stays cheap (RNG state + `party_gold` only) —
`show_preview` fires on every cursor move over a target, so widening it is not
free. The unit-state invariant moves to a test asserting `project_combat()`
leaves actor/target HP, modifiers, and inventory byte-identical. Contract wording
is corrected to describe what the runtime guard actually covers.

### D4 - L5 registries follow the content source; suspend bypass documented

Two boundaries, split:

- **Closed.** `RegistryManager.PRESET_DIRECTORIES` becomes source-relative:
  `reload_presets(source)` builds paths from the content root, and
  `select_campaign_source()` reloads registries before validating. **Strict
  replace** — a source that omits a family gets an empty family and loud load
  errors. Consistent with the DataManager replace-load contract; no override or
  duplicate-id semantics needed. This makes "self-contained source" true rather
  than aspirational.
- **Documented.** `_spawn_units_from_suspend` bypassing `OccupancyService`
  (`GameMap.gd:263`) is correct and stays. Resume restores exact serialized
  tiles; re-policying them could teleport a unit mid-campaign. Check 29's scoping
  to the normal spawn flow is deliberate and will be named in the slice doc.

Accepted risk: closing the registry boundary is the one item that *adds*
capability rather than removing risk, in a release whose checklist calls itself
foundation-only. Accepted on the grounds that it corrects a false claim in the
contract. It is also the first item to cut if the RC diff must stay purely
corrective.

### D5 - L6 `is_registered_id()`: delete it

Not merely unused — structurally unusable. It is an instance method doing
`get_node_or_null`, while every DataManager validator is `static` (deliberately,
so tests can drive them with fixture data without a tree). Static functions
cannot call it, so it cannot serve the "content validators ask the shared
registry" purpose its own docstring claims. Nothing authored carries a registry
id yet, so there is nothing for it to check.

Deleted along with its test coverage. When a validator genuinely needs it, the
shape that works is injection — registered ids passed into the static validator,
matching `collect_validation_errors(classes, weapons, items, skills)`.

### Low findings routed to the cleanup batch

L1, L3, L4, L7, L8 are accepted as written and fixed as a single batch. No
finding was rejected or accepted-as-risk beyond the D4 note above.
